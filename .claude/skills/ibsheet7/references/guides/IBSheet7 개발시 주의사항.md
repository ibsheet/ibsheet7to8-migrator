# IBSheet7 개발시 주의사항

IBSheet7 개발시 주의사항

IBSheet7 개발시 다른 css와의 충돌을 주의해 주세요.

가령 시트를 감싸고 있는 DIV객체나 Table 객체에 css를 적용하는 경우 안에 있는 IBSheet도 적용을 받을 수 있습니다. 이런 부분에 대해서는 개발 초기에 표준을 정하는 단계에서 테스트하여 올바른 표준을 잡지 않으면, 개발 후기에는 조치하기 어려운 경우가 있으므로 주의하시기 바랍니다.

주로 발생하는 경우는 아래와 같습니다.

IE7 이하에서 상위 div가 position:relative로 설정되어 있으면 브라우저 버그로 인해 시트내 팝업(달력, 콤보목록)이 뒤로 숨는 현상 발생 (position:static 권장)

IE6 에서 시트 상위의 DIV에 float:left 설정시 브라우저 버그로 인해 시트가 잘못그려지거나 안보이는 현상

각 브라우져에서의 시트모양이나 동작을 확인해 주세요.

1번과 마찬가지로 최신 브라우져에서는 잘 보여지나 IE6와 같이 오래된 브라우져에서는 CSS 해석에 오류가 많아 브라우져에 따라 다르게 보여질 수 있습니다. 따라서 개발시작부터 주기적으로 한번씩 현재 표준으로 잡고 개발중인 화면이 IE6나 타 브라우져에서도 생각했던 모양과 동일하게 나오는지 확인해 주세요.

json 타입에 유의해 주세요.

json은 자바스크립트 엔진이 해석하는 자료구조입니다. 따라서 xml과 달리 json을 쓸때는 스크립트에서 변수를 선언하는 것과 동일하게 문법이 준수되어야 합니다. 이때 특히 주의해야 하는 부분은 조회 json 데이터를 만들때인데, 자주 문제가 발생하는 유형은 아래와 같습니다.

조회 데이터에 줄넘김 문자가 있는 경우.

Ex)var json = {sawon:”홍길동”,desc:”성실히 일하고,

매사에 긍정적임”};

위와 같이 “일하고”문자 뒤에 줄넘김 문자가 있는 경우에는 script엔진이 오류를 발생시킵니다.

조회 데이터 안에 “(큰 따옴표[double quotation]) 혹은 ‘(작은 따옴표[single quotation])이 있는 경우. 

Ex)

var json = {sawon:’홍길동’,desc:’ doesn't matter’};

위와 같은 경우 desc의 내용 안에 작은따옴표가 포함되어 해석이 불가능해 진다.

조회나 저장이 비동기 형태임에 주의.

기존에 ActiveX 기반의 IBSheet3는 동기형태로 서버와 접속함으로, 조회 메서드 아랫줄에 조회 이후에 작업을 코딩하여도 되었으나, IBSheet7은 비동기 형태임으로 조회 후에 작업은 반드시 OnSearchEnd 나 OnSaveEnd 이벤트에서 기술해야 함.

Ex)

mySheet.DoSearch(“sheetWorx.do”,param);

if(mySheet.SearchRows()<1){

alert(“조회 된 데이터가 없습니다.”);

window.history.back();

}

위와 같은 코딩은 불가능하고, 조회 건수에 따른 작업은 반드시 OnSearchEnd 이벤트에서 수행하여야 한다.

높이 “100%” 설정 문제.

시트 초기화 구분에서 높이를 %단위로 주는 것은 권장하지 않고 있습니다. 이는 각 브라우져마다 표준이 조금씩 달라, 모든 브라우져에서 동일하게 보이기 어려움이 있기 때문입니다. 따라서 높이를 화면 크기에 맞게 조절하시려면, 일단 시트생성구문에서는 높이를 픽셀단위로 설정하시고, body 테그 안에서 OnSmartResize 이벤트 호출시 자바스크립트를 통해 시트의 높이를 조절하실 것을 권장합니다.

스크립트 지연 문제

IE 계열의 브라우져에서는 스크립트 연산이 많으면 스크립트 지연에 따른 confirm창이 나타날 수 있습니다. IBSheet7도 javascript 기반의 제품임으로 조회건수가 많아지면 이러한 창이 주기적으로 나타나게 되는데, 조회 건수가 row*column 으로 12440이 넘으면 경고 메시지가 나타날 수 있습니다. 이는 20개 컬럼을 사용하는 시트에서 조회 건수가 3000건건 넘을 때 나타날 수 있음을 의미합니다.

이를 해결하는 방법은 클라이언트 IE를 사용하지 않거나 클라이언트PC에 레지스트리를 수정하는 방법 밖에는 없습니다.

자세한 내용은 아래 msdn을 참고해 주세요.

http://support.microsoft.com/kb/175500

위의 경로를 들어가시면 fix it 버튼을 통해 설치프로그램을 받아 설치하시면 더 이상 이러한 문제가 발생하지 않습니다. 그리고 이와 동일한 역할을 하는 ActiveX도 만들어 제공하고 있사오니, 접속한 사용자가 IE8이하의 브라우져를 사용하는 경우에는 이 ActiveX를 설치시키어 문제를 해결하는 것도 한가지 방법이 되겠습니다.

컬럼 초기화시 반드시 Reset()메서드 호출.

기존 ActiveX와 마찬가지로 초기화 메서드(SetConfig,InitHeaders,InitColumns)는 한번만 호출이 가능하고, 다시 호출해야 하는 경우에는 Reset()메서드를 먼저 호출해 줘야 합니다.

엑셀 연동시 주의 사항

Down2Excel,LoadExcel 메서드 호출 후 반응이 없을때.

ibsheet.cfg 파일에 보면 LoadExcel.jsp 와 Down2Excel.jsp 파일에 대한 경로가 들어가 있는데, 이 파일이 모두 ibsheet.js 파일과 동일한 위치에 있다면  ./LoadExcel.jsp  , ./Down2Excel.jsp 로 설정하시기 바랍니다.

LoadExcel 메서드를 통해 excel 파일을 선택한 후에 반응이 없는 경우.

필수로 필요한 몇 가지 jar 파일이 없거나, 서버의 jdk와 버젼이 맞지 않은 경우입니다. 아이비시트의 엑셀관련 기능은 poi 라이브러리를 사용함으로 서버에 이 라이브러리가 있어야 하며, poi라이브러리를 사용하기 위해 서버는 JDK1.5 이상의 버전이 권장됩니다.

Down2Excel이나 LoadExcel 사용 후, 글자가 깨지는 경우.

Down2Excel.jsp 나 LoadExcel.jsp 파일을 열어 보면 엔코딩 설정에 관한 isUTF8 변수가 있는데 이 값을 조정하시기 바랍니다.

Spring,Struts2 와 같은 프레임웍을 사용하는 경우

filter-mapping을 * 로 정의하면 시트가 Down2Excel.jsp나 LoadExcel.jsp 로 전달하는 내용도 프레임웍을 통하게 되는데, 이 방식이 multipart 형태이기 때문에 프레임웍을 통과하고 나면 request안에 내용은 이미 프레임웍이 추출한 껍데기만 받게되어 Down2Excel이나 LoadExcel이 안될 수 있습니다. 따라서 filter-mapping을 *.do 로 정의하거나 꼭 *로 정의 하는 경우에는 Down2Excel.jsp나 LoadExcel.jsp 파일만은 프레임웍을 통하지 않도록 프레임웍 필터 앞에 필터를 하나 더 적용해 주어야 합니다.

디자인 적용은 /Main/ibsheet.css파일을 수정하여 적용하실 수 있으며, 수정하는 방법에 대해서는 “IBSheet7 CSS가이드” 문서를 참고하여 주세요.시트에 대한 디자인(색상이나 폰트)를 수정하시고자 하실때는 반드시 ibsheet.css 파일을 수정하시고, 절대 ibsheet.css 파일에 class와 동일한 이름으로 다른 css 파일에 정의하여 셋팅하지 마세요. 그리고 너비나 정렬과 관련된 부분은 css를 통해 설정하면 안됩니다. 정렬이나 너비는 모두 시트의 기능을 통해 설정하게 되어있으므로 만일 css에서 이 부분을 강제로 조정하게되면 의도치않게 디자인 될 수 있습니다.

브라우져 별 속도 차이 문제.

IBSheet7은 사용자 피씨의 브라우져가 갖고 있는 스크립트 파서에 의해 속도가 결정됩니다. 따라서 구버젼의 브라우져와 신버젼의 브라우져간의 속도차이는 5배에서 20배까지 나타날 수 있습니다.

따라서 성능을 확인하고자 하시는 경우에는 최신브라우져(IE9,FF,chrome)등으로 테스트하여 주시기 바랍니다.

IE6,7의 메모리 릭 문제.오래된 브라우져의 메모리 릭 문제는 사실상 완벽한 해결이 어려움.jquery만 사용해도 릭이 발생함. 릭에 발생하는 경우에는 브라우져를 리프레쉬 할 수록 로딩속도가 떨어지게 되고, 계속하면 브라우저가 닫혀버리는 현상이 발생함. 이런 문제를 확인하고 해결하기 위해서는 실제 사용하는 모든 js 파일들 (jquery나 jquery-ui 등)을 한 페이지에 넣고, 현상이 발생하는지 확인하면서 어떤 js에서 릭이 발생하는지 찾아보아야함.

Down2Excel에서 param 넘길시 엔코딩 문제.넘겨질 파라미터는 엔코딩해서 문자열을 만들어 주어야 안전함.

function makeParamEncrypt(key,data){

    return "&"+encodeURIComponent(key)+"="+encodeURIComponent(data);

}

ShowModalDialog() 지원 문제.ShowModal함수는 웹 표준이 아님으로 지원하지 않음. 이건 모든 IB Sheet 7 제품군에 동일 사항임.

트리 사용시 IE8 문제.IE8의 자체 버그로 인해 IBSheet7의 트리가 4레벨을 넘어가면 속도가 지연되는 현상이 있음. 따라서 Tree를 사용하는 화면은 가급적 Meta 테그를 이용하여 페이지 해석을 IE7으로 맞추는 것이 좋음.

<%

System.out.println(request.getHeader("User-Agent"));

if(request.getHeader("User-Agent").contains("MSIE 8.0")) {

response.setHeader("X-UA-Compatible","IE=EmulateIE7");

}

%>

트리사용시 SetConfig()메서드에 ChildPage 인자를 사용(값은 10 정도로 설정)

그룹 기능(ShowGroupRow)은 수정/저장이 불가능함.기능은 단순 조회 용도로만 사용이 가능함.

앞 컬럼 머지 기능 사용시 데이터량 주의시트는 SetConfig에서 설정한 page 수를 기준으로 데이터를 나누는데, 중간에 위/아래로 머지가 있는 경우 page 수를 기준으로 머지가 끊어지게 된다.단 머지 유형이 앞컬럼 머지인 경우, SetConfig의에 PrevColumnMergeMode를 설정하면 맨 앞 컬럼이 머지된 데이터까지 한번에 메모리로부터 데이터를 읽어오게 되는데, 첫번째 컬럼에 1000개 행이 머지되어 있다면 1000개 행이 모두 한번에 화면 위로 올라오면서 속도 저하가 있을 수 있다.

 다수의 컬럼을 ColHidden 메서드를 이용하여 감출때, RenderSheet() 메서드를 사용ColHidden(),DataInsert(),InitCellProperty() 메서드 를 여러번 호출해야 하는 로직에서는 렌더링을 일시적으로 막았다고, 기능이 모두 수행되고 난 다음에 렌더링을 개선 함으로 써 속도 향상을 가져올 수 있다.

한 화면에서 시트 제품의 개수 제한제품에 사용한도는 없으나 화면에 시트가 많아질수록 페이지 로딩 속도가 지연되는 것은 피할수 없다. 따라서 일반적인 화면에서는 시트의 개수를 4개 이내로 사용할 것을 권한다.

FormQueryString() 메서드 관련 참고사항- FormQueryString()함수는 input 객체의 내용을 encoding 없이 서버로 전달함으로서 &나 = 과 같은 기호가 데이터에 포함되어있는 경우 문제가 될수 있다. 따라서 문자열을 엔코딩하여 서버로 전달하는 FormQueryStringEnc() 함수를 사용할 것을 권한다.

웹표준 준수IE브라우져의 경우 전반적인 스크립트엔진 속도는 브라우저의 버젼 뿐 아니라 문서모드에 따라서도 상당한 차이가 발생한다. 브라우져로 하여금 최신 스크립트 엔진으로 페이지를 해석하게 하려면 페이지 상단에 DOCTYPE선언이나 헤더에 메타를 통한 문서모드 설정이 필요하다.<!DOCTYPE html><html><meta http-equiv="X-UA-Compatible" content="IE=edge" />

가급적 form객체안에 시트를 넣지 말것. 그리고 form안에 시트를 넣는 경우에는 절대 input 객체의 이름을 event로 지정하면 안됨.

onclick="clickFunc(event)"  식으로 호출될때 IE8이하 브라우져에서 문제가 발생함.
