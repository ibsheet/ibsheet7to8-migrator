### [COMP-0001] IBChart 7.2를 7.3으로 교체하면 기존 차트 코드를 그대로 쓸 수 있나요?

**질문**

- IBChart를 7.2 버전에서 7.3 버전으로 업그레이드하면 기존 코드를 그대로 쓸 수 있나요?
- IBChart 7.3으로 올릴 때 기존 차트 함수를 그대로 호출해도 되나요? 시트처럼 제품 파일 교체만으로 테스트가 가능한가요?
- IBSheet만 최신 버전 파일로 교체했는데 IBChart는 기존 버전을 계속 써도 되나요? ibchart.js만 교체해서 업그레이드할 수 있나요?

**답변**

IBChart 7.3은 7.2를 고려해 만들지 않아서 `ibchart.js` 파일만 교체하는 방식으로는 업그레이드할 수 없습니다. 7.2 대와 7.3 대는 함수명과 속성명, 함수의 대소문자 등이 서로 다르며, 7.2에서 7.3으로의 전환은 업그레이드가 아니라 신규 개발 개념이므로 7.3 차트 샘플을 참고해 새로 개발해야 합니다.

- 함수명 변경은 대부분 첫 글자가 소문자로 바뀌는 형태입니다(예: `SetOptions` → `setOptions`). 기존 함수가 없어진 것은 아니라는 설명도 있습니다.
- 크롬 등 브라우저에서 문제가 없다면 기존 7.2를 그대로 유지해도 무방합니다. IBChart는 크롬이나 기타 브라우저 패치가 없었습니다.

**적용 버전**: IBChart 7.2 대와 7.3 대 차이

**키워드**: IBChart 7.3, IBChart 7.2, SetOptions, setOptions, ibchart.js, 차트 업그레이드, 함수명 대소문자

### [COMP-0002] IBChart 7.2 버전을 더 받을 수 없나요? 7.2와 7.3의 라이선스 호환은 어떻게 되나요?

**질문**

- IBChart 7.2 버전으로 화면을 개발해 사용 중인데 7.2 버전을 더 이상 받을 수 없나요? 7.3으로 바꾸려면 어떤 점을 주의해야 하나요?
- IBChart를 7.2에서 7.3으로 올려도 이전 라이선스와 이전 버전 코드가 호환되나요?

**답변**

highChart와의 Oem 계약에 따라 IBChart 7.2 버전은 더 이상 배포가 어려워 차트를 7.3으로 변경해야 합니다. 7.2와 7.3은 개발 소스가 다르므로 7.2로 개발된 화면은 소스를 변경해야 합니다.

- IBChart 7.2.1.6(20160613)은 이전에 구매한 라이선스로 사용할 수 있습니다.
- IBChart 7.3.1.8(20180810)은 신규 라이선스가 적용되며 이전 버전과 호환되지 않습니다.

**적용 버전**: IBChart 7.2 배포 중단, 7.3 사용 / 7.2.1.6(20160613) 기존 라이선스 사용 가능 / 7.3.1.8(20180810) 신규 라이선스

**키워드**: IBChart 7.2, IBChart 7.3, 7.2.1.6, 7.3.1.8, 라이선스, highChart Oem, 배포 중단

### [COMP-0003] IBChart 7.3에서 highcharts js와 modules 폴더의 js를 별도로 include해야 하나요?

**질문**

- IBChart를 7.3 버전으로 업그레이드할 때 하이차트 js를 따로 include해야 하나요? 특수한 차트를 쓸 때 필요한 js도 궁금합니다.
- IBChart로 차트를 그리려면 어떤 js 파일을 링크해야 하나요? 간트차트 같은 특수 모양 차트는 어떻게 하나요?
- IBChart 적용 시 스크립트 파일이 여러 개 있는데 모두 필수로 포함해야 하나요?

**답변**

IBChart는 highchart 기반 제품이며 7.3부터 `ibchart.js` 내부에 있던 하이차트 모듈이 분리되었으므로 하이차트 js를 include하는 부분을 추가로 작업해야 합니다.

- 기본 모양 차트: `highcharts.js`, `highcharts-more.js`가 링크되어 있어야 합니다.
- 간트차트 같은 특수 모양 차트: modules 폴더의 관련 js 파일도 링크합니다.
- 여러 스크립트 중 일부는 드릴다운, 웹접근성, 간트 등 확장 기능을 쓸 때 사용하는 모듈이므로, 파일을 많이 호출하면 브라우저 로딩 속도가 저하될 수 있어 꼭 필요한 경우에만 링크하는 것이 좋습니다.
자세한 내용은 도움말 Appendix에서 확인할 수 있습니다.

**적용 버전**: 차트 7.3

**키워드**: highcharts.js, highcharts-more.js, modules, 간트차트, 드릴다운, 웹접근성, ibchart.js

**키워드**: CreateIBChart2, ibchartinfo.js, IBChart

### [COMP-0005] IBChart 메시지를 영어 등 다른 언어로 바꾸려면 어떻게 하나요?

**질문**

- IBChart의 기본 메시지를 영어로 바꾸려면 영문 번역 내용은 어디에 있고 어떻게 적용하나요?
- IBChart 가이드에 메시지 파일 형식을 통한 다국어 지원이라고 되어 있는데 실제로 어떻게 지원되나요?

**답변**

`ibchartinfo.js` 파일의 `IBLANG` 변수에 영문으로 번역된 내용이 있습니다. `createIBChart` 함수 호출 시 메시지를 설정할 수 있으며 설정 방법은 IBTab과 같습니다. 도움말 '4.2 차트 객체 생성'을 참고합니다.
다국어를 위한 별도의 특별한 기능은 지원되지 않으며, `ibchartmsg.xml`에 나오는 한국어 문구를 필요한 만큼 수정해서 사용하는 방식입니다.

**키워드**: IBLANG, ibchartinfo.js, createIBChart, ibchartmsg.xml, 다국어, 영문 메시지

### [COMP-0008] IBChart·IBTab의 license.txt 파일 노출을 피하려면 어떻게 하나요?

**질문**

- 구버전 IBChart와 IBTab은 license.txt를 사용합니다. 보안 지적으로 license.txt 노출을 피하려면 어떻게 하나요?

**답변**

license.txt를 사용하던 구버전(약 2015년 무렵)의 IBChart와 IBTab에는 시트처럼 자바스크립트 변수를 키로 쓰는 기능이 없습니다. 다음 중 하나로 대응합니다.

- 방법 1) license.txt 확장자를 License.aspx 등으로 바꾸고 `ibchart.cfg`나 `ibmditab.cfg`의 `LicenseFileName`을 License.aspx로 변경합니다(경로와 ajax 호출 시 반환되는 key string은 기존과 같아야 합니다).
- 방법 2) 2016년 이후 제품으로 업그레이드하고 `ibleaders.js` 파일에 키를 넣습니다. IBChart는 큰 변경이 없지만 IBTab은 사이에 나온 버전이 많아 업그레이드 후 해당 화면 테스트가 필요합니다.

**적용 버전**: 2016년 이후 제품은 ibleaders.js에 키 입력

**키워드**: license.txt, LicenseFileName, ibchart.cfg, ibmditab.cfg, ibleaders.js, License.aspx

### [COMP-0009] IBChart 라이선스 경고창이 특정 서버나 IE에서만 뜹니다

**질문**

- 개발 서버에서만 라이선스 경고창이 뜨는데 운영 서버와 코드는 같습니다. 차트 쪽에서 license 파일을 제대로 읽지 못하는 것으로 보일 때 어떻게 해결하나요?
- IBChart 사용 시 Chrome에서는 괜찮은데 IE에서만 라이선스 경고창이 뜹니다. 차트 라이선스는 어느 파일에서 확인하며 원인은 무엇인가요?

**답변**

차트는 `ibchart.js`와 동일한 위치의 license 파일에서 라이선스를 확인합니다. 원인은 다음과 같을 수 있습니다.

- 차트가 license 파일을 제대로 읽지 못하는 경우: IBChart 7.2.1.5 버전을 넣고 `ibleaders` 변수로 라이선스를 체크하는 형태로 변경하자 정상 동작한 사례가 있습니다. 변경 후에는 해당 화면 전체를 테스트해야 합니다.
- 제공되는 차트라이트를 쓰지 않고 하이차트의 이전 버전을 사용하는 경우일 수 있습니다.

**적용 버전**: IBChart 7.2.1.5

**키워드**: 라이선스 경고창, license, ibchart.js, ibleaders, IBChart 7.2.1.5, IE

### [COMP-0010] 시트 외 컴포넌트(멀티콤보·차트·탭·Org)와 함께 쓸 때 라이선스 경고·오류가 납니다

**질문**

- IBMultiCombo를 새로 사용하게 됐는데 라이선스 경고가 뜹니다. 시트 라이선스는 이미 적용되어 있습니다.
- 시트는 없고 차트만 있는 화면(모바일)에서 라이선스 경고 메시지가 나옵니다.
- 한 화면에 시트와 차트를 각각 iframe으로 두었더니 라이선스 오류가 납니다.
- 시트는 ibleaders.js로 라이선스를 관리하는데 탭이 있는 화면에서만 라이선스 오류가 납니다.
- IB Org#와 IBSheet7 라이선스를 각각 적용했더니 둘을 같이 쓰는 화면에서만 시트에 오류가 납니다.

**답변**

다른 컴포넌트 쪽에서 `ibleaders` 변수를 잘못 호출하거나 로드하지 못할 때 라이선스 경고가 납니다. 원인별로 확인합니다.

- 멀티콤보: `ibsheetinfo.js`에 `ibleaders` 변수가 이미 설정되어 있는데 멀티콤보를 호출하는 부분에서 `ibleaders` 변수를 다시 호출하며 잘못된 키 값을 설정하면 마지막 호출한 키 값 때문에 경고가 납니다. 마지막에 호출한 `ibleaders` 변수를 삭제합니다.
- 시트 없이 차트만 있는 화면: `ibleaders` 변수 자체가 로드되지 않았을 수 있으므로 `ibleaders.js` 파일을 import한 뒤 다시 테스트합니다.
- 시트와 차트를 각각 iframe으로 구성한 화면: 차트가 들어 있는 쪽에서도 `ibleaders.js`를 호출해야 합니다.
- 탭: `ibleaders.js`로 라이선스를 관리하는 방식은 2016년 이후 버전에 적용되므로, 탭이 이전 버전이면 최신 버전으로 교체합니다.
- IB Org#를 시트와 같은 화면에서 함께 쓸 때: 라이선스 파일의 구조가 다르므로 iborg 쪽 `ibleaders.js` 파일을 확인합니다.

**적용 버전**: ibleaders.js 방식은 2016년 이후 버전

**키워드**: ibleaders, ibleaders.js, 라이선스 경고, iframe, IBMultiCombo, IB Org#, ibsheetinfo.js

### [COMP-0011] 차트를 함께 쓰는 화면에서 특정 IP나 라이선스 재발급 후 차트 라이선스 오류가 납니다

**질문**

- IP 4번째 자리가 모두 허용되는 라이선스 키를 적용했는데 특정 IP에서만 라이선스 오류가 납니다. 차트를 함께 사용하고 있습니다. 원인이 무엇인가요?
- 얼마 전 라이선스를 다시 받아 적용했는데 차트에서 라이선스 오류가 나옵니다. 차트 같은 다른 컨트롤에는 라이선스를 어떻게 적용해야 하나요?

**적용 버전**: 차트 7.2.1.3 사용 시

**키워드**: 차트 라이선스, license 파일, cfg, IP 허용, IBChart 7.2.1.3

### [COMP-0013] 차트 샘플의 공통 폴더에 js 파일이 여러 개 있는데 모두 필요한가요?

**질문**

### [COMP-0098] IBUpload5로 서버 파일 삭제·다운로드나 외부 input 버튼 연결이 되나요? 지원 브라우저는?

- Mac: Safari 지원
- 모바일(iOS, Android): 사용할 수 없습니다

### [COMP-0118] IBUpload로 10MB 이상 파일을 올리면 오류가 납니다. 파일 크기 관련 설정 3가지는?

**질문**

- IBUpload로 10MB 이상 파일을 올리면 10MB에서 업로드가 멈추고 Framework error와 Script error가 납니다. SetLimit 외에 확인할 파일 크기 설정이 있나요?
- IBUpload에서 업로드 파일 크기를 확인하거나 제한하는 함수와 설정에는 어떤 것이 있나요?

**답변**

파일 크기 관련 기능은 세 가지입니다. 환경에 맞게 설정합니다.

- `GetFileSize()`: 사용자가 파일을 추가할 때 해당 PC의 파일 사이즈를 반환합니다.
- `SetLimit()`: 업로드 컨트롤에 추가할 파일의 개수, 개별 용량, 전체 용량을 제한합니다.
- 서버사이드 `IBUpload.jsp`의 `MultipartParser` 설정: 전송되는 총 파일 크기를 정하며 256MB 이상으로 크게 설정해야 합니다(256MB 강력 권장). 이 값이 작으면 업로드가 도중에 멈추고 오류가 빈번히 발생할 수 있으며, `SetLimit`의 총 용량보다 반드시 크게 입력해야 '업로드 중 오류가 발생하였습니다' 오류가 나지 않습니다. 예: `new MultipartParser(request,256*1024*1024)`

**키워드**: MultipartParser, SetLimit, GetFileSize, IBUpload.jsp, 업로드 용량, Framework error
