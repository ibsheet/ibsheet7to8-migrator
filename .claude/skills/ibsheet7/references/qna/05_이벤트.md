## 이벤트 선언·인자·발생 순서

### [EVT-0001] OnBeforeDownload에서 frm.Data.value 사용 시 에러가 납니다 (이벤트 인자 선언)

**질문**

- OnBeforeDownload 이벤트에서 frm.Data.value로 전송 전문을 수정하려고 하면 에러가 납니다. 이벤트 인자를 어떻게 선언해야 하나요?

**답변**

`EventArgsMode:1`로 설정된 경우 이벤트 인자가 하나 더 추가되므로 `OnBeforeDownload(sheetid,type, frm)` 형태로 선언해야 합니다. `sheetid` 없이 `(type, frm)`으로 받으면 `frm.Data.value`에서 에러가 납니다.

**키워드**: OnBeforeDownload, EventArgsMode, frm.Data.value, sheetid

### [EVT-0002] OnLoad 이벤트에서 DataInsert 등 로직을 실행하면 안 되는 이유

**질문**

- 시트가 생성된 후에 호출되는 콜백 이벤트가 있나요? onLoad 이벤트 안에 로직을 넣어도 되나요?
- 시트를 만든 직후 OnLoad 이벤트에서 바로 DataInsert(-1)로 행을 추가하려는데 에러가 납니다.

**답변**

시트 생성 후 발생하는 이벤트로 `onLoad()`가 있지만, 이 이벤트는 시트 객체가 DOM으로 생성되기 이전에 발생하고 시트 초기화가 아직 완료되지 않은 시점입니다. 그래서 이벤트 재정의 정도만 처리하고 로직을 넣는 것은 피하며, `DataInsert(-1)` 같은 행 추가는 처리되지 않습니다. 초기화 함수인 `initSheet()` 호출 이후에 행 추가가 이뤄지도록 작업합니다.

**키워드**: OnLoad, DataInsert, initSheet, 시트 생성 후 이벤트, DOM

### [EVT-0003] LoadSearchData 호출 직후 후속 로직이 렌더링 완료 전에 실행됩니다

**질문**

- LoadSearchData 호출 직후 이어서 실행한 이벤트가 시트 렌더링이 끝나기 전에 발생합니다.
- OnSearchEnd에서 블록을 해제해도 그 전에 블록이 닫히는 것처럼 보입니다.

**답변**

`LoadSearchData`는 비동기로 동작하므로 호출 직후 이어서 실행한 이벤트나 후속 로직이 시트 렌더링이 끝나기 전에 실행될 수 있습니다. 조회 후 처리는 `OnSearchEnd()`에서 하거나, `LoadSearchData()`에 `sync:1` 옵션을 넣어 조회한 뒤 이후 로직을 호출합니다. `OnSearchEnd()`는 일반 조회 후에도 발생하므로 특정 호출 뒤에만 실행해야 한다면 sync 옵션 방식을 씁니다. `OnSearchEnd()`는 내부적으로 RenderFinish 후에 발행되지만 비동기라 화면에는 렌더링이 끝나지 않은 것처럼 보일 수 있어 `LoadSearchData({Fx:1, Sync:1})`처럼 Sync 옵션을 설정해야 합니다.

**키워드**: LoadSearchData, OnSearchEnd, sync:1, Sync, 비동기, RenderFinish

### [EVT-0004] 데이터 로드 시 이벤트 발생 순서는? 로드 직후 합계 값을 읽으려면

**질문**

- 시트에 데이터를 로드한 직후 실행되는 이벤트나 함수가 있나요?
- 리스트에서 합계(sum) 값을 가져와 처리해야 하는데 로드되기 전의 값이 읽힙니다.

**답변**

조회 함수나 데이터 바인딩 함수가 호출되어 시트가 그려질 때 `OnLoadData`, `OnRowSearchEnd`, `OnSearchEnd` 순으로 이벤트가 발생합니다. `OnRowSearchEnd`는 행 단위로 데이터를 렌더링할 때마다 호출되고, `OnSearchEnd`는 전체 데이터의 렌더링이 끝나는 시점에 한 번만 발생합니다. 로드된 합계(sum) 값을 가져와 처리하려면 `OnSearchEnd`에서 작업합니다.

**키워드**: OnLoadData, OnRowSearchEnd, OnSearchEnd, 이벤트 발생 순서, 합계

### [EVT-0005] OnRowSearchEnd를 쓰면 속도가 느려집니다. 대안은?

**질문**

- 트리에서 특정 레벨의 행에만 체크박스를 노출하려고 OnRowSearchEnd 이벤트로 구현했더니 속도가 너무 느립니다.
- 성능 면에서 OnRowSearchEnd 이벤트를 써도 되나요?

**답변**

`OnRowSearchEnd` 이벤트는 성능 저하에 직접적인 영향을 줄 수 있어 가급적 사용을 지양하도록 권장합니다. 대신 `OnLoadData` 시점에 데이터를 직접 가공하는 방식을 사용합니다.

**키워드**: OnRowSearchEnd, OnLoadData, 성능 저하, 트리 체크박스

### [EVT-0006] OnLoadData 이벤트는 어느 버전부터 지원되나요?

**질문**

- OnLoadData 이벤트를 사용하려는데 동작하지 않습니다. 이 이벤트는 어느 버전부터 지원되나요?

**답변**

**적용 버전**: 7.0.0.0-20140117-10-M에서 최초 개발

**키워드**: OnLoadData, 최초 지원 버전, 7.0.0.0-20140117-10-M

### [EVT-0007] 서버모듈 2.0에서 LoadText 후 OnLoadText 이벤트가 발생하지 않습니다

**질문**

- 서버모듈 2.0에서 LoadText로 텍스트 파일을 로드한 뒤 OnLoadText 이벤트가 발생하지 않습니다. 로드된 데이터를 가공하려면 어떻게 하나요?

**답변**

서버모듈 2.0에서는 `OnLoadText` 이벤트가 발생하지 않으며 수정이 필요한 현상입니다. 대신 `OnLoadData` 이벤트가 발생하므로 이 이벤트에서 서버가 보낸 JSON 결과를 받아 값을 추출하거나 다른 시트에 바인딩하는 처리를 할 수 있습니다.

**적용 버전**: 서버모듈 2.0

**키워드**: OnLoadText, LoadText, OnLoadData, 서버모듈 2.0

### [EVT-0008] 컬럼 드래그 그룹핑 시작 시점에 허용·취소하려면? (OnGroupStart)

**질문**

- 그룹행을 사용할 때 헤더 컬럼을 드래그해 그룹핑하는 시작 시점에 조건을 검사해 그룹핑을 허용하거나 취소할 수 있는 이벤트가 있나요?

**답변**

그룹핑 시작 시점의 이벤트로 `OnGroupStart(cols)`가 제공되며 `cols`는 현재 그룹핑 중인 컬럼입니다. 이 이벤트에서 조건에 따라 true를 반환하면 그룹핑을 허용하고 false를 반환하면 허용하지 않도록 구현할 수 있습니다. 예제는 조회된 데이터가 있을 때만 그룹핑을 허용합니다. 이 이벤트는 기능 요청에 따라 별도 배포로 제공되었습니다.

**적용 버전**: 별도 배포로 제공

**키워드**: OnGroupStart, 그룹핑, cols, true, false

### [EVT-0009] Enable(False)로 비활성화한 그리드에서는 이벤트를 받을 수 없습니다

**질문**

- 그리드를 Enable(False)로 비활성화한 상태에서 그리드 이벤트를 받으려는데 클릭이 동작하지 않습니다. 어떻게 처리해야 하나요?

**답변**

그리드를 `Enable(False)`로 설정한 상태에서 그리드 이벤트를 받는 방식은 동작하지 않습니다. 이벤트는 상위 Div에서 받거나 다른 방식으로 처리해야 합니다.

**키워드**: Enable, Enable(False), 그리드 이벤트, 상위 Div

### [EVT-0010] 이벤트 공통 처리 기능이 있나요? 복사한 이벤트 함수가 동작하지 않는 이유

**질문**

- OnBeforeMovePage나 DoSearchPaging 호출 시 항상 공통으로 특정 동작(예: 화면 block 처리)을 실행하는 전역 옵션이 있나요?
- 다른 시트의 Checkbox 이벤트 함수(OnBeforeCheck)를 복사해 붙여넣었는데 이벤트가 동작하지 않습니다.

**답변**

- 공통 처리: 공통으로 이벤트를 처리하는 기능은 제품에서 제공하지 않으므로 이벤트를 재정의하는 방식으로 구현해야 합니다.
- 복사한 이벤트 함수가 동작하지 않을 때: 동일한 function이 하단에 이미 존재하는 경우가 있습니다. 이때는 새로 만든 function을 주석 처리하고 기존 function에서 처리하면 정상 동작합니다. 중복 정의부터 확인합니다.

**키워드**: OnBeforeMovePage, DoSearchPaging, OnBeforeCheck, 이벤트 재정의, 중복 function

### [EVT-0011] 시트 이벤트 함수는 어떻게 선언하나요? 이벤트가 호출되지 않을 때 확인할 점

**질문**

- IBSheet7에서 OnClick 같은 이벤트를 사용하려면 함수를 어떤 이름으로 작성해야 하나요?
- 서브시트_OnClick 형태로 이벤트 함수를 만들었는데 이벤트가 호출되지 않습니다.
- 이벤트를 정해진 이름의 함수(mySheet_OnButtonClick)로 만들지 않고 그리드 인스턴스에 핸들러를 직접 할당하는 방식으로 쓸 수 있나요?

**답변**

시트 이벤트는 `시트id_이벤트명` 형태의 function으로 선언합니다. 예: `function mySheet_OnClick(Row, Col, Value, CellX, CellY, CellW, CellH, rowType)`. 이벤트명의 철자와 대소문자가 정확해야 하며, `Onclick`처럼 대소문자를 다르게 선언하면 호출되지 않을 수 있습니다. IBSheet7의 이벤트 선언 방식은 function 객체를 선언하는 형태로만 제공되며 인스턴스에 핸들러를 할당하는 방식은 제공되지 않습니다.

**키워드**: OnClick, mySheet_OnClick, 이벤트 함수 선언, 대소문자, OnButtonClick

### [EVT-0012] 그리드 포커스 아웃(다른 곳 클릭) 이벤트가 있나요?

**질문**

**답변**

**키워드**: 포커스 아웃, OnClick, focus out

### [EVT-0013] OnClick에서 return false 하면 이후 동작이 중단됩니다 (SetComboOpenMode, onObjectClick 등록 시 콤보가 안 열림)

**질문**

- SetComboOpenMode와 OnClick을 같이 사용할 때 이벤트에서 return false를 하면 동작하지 않고 그냥 return만 하면 정상 동작합니다.
- onObjectClick 이벤트가 등록되어 있으면 콤보 셀이 한 번 클릭으로 열리지 않고 더블클릭해야 열립니다.

**답변**

Click 이벤트에서 false를 반환하면 이후 이벤트 처리를 종료하도록 처리됩니다. `SetComboOpenMode`를 같이 쓰는 경우처럼 후속 동작이 필요하면 false를 반환하지 말고 return만 합니다.
`onObjectClick`이 등록되어 있으면 클릭 이벤트를 처리하는 공통 함수(`IBSheet7Wrapper.EventDelegate`)가 호출되고, 이 함수가 `OnClick` 처리 후 마지막에 `return false;`를 반환해 이후 클릭 동작이 차단되므로 콤보 목록이 열리지 않고 더블클릭해야 열립니다. 함수 하단에 `eventName == "OnClick"`이면서 클릭한 셀의 Type이 `Combo`인 경우 `return;`으로 빠져나가는 분기를 추가하면 한 번의 클릭으로 열리며, 이 분기는 OnClick 이벤트이면서 Combo 타입 셀인 경우로만 한정되어 다른 동작에는 영향이 없습니다.

**키워드**: OnClick, return false, SetComboOpenMode, onObjectClick, IBSheet7Wrapper.EventDelegate, Combo

### [EVT-0014] OnClick 발생을 막거나, 같은 셀 재클릭 시 OnClick이 발생하지 않을 때

**질문**

- 셀을 클릭해도 OnClick 이벤트가 발생하지 않게 하고 싶습니다. 링크를 건 셀을 조건별로 동작하지 않게 하려면?
- 같은 셀을 다시 클릭했을 때 OnClick 이벤트가 발생하지 않습니다. 원래 이런 건가요?

**답변**

- 클릭했을 때 `OnClick` 이벤트가 발생하지 않게 하는 설정은 없습니다. `OnClick`에 전달되는 Row, Col, Value 인자로 동작 영역을 제한하거나 특정 값일 때만 처리하도록 원하는 조건으로 이벤트를 처리합니다.
- `OnClick`은 동일 셀에서도 호출됩니다. 호출되지 않는다면 사용 중인 프레임워크 등 시트 외부의 문제일 가능성이 있습니다.

**키워드**: OnClick, Row, Col, Value, 동일 셀 클릭

### [EVT-0015] OnClick에서 클릭한 컬럼을 구분하려면? (SaveName 비교, 체크박스 컬럼, DelCheck)

**질문**

- 행을 선택할 때 체크박스 컬럼을 클릭한 선택과 다른 컬럼을 클릭한 선택을 구분하려면 어떻게 구현하나요?
- 클릭 이벤트가 모든 컬럼에서 동작하는데 특정 컬럼에서만 동작하게 하려면 클릭한 셀의 컬럼 id 값은 어떻게 알 수 있나요?
- DelCheck 컬럼을 만들고 OnClick 이벤트에서 값을 확인하려는데 잘 되지 않습니다.

**답변**

### [EVT-0017] 시트 이벤트는 어떻게 선언하나요? (전역 시트ID_이벤트명 형식, 동적 지정·addEventListener 제약)

**질문**

- 시트를 생성하면서 OnClick 이벤트를 설정할 수 있나요? 이벤트는 어떻게 선언하나요?
- 시트에서 이벤트 함수를 선언했는데도 계속 이벤트가 동작하지 않습니다.
- `객체.이벤트 = function(){}` 형태나 mySheet.OnSearchEnd() 직접 호출, addEventListener 방식으로 이벤트를 등록할 수 있나요?

**답변**

시트 이벤트는 시트 생성 코드 이후에 `시트id_이벤트명(){}` 형태의 함수로 선언합니다. IBSheet는 시트 생성 시 이벤트를 `시트ID_이벤트명()` 형태로 만들며 ibsheet.js에 정의된 방식으로만 사용할 수 있습니다.

- 이벤트 함수는 시트 객체명을 이용해 전역에 function 객체로 선언해야 하며, 별도의 함수로 만들어 두었다가 동적으로 지정해 호출하는 방식은 지원되지 않습니다.
- 시트가 생성되는 시점 이후에 이벤트 함수를 선언하면 동작하지 않을 수 있으므로 샘플과 동일하게 전역에 선언합니다.
- `시트객체.이벤트 = function(){}` 형태는 제공되지 않습니다. 시트 id를 변수로 다루는 경우에는 `window[sheet.id+'_OnSearchEnd'] = function(code, msg, StCode, StMsg, Response){}`처럼 window 객체에 `id_이벤트명` 이름으로 정의합니다. `mySheet.OnSearchEnd()`처럼 바로 호출할 수는 없고 `Window[sheetId]`로 접근합니다.
- `ibsheet객체_이벤트명` 규칙의 function 객체로만 등록되므로 `addEventListener`처럼 같은 이벤트에 리스너를 추가로 등록(멀티바인딩)하는 방식은 지원되지 않습니다.

**키워드**: 시트ID_이벤트명, 이벤트 선언, 전역 함수, window[id+'_OnSearchEnd'], addEventListener, OnClick, OnSearchEnd

**질문**

### [EVT-0026] 서버가 보낸 메시지를 OnSearchEnd/OnSaveEnd의 Msg 인자로 받으려면?

**질문**

- 서버에서 저장·조회 결과 메시지를 내려주고 OnSaveEnd나 OnSearchEnd 이벤트에서 받아 알림창으로 띄우려면 어떻게 하나요?
- 서버 응답 JSON의 Result에 msg 키로 담아 보냈는데 OnSaveEnd의 Msg 파라미터는 빈 값입니다.
- 조회 결과에 문제가 있을 때 서버에서 메시지를 내려주고 OnSearchEnd 이벤트에서 표시하려면 어떻게 하나요?

**답변**

시트가 받아들일 수 있는 데이터 구조로 응답해야 합니다. 서버 응답의 Result에서 메시지를 담는 키는 `Message`여야 하며, 그러면 `OnSearchEnd`와 `OnSaveEnd` 이벤트의 두 번째 인자(Msg)로 받을 수 있습니다. `msg` 같은 임의의 키 이름으로 담으면 Msg 파라미터에 값이 전달되지 않습니다. HTTP 상태가 200이고 JSON으로 오류 내용을 보내는 경우에도 `{ Message : '오류내용' }`처럼 Message에 사용자에게 보여줄 내용을 담습니다. 조회는 도움말 6.2.1.5 RESULT 요소를 참고해 데이터를 구성하면 `OnSearchEnd`의 Code와 Message에 값이 전달됩니다. `OnSearchEnd`에서 Msg 값이 빈 문자열이 아닐 때 alert로 띄우는 구조라면 의도하지 않은 경고창은 서버의 조회 처리 로직이 해당 값을 내려주기 때문이므로 서버 쪽을 확인합니다. 자세한 구조는 개발자 가이드 6장을 참고합니다.

**키워드**: OnSaveEnd, OnSearchEnd, Message, Msg, Result, 메시지 처리

### [EVT-0027] 저장 후 OnSaveEnd Code가 -4로 옵니다 (응답이 200인데도)

**질문**

- 저장 후 네트워크 탭에서는 응답이 200이고 XML 구조도 정상인데 OnSaveEnd 이벤트의 Code가 -4로 옵니다.

**키워드**: OnSaveEnd, -4, 파싱 오류, 세션 끊김, redirect, F12

### [EVT-0028] OnSearchEnd·OnSaveEnd의 Code 값 0, -3, -4, -5, -6은 각각 무슨 뜻인가요?

**질문**

- OnSearchEnd 이벤트에서 받은 Code 값이 -3, -4, -5, -6처럼 음수로 오는데 각각 어떤 의미인가요?
- OnSaveEnd 이벤트의 Code 값이 -4로 전달되는 경우는 어떤 상황인가요?

- `0`: 정상
- `-3`: 요청 Url이 잘못되었거나 네트워크 오류 등으로 결과를 받지 못한 경우
- `-4`: 정상 응답은 받았으나 응답 결과 파싱 중 오류가 난 경우(대부분 데이터 이상). 조회에서는 받은 데이터의 JSON 문법·구조가 올바르지 않을 때 나타나므로 서버 응답 JSON을 점검합니다.
- `-5`: 응답 결과가 빈 값인 경우
- `-6`: 서버 응답 대기시간이 초과된 경우(WaitTimeOut 초과, 타임아웃)
`-1`, `-2`는 정의된 코드가 없어 저장 실패는 `-1`, 성공은 `0`을 반환하도록 구현할 수 있습니다. -3~-6 상황에서는 서버가 지정한 code와 msg 대신 IBSheet7에 내장된 코드가 반환되므로 서버가 보낸 Code·Message가 원하는 값으로 전달되지 않을 수 있습니다. 서버에서 Code를 직접 지정하려면 응답에 `<RESULT CODE='11' MESSAGE='1111'></RESULT>` 형태로 담아 보냅니다. 이 코드표는 7.x.x.x 가이드가 아닌 7.13.x.x 가이드 문서에 나옵니다.

**키워드**: OnSearchEnd, OnSaveEnd, Code, -3, -4, -5, -6, WaitTimeOut

### [EVT-0029] 저장 성공·실패에 따라 재조회·메시지·오류 팝업을 처리하려면? (OnSaveEnd code, msg)

**질문**

- 저장 후 성공 여부를 확인해 성공하면 재조회하고 실패하면 별도 처리하려면 어떤 이벤트를 사용하나요?
- DoSave 호출 후 저장 결과에 따라 alert 창 등으로 표시하는 메시지는 어떤 이벤트의 어떤 인자를 사용해야 하나요?
- 저장 실패 시 화면에 오류 메시지 팝업을 띄우려면 어떤 이벤트를 사용해야 하나요?

**답변**

`OnSaveEnd(code, msg)` 이벤트를 사용합니다. DoSave는 저장 URL을 호출해 저장 결과 XML을 읽어 들인 뒤 `OnSaveEnd`를 발생시키고 종료하므로, 저장 결과 메시지 처리(alert, 오류 팝업 등)는 이 이벤트의 `Code`와 `Msg` 인자에서 구현합니다. 형식은 `function mySheet_OnSaveEnd(code,msg){ ... }`이며 `code >= 0`이면 저장 성공으로 보고 재조회하거나 `msg`로 성공 메시지를 표시하고, 아니면 실패 처리를 합니다. `msg`가 비어 있지 않으면 알림으로 표시할 수 있습니다. 메시지 뒤에 `\r\n` 문자열이 붙어서 내려오므로 사용 전에 제거합니다.

**키워드**: OnSaveEnd, DoSave, Code, Msg, 재조회, 오류 팝업

### [EVT-0030] OnSearchEnd에서 오류 코드별로 메시지를 분기하려면? (IBSheet3과 인자 차이)

### [EVT-0031] 저장 시 서버가 500·502 오류를 반환하면 시트에서 어떻게 처리하나요? (Code -3)

**질문**

- 저장한 뒤 서버에서 500 error가 발생하면 시트에서 이를 처리할 방법이 있나요?
- OnSaveEnd에서 서버가 500 에러를 반환하면 Code가 -3으로 전달되고 메시지가 나오지 않습니다.
- 저장 로직이 오래 걸려 연결이 끊기고 서버가 502 오류를 반환합니다. WaitTimeOut을 늘려도 같을 때 시트에서 오류를 어떻게 알 수 있나요?

**답변**

- `OnSaveEnd` 이벤트의 `Response` 인자를 사용합니다. Response는 서버에서 정상적으로 처리되지 않은 경우(응답 코드가 100보다 작거나 400 이상일 때)에만 전달되므로 이 응답 결과 코드로 분기합니다.
- `OnSearchEnd`, `OnSaveEnd` 이벤트는 `responseText`를 인자로 전달하도록 처리되어 있어, 500 에러로 Code가 -3이 되고 메시지가 나오지 않을 때 이 인자로 서버 응답 내용을 받을 수 있습니다. 반영된 버전은 확인되지 않았습니다.
- 502 같은 서버 측 오류는 서버 환경마다 설정이 달라 시트 차원의 별도 참고 자료가 없습니다. 다만 `OnSaveEnd`의 3번째, 4번째 인자로 에러코드가 전달되므로 이를 보고 후처리를 판단합니다.

**키워드**: OnSaveEnd, Response, responseText, 500, 502, WaitTimeOut, -3

- 화면에 시트가 여러 개 있을 때 모든 시트의 데이터 로드가 끝난 시점에 이벤트를 발생시키려면 어떻게 확인하나요?

- 조회가 끝나 데이터 바인딩과 화면 렌더링이 모두 끝난 뒤에 발생하는 이벤트가 있나요?

**답변**

데이터 바인딩이 끝난 뒤에는 `OnSearchEnd` 이벤트가 발생합니다. 로딩 이미지가 사라진 다음 시점을 알려 주는 별도의 이벤트는 없으며, `OnSearchEnd` 이벤트가 끝나는 시점을 렌더링이 끝나는 시점으로 보면 됩니다. 자체 대기 이미지는 `onSearchEnd` 이벤트에서 감추는(hide) 시점을 잡으면 될 것 같습니다. 시트가 여러 개일 때는 전역 변수를 두고 각 시트의 `OnSearchEnd`에서 카운터를 증가시켜, 예를 들어 `onsearchCnt++; if(onsearchCnt==3){ ... }`처럼 카운트가 시트 수와 같아지면 최종 처리 함수를 호출합니다.

### [EVT-0041] OnSearchEnd에서 조회한 시트 객체나 조회 조건을 알 수 있나요?

**질문**

- OnSearchEnd 이벤트에서 공통 로직으로 조회한 시트의 메서드를 호출하고 싶은데 인자에 시트 객체가 없습니다.
- OnSearchEnd 이벤트 안에서 조회할 때 사용한 조회 조건을 알 수 있나요?

**답변**

- 시트 객체: `OnSearchEnd`는 인자에 조회한 시트 객체가 없어 메서드 응용이 어렵습니다. 시트 배열인 `Grids` 중 create 이후 Focused가 된 조회 시트를 찾아 사용합니다. 예: `Grids.Focused.SetCellBackColor(1, 0, '#FF0000')`.
- 조회 조건: `OnSearchEnd`에서는 조회 조건을 알 수 없으며 조건에 따른 처리는 `DoSearch` 호출 전에 먼저 하는 것이 맞습니다. 꼭 필요하면 조회 전에 시트 객체에 변수를 설정(`sheet.A = 조회 파라미터`)하고 `OnSearchEnd`에서 `sheet.A`로 꺼내 씁니다.

**키워드**: OnSearchEnd, Grids, Grids.Focused, 조회 조건, 시트 객체

### [EVT-0042] 세션 만료·서버 오류 응답을 모든 화면에서 공통으로 처리하려면? (OnLoadData 오버라이드)

**질문**

- OnSearchEnd나 OnSaveEnd를 모든 화면에 정의하기 어려울 때 조회·저장 응답의 세션 만료 같은 오류를 공통으로 처리하는 방법이 있나요?
- DoSearch나 DoSave 중 세션이 끊기면 시트가 오류만 내고 로그인 페이지로 이동하지 않습니다.
- 이전 IBSheet에서 ServerMessage 속성으로 처리하던 서버 오류를 지금은 어떻게 처리하나요?
- 서버가 404 같은 오류 응답을 내려줄 때도 OnLoadData 이벤트가 발생하나요?

**답변**

`OnSearchEnd`, `OnSaveEnd`보다 먼저 발생하는 `OnLoadData` 이벤트를 `ibsheetinfo.js`의 `createIBSheet()`/`createIBSheet2()`에서 오버라이드해 공통 대응합니다.

- 서버가 `Result : {Code:-256, Message:...}` 형태의 오류 JSON을 내려주면, 이 이벤트에서 수신 데이터를 JSON으로 변환해 `Result.Code`가 음수일 때 메시지를 알리고 `location.href`로 로그인 페이지로 이동시킵니다(예: -7이면 메시지 후 이동). `DoSearch`, `DoSave` 양쪽에 쓸 수 있으며 예제는 XML 응답을 고려하지 않습니다.
- 화면에 정의된 `OnLoadData`가 있으면 변수에 보관했다가 공통 로직 뒤에 호출합니다. 공통 처리가 필요 없다면 `OnLoadData`에서 반환받는 Data의 `Result` 값을 참조합니다.
- 서버가 HTTP 코드 200으로 로그아웃 메시지를 내려주는 세션 만료 구조라면 `OnLoadData`로 들어오는 데이터를 분석해 세션을 체크합니다.
- 공통 프레임워크에서 서버 에러 내용을 미리 정의해 두고 `OnLoadData`에서 에러 내용에 따라 분기하면 에러 메시지를 공통으로 처리할 수 있습니다.
- 404 같은 오류가 반환되면 `OnLoadData`는 발생하지 않으며 응답이 200일 때만 발생합니다.

**키워드**: OnLoadData, createIBSheet, 세션 만료, Result.Code, 공통 오류 처리, ibsheetinfo.js

### [EVT-0043] OnLoadData 사용 시 오류가 나거나 저장이 안 되거나 변경이 반영되지 않는 경우

**질문**

- OnLoadData에서 문자열 data를 JSON으로 파싱한 뒤 data.data 배열을 for문으로 순회하는데 에러가 납니다.
- 저장했는데 OnSaveEnd 이벤트가 발생하지 않습니다. OnLoadData에서 작업하고 있는데 관련이 있나요?
- 조회 로직을 OnSearchEnd에서 OnLoadData로 옮겼더니 조회는 빨라졌지만 저장이 되지 않습니다.
- OnLoadData 이벤트에서 조회 데이터를 가공했는데 변경 내용이 화면에 반영되지 않습니다.
- OnLoadData 안에서 GetTreeJson()을 호출하면 Array(0)이 나옵니다.

**답변**

`OnLoadData`는 시트에 데이터를 바인딩하기 전, 렌더링 전에 데이터를 받아 가공할 수 있는 이벤트입니다. 확인할 사항은 다음과 같습니다.

- 가공한 JSON 객체를 반드시 return 해야 변경 값이 반영되어 렌더링됩니다.
- 바인딩 전에 발생하므로 이 안에서 `GetTreeJson()`을 호출하면 `Array(0)`이 나옵니다. 서버에서 받은 데이터는 인자로 넘어온 data를 가공해 리턴하는 형태로 처리합니다.
- 조회 함수와 저장 함수(`DoSave()`)를 호출할 때 모두 발생합니다. 저장 시 전달되는 데이터를 고려하지 않고 처리하면 에러가 발생해 `OnSaveEnd`가 발생하지 않거나 저장이 되지 않을 수 있습니다. JSON 안에 `Result`가 있으면 더 이상 진행하지 않도록 수정합니다.
- JSON 키는 대소문자를 구분합니다. 데이터 배열의 키가 `data`가 아니라 `Data`여서 for문이 동작하지 않은 사례가 있으므로 조회 JSON의 실제 키 이름을 확인합니다.

**키워드**: OnLoadData, return, DoSave, OnSaveEnd, Result, GetTreeJson, 대소문자

### [EVT-0044] OnSearchEnd의 loop가 느립니다. OnLoadData에서 처리하면 빠른가요?

**질문**

- 조회 후 OnSearchEnd 이벤트에서 행마다 루프를 돌며 데이터를 가공하고 있는데 더 나은 방법이 있나요?
- OnSearchEnd에서 loop를 돌며 데이터를 처리하니 느립니다. OnSearchEnd보다 빠른 이벤트가 있나요?
- JSON 데이터를 바인딩할 때 데이터 조건에 따라 editable을 처리하려면 어느 이벤트에서 해야 하나요?
- 조회 후 불필요한 행을 OnLoadData에서 빼는 경우와 OnSearchEnd에서 삭제하는 경우 변경 데이터 판단이 어떻게 다른가요?

**답변**

`OnSearchEnd`에서 loop를 돌며 처리하는 방식은 느리므로 `OnLoadData` 이벤트에서 JSON 데이터를 수정하는 방법을 권장합니다. 조건별 editable 처리는 `OnLoadData()` 또는 `OnSearchEnd()`에서 할 수 있으며 속도 면에서는 `OnLoadData`가 더 빠릅니다. `OnSearchEnd`보다 빠른 이벤트는 `OnLoadData` 외에는 없으며, 이때 데이터는 도움말 6.2.1.1 DATA 요소의 데이터 구조와 같이 리턴해야 합니다.
변경 상태 판단도 다릅니다. `OnLoadData()`에서 처리하면 조회될 데이터 자체가 가공되므로 시트는 수정된 데이터가 없다고 판단하고, `OnSearchEnd()`에서 데이터가 그려진 이후에 행을 삭제하면 변경된 데이터가 있다고 판단합니다.

**키워드**: OnLoadData, OnSearchEnd, loop 성능, editable, 변경 상태, DATA 요소

### [EVT-0045] 조회 데이터를 바인딩 전에 가공·변환하려면? (표시값 변환, HTML 변환, 가로 머지, JsonAttribute)

**질문**

- 조회 결과 컬럼 값('Y'/'N')을 '예'/'아니오'로 바꿔 보여주고 싶습니다. 루프로 직접 수정하지 않고 표시 값만 바꾸는 방법이 있나요?
- 음수 값을 삼각형 모양으로 보여주려고 하는데 표시 포맷이 없다면 화면에 표시하기 전에 값을 바꿀 수 있는 방법이 있나요?
- 조회 데이터에 포함된 HTML 코드를 시트에 바인딩하기 전에 일반 문자로 변환하고 싶습니다.
- 서버에서 조회해 온 데이터를 시트에 로드하기 전에 내용을 수정하려면 어떤 이벤트를 사용하나요?
- 조회한 값에 따라 시트 생성 시점에 formula 같은 조건식을 넣을 수 있나요?

**답변**

표시 값만 바꾸는 별도 방법은 없고, 데이터를 시트에 바인딩하기 직전에 발생하는 `OnLoadData` 이벤트에서 처리합니다. 이 이벤트는 반드시 return 값이 있어야 합니다.

- 값 변환: 전체 행을 루프로 돌면서 값을 변경합니다.
- HTML 코드를 문자로 변환: `var d = document.createElement("div"); d.innerHTML = data; return d.innerText;`
- 조회 데이터 재구성: 가로 머지를 위해 조회 결과를 가공하는 로직 등을 이 이벤트로 옮겨 처리합니다.
- 조건에 따른 활성화·색상 처리: IBSheet7에는 시트 생성 시점의 formula 기능이 없어 데이터를 받아 처리하는 시점에 해야 하며, `OnSearchEnd`보다 먼저 발생하는 `OnLoadData`에서 `JsonAttribute`를 이용할 수 있습니다.
- 수정한 데이터를 시트에 조회합니다. 서버 페이징에서 필터를 서버 쿼리로 처리하는 방법은 확인되지 않았습니다.

**키워드**: OnLoadData, JsonAttribute, 데이터 가공, HTML 변환, 가로 머지, return

### [EVT-0060] OnSaveEnd의 Code가 항상 -1이거나 서버가 보낸 값과 다르게 옵니다

**질문**

- 그리드 저장 후 OnSaveEnd의 Code 값이 계속 -1만 리턴됩니다. 데이터는 DB에 정상 저장됩니다.
- OnSaveEnd의 Code 인자는 무엇을 의미하나요? 결과에 code가 없으면 어떤 값이 오나요?
- 서버가 응답으로 Code를 -1로 보냈는데 OnSaveEnd에서 Code가 0으로 찍힙니다.
- 서버가 보낸 code 값을 OnSaveEnd에서 받지 못하는 것 같습니다.

**답변**

- Code는 시트가 자동으로 판단하는 값이 아니라 서버가 내려준 결과의 code 값이며, 결과 XML에 code가 없으면 -1이 전달됩니다. 서버단에서 성공 시 0 또는 0 이상, 오류 시 0 이하의 값을 리턴하도록 구현하고, `{Result:{Code:0,Message:'저장 되었습니다.'}}` 또는 `{Result:{Code:-1,Message:'오류가 발생하였습니다.'}}` 같은 값을 서버에서 rtnData에 넣어 보냅니다.
- OnSaveEnd의 Return Code는 0 이상이면 정상, 음수이면 오류로 판단합니다. -3~-6은 정의된 오류이고 그 외 코드는 사용자가 지정할 수 있으며 -1과 -2는 정의된 코드가 없으므로, -1은 서버 사이드에서 저장 실패 시 보내도록 구현된 값으로 보입니다. 서버 로직을 디버깅해 어떤 처리일 때 -1이 출력되는지 확인합니다. 저장 실패는 -1, 성공은 0을 보내도록 구현하면 됩니다. 이 코드들은 StCode가 200일 때 나타나는 코드이며, 200이 아닌 코드는 StCode를 함께 출력해 확인합니다.
- 서버가 -1을 보냈는데 OnSaveEnd에서만 0으로 보인다면 응답에 쓴 code 이름의 대소문자가 맞지 않아서일 수 있으니 대소문자를 맞춥니다.
- 다른 설명으로는 서버가 보내는 `code>0`이면 정상 저장으로 판단되며 보낸 code 값은 OnSaveEnd에서 받을 수 있고, 에러일 때 받아야 할 메시지는 응답(response) 부분에 넣어야 한다고 합니다. Jackson 라이브러리를 쓸 때는 name과 value를 Map에 넣어 code 값을 구성할 수 있습니다.

**키워드**: OnSaveEnd, Code, -1, Result, Message, StCode, Jackson

- OnEditValidation은 자동계산 컬럼의 셀도 함께 체크하나요?

**답변**

- `ColValueDup`: `OnEditValidation` 안에서 사용하면 편집된 값이 아니라 데이터셋에 있는 데이터를 기준으로 체크하는 것이 정상 동작입니다. 편집 값으로 검사하려면 `OnChange` 이벤트에서 사용하거나 `FindText`를 이용해야 할 것으로 보입니다.
- 날짜 타입 컬럼: 달력으로 선택한 값을 `OnEditValidation`에서 정상적으로 받지 못하므로 해당 검사는 `onchange` 이벤트에서 처리하는 것이 좋습니다.
- 자동계산 컬럼: `OnEditValidation`은 편집한 셀만 체크하며 자동계산 컬럼에 해당하는 셀까지는 지원하지 않습니다.

**키워드**: OnEditValidation, ColValueDup, FindText, OnChange, 날짜 컬럼, 자동계산

### [EVT-0066] 붙여넣기(Ctrl+V)를 감지하고 붙여넣은 셀 위치를 알려면? (OnChange RaiseFlag 2, OnAfterPaste)

**질문**

- 복사 후 붙여넣기로 값이 바뀔 때만 별도 처리를 하고 싶습니다. 붙여넣기 관련 이벤트와 붙여넣은 위치(행, 열)를 알 수 있는 방법이 있나요?
- 엑셀에서 복사해 시트에 붙여넣을 때 OnChange가 발생하지 않는 것 같습니다. 붙여넣기만 구분해서 처리하려면 어떻게 하나요?
- onkeyup에서 키코드로 Ctrl+V를 감지하면 빠르게 누를 때 이벤트가 잘 발생하지 않습니다.
- 셀을 편집하거나 값을 붙여넣은 뒤 검증·통신 같은 로직을 실행하려면 어느 이벤트를 써야 하나요?

**답변**

붙여넣기에서도 `OnChange`는 발생합니다. `OnChange(Row, Col, Value, OldValue, RaiseFlag)`의 `RaiseFlag`가 2(Ctrl+V)이면 붙여넣기로 값이 바뀐 것이므로 이 값으로 분기하며, 여러 셀을 붙여넣으면 셀별로 Row와 Col이 모두 전달됩니다.

- `OnBeforePaste(text)`와 `OnAfterPaste()`도 있지만 붙여넣기가 진행된 위치(행, 열) 정보는 갖고 있지 않으며, `OnAfterPaste`에서는 붙여넣을 데이터만 확인할 수 있습니다. `OnChange`의 5번째 인자로 값이 어디서 들어왔는지 확인합니다.
- `onkeyup`에서 키코드로 Ctrl+V를 감지하는 방식은 빠르게 누르면 이벤트가 잘 발생하지 않을 수 있으므로 `OnChange` 처리가 권장됩니다.
- `OnAfterEdit`에 넣은 로직은 Ctrl+V 붙여넣기 데이터에는 실행되지 않으므로, 붙여넣은 값의 검증이나 ajax 통신 등은 `OnChange`에서 처리합니다.
- `OnChange`가 발생하지 않으면 `InitColumns`에서 상태 컬럼(`Type:"Status"`)이 정의되어 있는지 확인합니다. `RaiseFlag` 분기에서 2(Ctrl+V)를 잘못 다루면 붙여넣기 때 로직이 동작하지 않는 것처럼 보일 수 있습니다.

**키워드**: OnChange, RaiseFlag, OnAfterPaste, OnBeforePaste, Ctrl+V, 붙여넣기 감지, Type:"Status"

### [EVT-0067] 여러 행을 붙여넣으면 OnChange의 계산·값 설정이 첫 행(선택 행)에만 적용됩니다

### [EVT-0068] 붙여넣기로 발생한 OnChange에서 GetCellValue가 변경 전 값을 반환합니다

### [EVT-0070] 엑셀 다운로드 후 OnDownFinish 이벤트가 발생하지 않습니다

**질문**

- 엑셀 다운로드가 끝났을 때 호출되는 콜백 함수나 이벤트가 있나요? 어떤 조건에서 호출되지 않을 수 있나요?
- ibsheet.cfg에서 DownWaitImageVisible을 0으로 설정했더니 다운로드·업로드가 끝나도 OnDownFinish 이벤트가 발생하지 않습니다.
- 제공된 서버모듈을 쓰지 않고 엑셀 다운로드를 직접 구현했더니 OnDownFinish 이벤트가 발생하지 않습니다.
- 엑셀 다운로드 중 서버에서 오류가 나면 alert가 뜨고 OnDownFinish 이벤트가 발생하지 않습니다.

**답변**

`OnDownFinish()`는 쿠키에 `downloadtoken` 값을 세팅하는 방식으로 다운로드 완료를 알아내므로, 쿠키를 허용하지 않는 서버(WAS 설정 등)에서는 발생하지 않습니다. 확인할 사항은 다음과 같습니다.

- `DownWaitImageVisible` 설정: 쿠키를 허용하지 않는 서버에서는 대기 이미지를 닫을 시점이 없어 `DownWaitImageVisible:0`으로 대기 이미지를 띄우지 않게 하는데, 이 경우 다운로드/업로드 후 `OnDownFinish`도 발생하지 않습니다. 이 설정을 적용하기 전에 다운로드 완료 이벤트를 쓰는 로직이 있는지 확인합니다.
- 쿠키 Path: 쿠키에 Path 값을 넣은 것이 원인이었던 사례가 있습니다. `DirectDown2Excel`로 다운로드한 뒤 `Down2Excel`을 호출하면 이벤트가 발생하지 않다가 이 부분을 수정하자 정상 발생했습니다.
- 서버모듈 없이 직접 구현: `Down2Excel` 등 서버모듈 함수를 호출하면 IBSheet가 임의의 토큰 값을 쿠키로 만들고 Interval로 쿠키 값 변경을 확인합니다. 직접 구현했다면 클라이언트 `OnBeforeDownload`에서 폼 Data의 `downloadTokenValue` 값을 읽고 submit한 뒤, 서버에서 엑셀 완료 전에 그 값을 `fileDownloadToken` 쿠키로 응답에 추가합니다.
- 서버 오류: 서버에서 오류가 나면 alert로 오류 메시지만 표시하고 `OnDownFinish`는 발생시키지 않으며, 오류 상황에서 이 이벤트를 처리하는 방법은 확인되지 않았습니다.

**키워드**: OnDownFinish, DownWaitImageVisible, 쿠키, downloadTokenValue, fileDownloadToken, Down2Excel, DirectDown2Excel

### [EVT-0073] 엑셀 업로드(LoadExcel) 후 검증·행 색상 등 후처리는 어디에서 하나요? (OnLoadExcel)

- 엑셀 파일을 업로드한 뒤 데이터의 유효성을 검증하려면 어느 시점에 로직을 넣어야 하나요?
- 엑셀 로드(LoadExcel) 이후에 동작하는 callback 함수나 이벤트는 무엇인가요? 이벤트를 걸었더니 최초 한 번만 실행됩니다.

### [EVT-0076] 엑셀 업로드 시 선택한 파일명·경로를 확인하거나 파일 선택 시점에 처리하려면? (OnLoadFileSelect)

### [EVT-0087] OnVScroll 스크롤 조회가 중복 실행되거나 이벤트가 계속 발생합니다

**질문**

### [EVT-0100] 드래그 앤 드롭으로 행 순서를 바꾸려면? (OnDropEnd와 DataMove, 항상 첫 행으로 이동하는 문제)

**질문**

- 드래그 앤 드롭으로 같은 시트 안에서 행 순서를 바꾸고 싶은데 OnDropEnd에서 행을 복사하고 삭제하면 순서가 자꾸 꼬입니다.
- OnDropEnd에서 DataInsert, SetCellValue, RowDelete로 행을 옮겼더니 위쪽으로 드롭하면 한 행 위의 데이터가 이동합니다.
- DragMode:1로 행 드래그는 되는데 놓으면 항상 첫 번째 행으로만 이동합니다.
- DragMode를 설정하고 DropEnd 이벤트에서 DataMove를 쓰는데 바로 위아래 행으로 옮길 때 잘 안 옮겨집니다.

**답변**

`DragMode:1`은 행을 Drag&Drop할 수 있게만 하는 속성이므로 Drop 후 순서 변경은 `OnDropEnd`에서 직접 처리해야 합니다.

- 같은 시트 안: `DataInsert()`, `SetCellValue`, `RowDelete()`를 조합하는 대신 이 동작이 포함된 `DataMove()`를 사용합니다. 예: `function mySheet1_OnDropEnd (FromSheet, FromRow, ToSheet, ToRow, X, Y, Type) { FromSheet.DataMove(ToRow, FromRow); }`. 마우스가 위치한 행의 아래로 이동시키려면 `toSheet.DataMove(toRow + 1, fromRow);`처럼 사용합니다. 항상 첫 번째 행으로 이동한다면 ToRow와 FromRow의 순서가 뒤바뀌지 않았는지 확인합니다.
- 다른 시트로 이동: 행 추가/삭제도 필요합니다. `GetRowData(FromRow)`로 드래그한 행 데이터를 얻어 `SetRowData(ToRow+1, rowjson, {Add:1})`로 드롭 위치 아래에 추가한 뒤 원본 행을 `RowDelete`로 삭제합니다. 같은 시트 안에서 `FromSheet==ToSheet&&ToRow<FromRow`이면 삭제할 행 번호 `posRow`를 1 증가시킵니다. 같은 시트 안의 이동을 막으려면 `if(FromSheet == ToSheet) return;`을 넣습니다.
- 이벤트의 첫 번째 인자가 `SheetObj`인데 이를 반영하지 않고 구현해 잘못 동작한 사례가 있습니다. 또한 바로 위·아래 행으로 이동할 때는 마우스 포인터가 정확하지 않아 잘 옮겨지지 않으므로 화면 UI에 한 단계 위·아래로 이동하는 버튼을 만들어 처리합니다.

**키워드**: OnDropEnd, DataMove, DragMode, SetRowData, RowDelete, FromRow, ToRow

전체체크가 일부 데이터에 대해서만 동작하는 기능은 없습니다. 굳이 500건에만 동작시키려면 전체체크 클릭 시 호출되는 `OnBeforeCheckAll()`에서 전체체크를 취소하고 `SetCellValue()`로 1~500건만 체크하도록 구현할 수 있습니다. 다만 전체체크는 해제된 채 데이터만 500개 체크되어 정합성이 맞지 않으므로, 데이터를 최대 500건까지만 가져온 상태에서 전체체크를 동작시키는 방식이 적합합니다.

**키워드**: OnBeforeCheckAll, SetCellValue, 전체 체크 일부, 500건

### [EVT-0105] 체크박스 체크를 조건에 따라 막으려면? (OnBeforeCheck, SetAllowCheck)

**질문**

- OnBeforeCheck 이벤트에서 조건에 따라 체크박스 체크를 막으려고 return false를 했는데 체크가 빠지지 않습니다.
- DelCheck 컬럼의 삭제 체크박스를 누르면 확인 문구가 뜨고 확인 시에만 삭제되게 하려면 어떻게 하나요?
- 첫 번째 시트의 체크박스가 체크되어 있으면 두 번째 시트에서는 체크할 수 없게 하려면 어떤 이벤트를 써야 하나요?
- 헤더 체크박스 클릭으로 전체 체크할 때 숨겨진 행은 체크되지 않게 하려면 어떻게 하나요?
- 체크박스와 라디오 값을 조건에 따라 제어하려면 어떤 이벤트를 써야 정확한가요?

**답변**

체크박스나 라디오는 `OnBeforeCheck`, `OnAfterCheck` 이벤트로 제어합니다(`OnSelectCell` 시점에서는 정확한 값 확인이 어렵습니다). `OnBeforeCheck`에서 `return false` 한다고 체크가 취소되지는 않으며, 조건에 따라 체크를 막으려면 `SetAllowCheck(false)`(또는 `SetAllowCheck(0)`)를 호출합니다.

- 삭제 전 확인창: `OnBeforeCheck`에서 파라미터로 row, col 정보를 얻어 col이 삭제 컬럼 인덱스(`SaveNameCol('sDelete')`)와 같을 때 `confirm`으로 확인을 받은 뒤 `SetAllowCheck(1)`을 호출합니다. 자세한 내용은 개발자 가이드의 OnBeforeCheck Event, SaveNameCol Method, AllowCheck Method를 참고합니다.
- 숨겨진 행 제외: `CheckAll` 메소드가 아니라 헤더 체크박스 클릭으로 전체 체크하는 경우, `OnBeforeCheck`에서 `GetRowHidden(Row)`로 숨김 여부를 확인해 숨겨진 행이면 `SetAllowCheck(0)`으로 체크를 막습니다.
- 다른 시트 체크 상태에 따른 제한(헤더 전체체크 포함): `OnBeforeCheckAll`과 `OnBeforeCheck` 두 이벤트에서 체크를 제한하면 될 것으로 보입니다.

**키워드**: OnBeforeCheck, SetAllowCheck, OnAfterCheck, OnBeforeCheckAll, GetRowHidden, SaveNameCol

### [EVT-0106] 헤더 전체 체크 시 행마다 발생하는 OnBeforeCheck 이벤트를 막을 수 있나요?

**질문**

- 헤더 전체 체크로 모든 행이 체크될 때 행마다 OnBeforeCheck 이벤트가 발생해 자식 행 동기화 같은 로직이 행 수만큼 실행됩니다. 이를 막을 수 있나요?

### [EVT-0107] 헤더 전체 체크박스 이벤트는 무엇인가요? OnBeforeCheckAll과 OnCheckAllEnd의 차이

**질문**

- 시트 헤더의 전체 체크박스를 클릭할 때 발생하는 이벤트에는 무엇이 있고, 체크 후 로직(예: 합계 계산)은 어떤 이벤트에서 처리하나요?
- 헤더의 전체 체크박스를 클릭했을 때 실행할 로직은 어느 이벤트를 사용해야 하나요?
- OnBeforeCheckAll 이벤트에는 인자가 없고 OnCheckAllEnd 이벤트에는 인자가 있는데 정상인가요?
- OnBeforecheckAll 이벤트를 사용하는데 동작하지 않습니다. 어느 버전부터 사용할 수 있나요?

**답변**

헤더 전체 체크박스에는 `OnBeforeCheckAll`(전체 체크 처리 이전에 발생)과 `OnCheckAllEnd(Col, Value)`(전체 체크 후 발생) 이벤트가 있으며 헤더를 클릭할 때 각각 한 번만 발생합니다. 개별 체크 이벤트인 `OnBeforeCheck`는 전체체크 시 모든 행에 대해 발생하므로 헤더 전체체크 처리에는 이 두 이벤트를 사용합니다. 조건에 따라 전체체크를 제어하려면 `OnBeforeCheckAll`을, 전체체크 후 선택 행 합계 계산 같은 로직은 `OnCheckAllEnd`에서 시트를 순회하며 처리합니다. `OnBeforeCheckAll` 이벤트에는 인자가 없는 것이 맞으며 자세한 내용은 매뉴얼을 참고합니다. `OnBeforecheckAll` 이벤트는 7.0.1.0 이상에서 사용되며 7.0.0.0-20140220-17-M 버전에서는 동작하지 않으므로 7.0.1.0 이상 버전을 사용해야 합니다.

**적용 버전**: 7.0.1.0 이상(7.0.0.0-20140220-17-M에서는 동작하지 않음)

**키워드**: OnBeforeCheckAll, OnCheckAllEnd, OnBeforeCheck, 헤더 전체 체크박스, 7.0.1.0

### [EVT-0108] 헤더 전체 체크박스를 상황에 따라 비활성화하거나 동작을 막으려면? (OnBeforeCheckAll)

**질문**

- 체크박스 컬럼의 헤더 전체체크를 누르면 모든 행이 체크되면서 행마다 수정 불가 메시지가 나옵니다. 이 동작을 막거나 제어하려면?
- 시트 헤더에 있는 전체 체크 체크박스를 상황에 따라 활성 또는 비활성(disabled) 처리하려면 어떻게 하나요?
- 헤더 전체 체크박스(HeaderCheck)를 상황에 따라 동작하지 않게 하거나 동작하게 하려면 어떻게 하나요?

**답변**

헤더 체크박스는 editable 자체를 설정할 수 없으므로 `OnBeforeCheckAll` 이벤트를 통해 제어합니다. 전체 체크박스가 체크되기 전에 발생하는 `OnBeforeCheckAll`에서 `return false;`(false 반환)하면 전체 체크/해제 동작이 취소되며, 이 이벤트로 전달되는 `Row`, `Col` 인자값으로 분기 처리해 원하는 조건에서만 동작하도록 구현합니다.

**키워드**: OnBeforeCheckAll, HeaderCheck, 전체 체크 비활성화, return false, editable

### [EVT-0109] 헤더 클릭 시 OnClick·OnDblClick 로직이 실행되거나 헤더 값이 0/1로 바뀌면? (헤더 제외)

**질문**

- 데이터 셀의 OnClick 또는 OnDblClick 로직이 헤더(구분선 포함)를 클릭해도 실행됩니다. 헤더에서는 제외하려면?
- 헤더를 눌러 정렬하거나 구분선을 더블클릭할 때 헤더 텍스트나 전체 체크박스 값이 0 또는 1로 바뀝니다.
- SetDataLinkMouse로 링크를 건 컬럼의 헤더를 클릭하면 정렬되지 않고 링크된 페이지로 이동합니다.
- 헤더 셀을 클릭했을 때 팝업을 띄우려면 어떤 이벤트를 써야 하나요?

- 원인 예: `OnClick`에서 `SetCellValue`로 값을 넣는 로직이 헤더 행을 제외하지 않으면 헤더에도 값이 들어가며, 링크 이동을 `OnClick`으로 처리하면 헤더 클릭에서도 링크 이동이 일어나 정렬이 되지 않습니다.
- 설정: ibsheet.cfg 파일에 `HeaderEventMode`를 2로 설정하는 방법도 있습니다.

**키워드**: OnClick, OnDblClick, HeaderRows, rowType, HeaderRow, HeaderEventMode, SetDataLinkMouse

### [EVT-0110] 헤더에서 OnClick이 실행되지 않거나 return false로 헤더 크기 조절이 막힙니다

**질문**

- 헤더에 OnDblClick과 OnClick 이벤트를 모두 사용하려는데 정렬 기능이 있으면 OnClick 이벤트가 실행되지 않습니다.
- OnDblClick 이벤트에서 헤더를 제외하려고 로직을 넣었더니 헤더 경계를 더블클릭해 컬럼 너비를 조절하는 동작이 막힙니다.

- 정렬: 소팅 기능을 사용하는 헤더에서는 `OnClick` 이벤트를 잡을 수 없으므로, 헤더에서 `OnClick`을 사용하려면 소트 기능을 빼야 합니다.
- return false: `OnClick`이나 `OnDblClick`에서 `return false`를 하면 이벤트가 중단되어 헤더 경계 더블클릭 크기 조절 기능도 동작하지 않습니다. ibsheet.cfg에서 `HeaderEventMode`를 2로 설정하면 헤더에서는 MouseDown, MouseMove 이벤트만 발생합니다.
- 헤더·데이터 경계 더블클릭: `OnDblClick`에서 `HeaderRows`를 이용해 처리하며, 데이터 행의 위치를 정확히 확인해야 하면 `GetDataFirstRow`, `GetDataLastRow`를 사용할 수 있습니다.

### [EVT-0111] 합계·소계 행 클릭 시 OnClick 로직을 제외하거나 소계 행 클릭을 잡으려면?

**질문**

### [EVT-0112] OnDblClick 동작 특성과 문제 (OnClick 2회 선행, 스크립트 에러, IE11 미발생)

**키워드**: OnDblClick, OnClick, SetEnable, GetEnable, IE11, 더블클릭

### [EVT-0114] 체크박스와 OnClick: 값이 한 박자 늦게 읽히거나 간헐적으로 미동작하거나 SetCellValue 후 로직이 실행되지 않습니다

### [EVT-0123] OnSelectCell의 isDelete 인자는 언제 true가 되나요? 행 삭제 시 값 갱신·확인 메시지 처리

**질문**

- OnSelectCell 이벤트의 다섯 번째 인자 isDelete가 undefined로 나옵니다. 언제 값이 들어오나요?
- 행을 삭제할 때도 다른 시트나 합계 값을 갱신하려면 어떤 이벤트를 쓰나요?
- 신규 행을 삭제할 때 확인 메시지를 띄우거나 계산 로직을 넣으려면 어떻게 하나요?

**답변**

`OnSelectCell(OldRow, OldCol, NewRow, NewCol, isDelete)`의 `isDelete`는 추가된 행이 삭제되면서 `OnSelectCell`이 발생할 때 true를 반환합니다.

- 이때 `OnSelectCell` 안에서는 삭제된 행의 값을 읽을 수 없으므로, `OnMouseDown`에서 삭제 체크를 하기 전에 해당 행을 기억해 두었다가 값을 읽습니다.
- 행 추가·삭제 시 다른 시트 값을 갱신하려면 `OnChange`, `OnSelectCell`, `OnClick`을 함께 사용합니다. `isDelete`가 true이면 `OnChange`의 계산 로직을 호출하고, 행이 하나도 없는 경우는 `OnClick`에서 `RowCount()`가 0일 때 `OnChange`를 한 번 더 호출합니다.
- 두 시트의 추가·삭제를 함께 동작시키려면 `Type`을 checkBox로 주고 `OnChange()`에서 값을 변경해 삭제하는 방법이 있습니다.
- 신규 행 삭제 시 확인 메시지는 cfg의 `NewRowDeleteMode`로 설정합니다. 신규 행 삭제 시 계산 같은 로직은 별도 이벤트가 없으므로 `OnSelectCell`에서 NewRow와 OldRow를 찾아 처리해야 할 것으로 보입니다.

**키워드**: isDelete, OnSelectCell, NewRowDeleteMode, OnChange, OnMouseDown, 행 삭제 이벤트, 합계 갱신

### [EVT-0124] 신규 행 삭제 후 OnSelectCell이 발생하지 않거나 NewRow와 OldRow가 같아 디테일이 조회되지 않습니다

**질문**

- 신규로 추가한 행을 삭제한 뒤에 OnSelectCell 이벤트가 발생하지 않습니다. 정상 동작인가요?
- rowDelete()로 행을 삭제하면 OnSelectCell이 발생하지 않는 것처럼 보이고 데이터 조회가 되지 않습니다.
- 행을 추가한 뒤 삭제 체크하면 OnSelectCell의 NewRow와 OldRow 값이 같아 디테일이 조회되지 않습니다.

**답변**

신규 행을 삭제한 뒤에는 `OnSelectCell` 이벤트가 발생하지 않는 것이 원래 동작이며, 이후 릴리즈에서 개선될 가능성이 있습니다. 증상에 따라 다음과 같이 처리합니다.

- `OnSelectCell`에서 이전 행과 새 행이 같으면 return하는 로직이 있으면, 행이 삭제되면서 row index가 바뀔 때 return으로 빠져 조회가 되지 않습니다. seq 컬럼을 추가해 변경된 행의 seq 값이 같은 경우에만 return하도록 처리합니다.
- 마스터/디테일 화면에서 삭제 체크 시 NewRow와 OldRow가 같으면, `OnBeforeCheck`에서 행 상태가 `I`(신규 행)이고 컬럼 타입이 `DelCheck`일 때 `OnSelectCell`을 직접 호출하는 우회 방법을 사용할 수 있습니다. 삭제 행이 마지막 행이면 `OnSelectCell(Row,Col,Row-1,Col)`, 아니면 `OnSelectCell(Row,Col,Row+1,Col)`을 호출합니다. 합계 행(AutoSum)이 있으면 마지막 데이터 행은 `LastRow()-1`로 계산합니다.

**키워드**: OnSelectCell, RowDelete, DelCheck, OnBeforeCheck, NewRow, OldRow, 마스터 디테일, 신규 행 삭제

- OnRowDelete 이벤트에서 삭제가 반영된 이후의 행 목록을 조회하고 싶습니다. 방법이 있나요?

**답변**

- `DelCheck()`는 실제 Row를 지우는 것이 아니라 상태값만 바꾸기 때문에 `onRowDelete()` 이벤트가 발생하지 않습니다. 이 경우 `onChange()` 이벤트에서 삭제 상태 변경을 확인합니다.
- `OnRowDelete`는 행이 실제로 삭제되기 전에 호출됩니다. 예를 들어 행이 3개일 때 `LastRow()`를 호출하면 삭제 전의 3개가 반환됩니다. 이 동작은 구조상 바꿀 수 없을 것으로 보이며, 이벤트의 row 인자로 삭제 대상 행을 받아 그 행을 제외하고 계산하도록 로직을 구성합니다.

**키워드**: OnRowDelete, DelCheck, OnChange, LastRow, 행 삭제, 삭제 상태

### [EVT-0126] 삭제 기능을 신규 추가한 행에만 적용하고 조회된 행은 삭제되지 않게 하려면?

**질문**

**답변**

두 가지 방법이 있습니다.

- `OnRowSearchEnd(row)` 이벤트에서 조회로 로드된 행이면 로컬 삭제 버튼 셀을 `SetCellEditable()`로 비활성화합니다.
- `OnBeforeCheck(row, col)` 이벤트에서 `GetRowData(row)`로 해당 행의 status 값을 구해, `I`(신규 추가 행)인 경우에만 `RowDelete(row)`로 삭제합니다.

**키워드**: OnRowSearchEnd, SetCellEditable, OnBeforeCheck, GetRowData, RowDelete, 신규 행 삭제

### [EVT-0127] DataInsert·SetRowData로 추가한 데이터가 OnSelectCell 재조회로 사라지는 이유

**질문**

- DataInsert와 SetRowData로 팝업 선택 데이터를 추가했는데, 다른 시트에 넣은 데이터가 사라지고 아무것도 나타나지 않습니다. 원인이 무엇인가요?

**답변**

버전 문제가 아니라 이벤트 로직 때문입니다. 행을 추가하고 값을 넣는 동작이 `OnSelectCell` 이벤트를 실행시키는데, 이 이벤트 안에 다른 시트를 재조회하는 로직이 있으면 방금 넣은 데이터가 재조회 결과로 바뀌어 사라집니다. 행 추가로 들어온 데이터는 재조회하지 않으려면 `OnSelectCell`에서 `GetCellValue(NewRow, 'sStatus')`가 `I`가 아닐 때만 조회하도록 조건을 넣습니다.

**키워드**: DataInsert, SetRowData, OnSelectCell, GetCellValue, 재조회, sStatus

### [EVT-0129] 마스터 시트 선택 행 값으로 디테일을 조회하려면? (OnClick 대신 OnSelectCell)

**질문**

- Master-Detail 구조에서 Master 시트의 선택 행 컬럼 값을 파라미터로 Detail 시트를 조회하려면 어떻게 해야 하나요?

**답변**

마스터/디테일 구조의 시트에서는 `OnClick` 대신 `OnSelectCell(row,col,oldrow,oldcol)` 이벤트에 디테일 조회 로직을 넣는 것이 좋습니다. `OnSelectCell`은 셀이 선택될 때 발생해 키보드와 마우스 모두에 반응합니다.

- 이 방법은 접근성 모드가 아닐 때의 방법입니다.

**키워드**: OnSelectCell, OnClick, GetCellValue, NewRow, 마스터 디테일, Detail 조회, 키보드 이동

### [EVT-0130] 조회 후 SelectCell로 포커스를 이동했는데 OnSelectCell에서 디테일이 조회되지 않습니다

**질문**

- 마스터 조회 후 SelectCell로 포커스를 강제 이동시켰는데 디테일 시트가 조회되지 않습니다. 원인이 무엇인가요?

**답변**

- `OnSelectCell`에서 `NewRow != OldRow` 조건으로 처리하고 있으면 `SelectCell`로 포커스를 이동해도 디테일 조회가 일어나지 않을 수 있으므로 이 조건을 뺍니다.

### [EVT-0131] 디테일 시트를 수정하는 중에는 마스터 시트가 다른 행으로 이동하지 못하게 하려면?

**질문**

### [EVT-0132] SelectRow로 행을 선택한 뒤 OnClick 이벤트를 강제로 발생시키려면?

**질문**

- 마스터의 OnClick으로 디테일을 조회하는데, SelectRow 함수로 행을 선택한 뒤 OnClick 이벤트를 강제로 발생시키려면 어떻게 하나요?

**답변**

`SelectRow()` 다음에 `mySheet_OnClick(1,3);`처럼 OnClick 이벤트 함수를 직접 호출합니다. `OnSelectCell`은 사용자 클릭, 방향키 이동, `SelectRow` 등의 함수 호출에서도 모두 발생하므로, 방향키 이동으로 발생하는 것을 원하지 않아 `OnClick`에서 구현한 경우에 이 방법을 씁니다.

**키워드**: SelectRow, OnClick, OnSelectCell, 이벤트 강제 호출, 마스터 디테일

### [EVT-0133] 이미 선택된 셀을 다시 클릭하면 OnSelectCell이 발생하지 않는 이유와 대처 방법

**질문**

- 이미 선택된 셀을 한 번 더 클릭하면 OnSelectCell 이벤트가 발생하지 않습니다. 다시 선택하는 경우에도 처리하려면 어떻게 하나요?
- 시트에서 포커스가 빠져나갔다가 원래 포커스된 셀을 다시 클릭하면 OnSelectCell 이벤트가 발생하지 않습니다. 발생시킬 수 있나요?
- 조회 직후 첫 번째 컬럼(체크박스)을 체크했더니 OnSelectCell 이벤트가 발생하지 않습니다.
- OnSelectCell 이벤트는 언제 발생하나요?

**답변**

`OnSelectCell`은 셀이 선택되는 시점에 발생하는 이벤트로, 사용자 클릭과 키보드 방향키 이동, `SelectRow` 같은 함수 호출 때도 발생합니다. 이미 선택된 셀을 다시 선택하거나 계속 클릭해도, 포커스가 빠졌다가 원래 셀을 다시 클릭해도 발생하지 않는 것이 정상 동작이며 이 이벤트 하나로 처리하기는 어렵습니다.

- 클릭할 때마다 실행해야 하는 로직은 `OnClick` 이벤트에 둡니다.
- `OnMouseDown`/`OnMouseUp` 안에서 `MouseRow()`, `MouseCol()` 값이 `GetSelectRow()`, `GetSelectCol()`과 같을 때 `mySheet_OnSelectCell(row,col,row,col)`처럼 OnSelectCell 핸들러를 직접 호출하는 방식으로 처리할 수 있습니다.
- 조회 직후 이미 포커스가 있는 셀의 체크가 문제라면 `SetFocusAfterProcess`로 조회 후 포커스를 두지 않거나 `OnChange` 이벤트에서 처리합니다. 이 경우 `OnSelectCell`보다 `OnChange`에서 처리하는 편이 더 효율적입니다.

**키워드**: OnSelectCell, OnClick, OnMouseDown, OnMouseUp, MouseRow, GetSelectRow, SetFocusAfterProcess, OnChange

### [EVT-0134] OnSelectCell의 oldrow·oldcol 활용과 이벤트 밖에서 이전 선택 행을 알 수 있는지

이벤트 밖에서 oldRow 값을 `GetSelectRow`와 같은 함수로 얻는 기능은 제공되지 않습니다. 이전 행 정보가 필요하면 `OnSelectCell` 이벤트의 `oldrow`, `oldcol` 인자를 이용합니다. 편집 중인 행에서 벗어나는 선택을 경고하거나 되돌리는 처리도 `OnSelectCell`에서 `oldrow`, `oldcol` 값을 이용해 구현할 수 있습니다.

**키워드**: OnSelectCell, oldRow, oldCol, GetSelectRow, 이전 선택 행, 편집 중 행 이동

### [EVT-0136] OnSelectCell에서 선택 행·컬럼 정보로 컬럼별 분기, 체크박스 체크, form 연동을 하려면?

### [EVT-0137] 헤더행을 눌러도 OnClick 로직이 실행됩니다. 헤더행에서 제외하려면?

### [EVT-0139] 드래그로 셀 영역을 선택한 뒤 처리할 이벤트는? (OnSelectEnd, SelectionRowsMode)

**질문**

- 마우스나 키보드로 드래그해 셀 영역을 선택한 뒤 선택이 완료된 시점에 발생하는 이벤트가 있나요?
- 마우스 드래그로 여러 셀을 선택한 뒤 팝업을 띄우려고 합니다. 어느 이벤트를 사용해야 하나요?
- OnSelectEnd 이벤트에서 반환되는 행에 드래그한 행 이외에 별도로 선택한 행까지 포함됩니다. 어떻게 해결하나요?

**답변**

`OnSelectEnd` 이벤트를 사용합니다. 셀 영역 선택이 완료되었을 때 발생하므로 선택 후 처리할 내용(예: 팝업 표시)을 이 이벤트에 구현합니다.

- OnChange 이벤트 안에서 SetCellValue나 CellValue로 값을 넣으면 OnChange가 계속 다시 발생하고 Maximum call stack size exceeded 오류가 납니다. 어떻게 막나요?
- SetCellValue(CellValue)로 값을 바꿀 때 OnChange 이벤트가 발생하지 않게 하려면 어떤 인자를 지정하나요?
- 전체 체크박스를 누르면 브라우저가 멈춥니다. 어떤 원인을 확인해야 하나요?
- OnSearchEnd 등에서 SetCellValue로 헤더 텍스트를 변경할 때 변경에 따른 이벤트가 발생하지 않게 하려면 어떻게 하나요?

**답변**

`OnChange`에서 `CellValue`를 호출하면 또 `OnChange`가 발생해 무한루프(Maximum call stack size exceeded)에 빠지거나, 전체 체크 시 브라우저가 멈출 수 있고, `OnChange` 로직이 다 수행되기 전에 다시 `OnChange`가 발생해 정상 동작하지 않을 수 있습니다. `SetCellValue`/`CellValue`의 이벤트 발생 옵션을 꺼서 막습니다.

- 4번째 인자를 0으로 설정합니다. 예: `Grids[0].SetCellValue(3,8,"1245",0)`
- 또는 `{event:0}`를 줍니다. 예: `SetCellValue(row,col,value,{event:0})`. 헤더 텍스트를 변경하면서 이벤트 발생을 막을 때도 같은 방식입니다.
- 팝업 시트에서 다른 시트에 `CellValue`로 값을 넣었는데 들어가지 않는 경우는 `onchange` 이벤트가 두 번 실행되어 발생하는 현상이므로, 값을 set할 때 `onchange`가 발생하지 않도록 설정합니다.
- 붙여넣기 이후 `OnChange` 안에서 호출하는 `SetCellValue`도 `OnChange`를 다시 발생시키지 않도록 설정해야 합니다.
- ActiveX에서는 `CellValue2`가 같은 용도였고, IBSheet7에서는 `CellValue`의 인자로 설정합니다.

**키워드**: SetCellValue, CellValue, OnChange, event:0, 무한루프, Maximum call stack size exceeded, CellValue2

### [EVT-0186] 값을 변경한 뒤 조건에 맞지 않으면 이전 값으로 되돌리려면? (OnChange의 OldValue, event:0)

**질문**

- 셀 값을 변경했을 때 조건에 맞지 않으면 이전 값으로 되돌리려면 어떻게 하나요?
- 콤보박스에서 값을 변경할 때 이전 선택값을 가져와서 되돌릴 수 있나요?
- 콤보 목록에서 항목을 선택하면 파일 다운로드 같은 동작을 하고, 콤보가 닫힐 때는 최초 조회 항목으로 다시 표시하려면 어떻게 하나요?

**답변**

`OnChange`는 값 변경이 이미 완료된 이후에 발생하므로, 조건에 따라 되돌리려면 `OldValue`(또는 `oldValue()`)로 이전 값을 받아 `SetCellValue`로 다시 넣는 수밖에 없습니다. `SetCellValue(Row, Col, OldValue, {event:0})`처럼 `{event:0}`를 주면 값을 원복하면서 `OnChange`가 다시 발생하지 않습니다.
콤보는 값이 변경되면 `onChange()`가 발생하고 별도 설정 없이 원래 값으로 되돌리면 `onChange`가 또 발생합니다. 항목 선택 시 발생하는 `OnChange()`에서 원하는 동작(파일 받기 등)을 구현한 뒤 마지막에 `setCellValue(row,col,oldvalue,{event:0})`으로 이전 값으로 되돌립니다.

**키워드**: OnChange, OldValue, SetCellValue, event:0, 콤보, 값 원복

- `OnSearchEnd`에서 조회조건을 세팅하는 함수를 호출하는 구조에서 기본 인자 하나가 넘어오지 않아 `DoSearch()`가 무한 반복되면서 무한 루프가 발생한 사례가 있으므로 인자가 빠지지 않는지 확인합니다.
- `OnSearchEnd` 안에서 `DoSearch()`를 다시 호출하면 두 번의 조회가 비동기 형태로 이루어지고 그 과정에서 `SetEditable(1)`이 두 번 호출되어 오류가 발생합니다. 꼭 두 번 호출해야 한다면 setTimeout을 걸거나 동기 형태로 조회합니다.
- `Reset()`이나 `RemoveAll()` 이후 시트 초기화와 재조회를 바로 이어서 호출하면 디버그 모드에서 문제가 생기거나 오류가 날 수 있으므로, 재초기화와 재조회를 `setTimeout`으로 처리합니다.
