## 머지 종류·기본 설정

### [MRG-0001] 데이터 행(데이터 영역)을 가로로 머지하려면 DataRowMerge와 RowMerge를 어떻게 설정하나요?

**질문**

- 세로 머지뿐 아니라 데이터 영역의 가로 머지도 하고 싶습니다. 일부 컬럼만 가로로 머지하려면 어떻게 설정하나요?
- IBSheet7에서 세로 병합은 되는데, 헤더가 아닌 데이터 행에서 첫 번째와 두 번째 컬럼처럼 인접한 컬럼을 가로로 병합하려면 어떻게 설정하나요?
- 시트의 데이터 영역을 가로 방향으로 머지(병합)하고 싶은데 적용되지 않습니다. 어떤 옵션이나 함수를 설정해야 하나요?
- 시트의 데이터 행에 머지를 전체 적용 방식으로 적용하고 싶습니다. 어떤 메소드를 어떤 값으로 호출하면 되나요?

**답변**

데이터 영역의 가로 머지는 기본값 0(허용하지 않음)이므로 허용 설정이 필요합니다.

- 시트 초기화 시 Cfg(`SetConfig`)에 `DataRowMerge:1`을 설정하거나, 동적으로 설정할 때는 `SetDataRowMerge(1)` 메소드를 호출합니다(전체 적용 방식).
- `SetConfig`에 `MergeSheet`(머지 종류)와 `DataRowMerge:1`을 함께 설정하면 데이터 영역이 가로로 머지됩니다.
- 컬럼을 초기화할 때 가로로 머지할 컬럼에는 `RowMerge:1`, 가로 머지를 허용하지 않을 컬럼에는 `RowMerge:0` 속성을 설정합니다. 특정 컬럼 2개만 가로 머지하려면 나머지 컬럼에 `RowMerge:0`을 줍니다.

**키워드**: DataRowMerge, SetDataRowMerge, RowMerge, MergeSheet, 가로 머지, SetConfig

### [MRG-0003] 머지된 상단 행을 SetFrozenRows로 고정할 때 머지가 깨지거나 재조회 후 고정이 풀리는 경우

**질문**

- 머지된 상단 행을 SetFrozenRows로 고정하면 머지가 깨지거나 조회 후 SetFrozenRows가 동작하지 않습니다. 어떻게 설정해야 하나요?
- 조회 후 머지 유형을 msPrevColumnMerge로 바꾸고 SetDataMerge()로 머지했더니 재조회하면 상단 고정행이 고정되지 않습니다.

**답변**

초기화 시 `MergeSheet`가 `msNone`이나 `msHeaderOnly`가 아니면 `SetFrozenRows` 자체가 되지 않습니다. `SetConfig`에 `MergeSheet:msHeaderOnly`를 설정하고 `OnSearchEnd`에서 `SetFrozenRows(4)`, `SetMergeSheet(7)`, `SetDataMerge()`, `SetMergeCell(2, 1, 3, 1)` 순으로 호출합니다. 조회 후 머지 유형을 `msPrevColumnMerge`로 바꾸고 `SetDataMerge()`로 머지한 뒤 다시 조회하면 상단 고정행이 고정되지 않으므로, `SetDataMerge()`를 호출한 이후에 머지 유형을 원래의 헤더 전용 머지 유형으로 다시 바꿔 줍니다. 제품 버전이 너무 낮으면 업그레이드를 권장합니다.

**키워드**: SetFrozenRows, MergeSheet, msHeaderOnly, SetMergeSheet, SetDataMerge, msPrevColumnMerge, 상단 고정행

### [MRG-0004] 셀 병합(머지)을 사용하려면 MergeSheet와 ColMerge를 어떻게 설정하고, 설정해도 머지되지 않으면 무엇을 확인하나요?

**질문**

- 시트에서 셀 머지를 사용하려면 어떤 함수와 속성을 설정해야 하나요? 헤더 머지와 데이터 영역 머지는 어떻게 다른가요?
- 컬럼에 ColMerge:1을 주었는데도 데이터가 병합되지 않고 헤더 병합 방법도 궁금합니다.
- ColMerge나 SetDataRowMerge, SetRowMerge로 머지를 적용했는데 머지가 되지 않습니다. 무엇을 확인해야 하나요?
- 헤더를 두 줄로 만들었는데 MergeSheet를 1로 설정했는데도 상하좌우 머지가 되지 않습니다.

**답변**

SetConfig에서 `MergeSheet`로 머지의 종류를 결정하고, InitColumns에서 컬럼별 `ColMerge`를 설정합니다. 헤더 영역은 `MergeSheet` 속성을 따르고, 데이터 영역은 `MergeSheet` 속성과 컬럼별 `ColMerge` 속성을 함께 따릅니다. `MergeSheet` 설정값은 도움말을 참고합니다.

- `ColMerge` 기본값이 1이므로 머지하지 않을 컬럼은 0으로 설정해야 합니다.
- `msHeaderOnly`는 헤더만 병합하겠다는 의미이므로 데이터 병합에는 도움말의 `MergeSheet` 항목에서 맞는 종류를 설정합니다.
- cfg에 `MergeSheet` 설정이 빠져 있으면 `ColMerge`, `SetDataRowMerge`, `SetRowMerge` 등으로 머지를 지정해도 적용되지 않습니다.
- `MergeSheet`를 1로 설정했는데도 실제로는 0으로 적용되던 사례가 있으므로 실제 적용된 값을 확인하고 `ColMerge:1`을 설정합니다.

**키워드**: MergeSheet, ColMerge, SetConfig, InitColumns, msHeaderOnly, 머지 설정

### [MRG-0005] MergeSheet(SetMergeSheet)에 지정할 수 있는 값과 머지 종류, 병합 해제(msNone)

**질문**

- MergeSheet(SetMergeSheet)에 지정할 수 있는 머지 종류와 값은 무엇인가요? 동적으로 데이터를 추가한 뒤에도 데이터 영역 머지가 가능한가요?
- 앞컬럼 머지, 전체 머지, 기준컬럼 머지는 각각 어떻게 다른가요?
- 시트의 헤더와 데이터 영역에서 병합이 적용되지 않게 하려면 어떻게 설정하나요?
- MergeSheet에 msBaseColumnMerge와 msHeaderOnly를 조합해 설정했는데 오류가 발생합니다.

**답변**

`SetMergeSheet(Enum)`으로 머지 형태를 정할 수 있고 동적으로 데이터를 추가한 뒤에도 가능합니다. 값은 다음과 같습니다.

- 0 `msNone`: 사용 안 함(병합을 해제하려면 `SetConfig`의 `MergeSheet`를 `msNone`으로 설정)
- 1 `msAll`: 전체 영역 자동 셀 병합(같은 데이터면 모두 머지)
- 2 `msPrevColumnMerge`: 이전 컬럼의 셀 병합 영역 내 병합(앞컬럼 머지)
- 3 `msFixedMerge`: 단위 데이터행 구조에서 고정 셀 병합
- 4 `msBaseColumnMerge`: 기준 컬럼의 셀 병합 영역 내 병합(첫 번째 컬럼만 바라보면서 머지)
- 5 `msHeaderOnly`: 헤더 영역 자동 병합
- 7 `msHeaderOnly + msPrevColumnMerge`, 8 `msHeaderOnly + msFixedMerge`, 9 `msHeaderOnly + msBaseColumnMerge`
상수 철자가 틀려 오류가 나는 경우가 있으므로 `msHaderOnly`처럼 e를 빠뜨리지 말고 `msBaseColumnMerge+msHeaderOnly`로 정확히 씁니다.

**키워드**: MergeSheet, SetMergeSheet, msNone, msAll, msPrevColumnMerge, msBaseColumnMerge

### [MRG-0006] MergeSheet, ColMerge, DataRowMerge, SetMergeCell 머지 옵션의 관계와 우선순위

**질문**

- MergeSheet, ColMerge, DataRowMerge, SetMergeCell 같은 머지 관련 옵션은 서로 어떤 관계이고 어떤 우선순위로 적용되나요?

**답변**

가장 우선권을 갖는 것은 `MergeSheet`입니다. `msNone`이면 `ColMerge`와 `DataRowMerge`는 소용이 없고, `msAll`, `msPrevColumnMerge`, `7`(앞컬럼머지, 헤더는 무조건 머지)일 때만 의미를 갖습니다. `ColMerge`(InitColumns 인자)는 위아래로 같은 값이 있을 때, `DataRowMerge`는 좌우로 같은 값이 있을 때 머지 허용 여부를 정합니다. 컬럼별 `ColMerge` 기본값은 1이며 `ColMerge:0`인 컬럼은 머지에서 제외됩니다. 강제 머지는 `SetMergeCell`을 씁니다.

**키워드**: MergeSheet, ColMerge, DataRowMerge, SetMergeCell, 머지 우선순위

### [MRG-0007] ColMerge를 true로 했는데 데이터 영역이 머지되지 않거나, 반대로 데이터 행 머지를 막으려면 MergeSheet를 어떻게 하나요?

**질문**

- 컬럼의 ColMerge 속성을 true로 설정했는데도 데이터 영역의 머지가 되지 않습니다. 원인이 무엇인가요?
- 헤더만 머지되고 데이터 영역은 머지가 되지 않습니다. 데이터 영역도 머지하려면 어떻게 설정해야 하나요?
- MergeSheet를 msFixedMerge로 사용 중인데 데이터 행에서 컬럼이 모두 머지됩니다. 데이터 행은 머지되지 않게 하려면 어떻게 하나요?

**답변**

머지는 cfg의 `MergeSheet` 속성과 컬럼별 `ColMerge` 속성에 따라 결정됩니다.

- `MergeSheet:msHeaderOnly`만 쓰면 컬럼별 `ColMerge`가 1이어도 데이터 영역 머지는 이루어지지 않습니다. 데이터 영역도 머지하려면 `msPrevColumnMerge`를 추가해 헤더 머지와 앞컬럼 머지를 같이 사용하도록 설정합니다. 많이 쓰는 값은 7로, 데이터 영역도 앞컬럼 머지 규칙을 따릅니다. 머지 규칙을 따르지 않을 컬럼에는 `ColMerge:0`을 설정합니다.
- 반대로 `msFixedMerge` 사용 중 데이터 행 머지를 막으려면 `MergeSheet`를 `msHeaderOnly`로 설정합니다. `ColMerge`를 0으로 바꾸지 않아도 데이터 행에서는 머지가 되지 않습니다.

**키워드**: MergeSheet, msHeaderOnly, msPrevColumnMerge, msFixedMerge, ColMerge, 데이터 영역 머지

### [MRG-0008] 앞컬럼 머지(msPrevColumnMerge)와 rowspan 형태 병합을 위한 MergeSheet 값과 조회 데이터 구성

**질문**

- 앞컬럼 머지를 적용하려는데 전체 머지가 되고 있습니다. 앞컬럼 머지를 사용하려면 mergeSheet를 어떻게 설정해야 하나요?
- 시트에서 어떤 컬럼에 연관된 다른 컬럼들은 모두 머지해야 합니다. 어떤 머지 설정을 사용해야 하나요?
- 조회 결과에서 같은 값을 가진 여러 행의 일부 컬럼을 하나의 셀처럼 rowspan으로 병합해 표시하려면 어떻게 하나요? 첫 행에만 값이 있어도 되나요?

**답변**

앞컬럼 머지를 사용하려면 `MergeSheet`(mergeSheet)를 `msPrevColumnMerge`(2) 또는 헤더 머지까지 포함한 7로 설정합니다. 어떤 컬럼에 연관된 컬럼들을 모두 머지하려면 `mergesheet`를 7번으로 사용합니다. 예: `initSheet.Cfg = {... MergeSheet: msPrevColumnMerge}`.
같은 데이터를 머지해 하나의 셀처럼 표시하려면 첫 행에만 값을 내려주면 안 되고, 병합할 컬럼의 모든 행에 같은 값이 들어 있도록 조회 데이터(쿼리)를 구성해야 합니다.

**키워드**: MergeSheet, msPrevColumnMerge, 앞컬럼 머지, rowspan, 조회 데이터

### [MRG-0009] 행을 추가한 데이터가 머지되지 않거나 추가한 마지막 행이 이전 머지에 포함되는 경우

**질문**

- 행을 추가한 데이터의 머지가 잘 되지 않습니다. MergeSheet가 msHeaderOnly로 되어 있는 경우 어떻게 해야 하나요?
- 앞컬럼 머지로 머지된 데이터 끝에 행을 추가해 같은 값을 입력하고 저장한 뒤 다시 조회하면 추가한 행까지 머지됩니다. 추가한 행은 머지에서 제외하려면 어떻게 하나요?

**답변**

`MergeSheet`가 `msHeaderOnly`로 되어 있으면 `msPrevColumnMerge + msHeaderOnly`로 바꿔야 합니다. 행 추가로 넣은 데이터는 머지되지 않고 추가하는 행이 많아질수록 속도가 저하되므로, `LoadSearchData` 함수로 데이터 구조를 만들어 로드하면 자동으로 머지될 것으로 보입니다.
저장 후 재조회 시 추가한 행이 이전 머지에 포함되는 것을 막으려면 `MergeSheet`를 `msPrevColumnMerge + msHeaderOnly`로 설정하고, 행 추가 여부를 나타내는 플래그 컬럼을 머지되는 데이터 컬럼 앞에 위치시키면 될 것으로 보입니다.

**키워드**: MergeSheet, msPrevColumnMerge, msHeaderOnly, LoadSearchData, 행 추가, 플래그 컬럼

### [MRG-0010] LoadExcel로 엑셀을 불러온 뒤 같은 값 셀을 병합하려면 어떻게 하나요?

**키워드**: LoadExcel, MergeSheet, SetMergeSheet, SetConfig, 엑셀 로드 머지

### [MRG-0011] 조건에 따라 컬럼을 동적으로 만드는 시트(Reset 후 재생성)에서 머지 Cfg를 어떻게 설정하나요?

**질문**

- 조건에 따라 컬럼을 동적으로 만드는 시트(Reset 후 다시 생성)에서 헤더행 머지와 데이터행의 세로·가로 병합 기능을 쓰고 싶습니다. 어떤 설정이 필요한가요?

**답변**

시트 병합은 Cfg의 `MergeSheet` 속성값과 컬럼별 `ColMerge` 속성에 따라 동작합니다. 따라서 `Reset()` 이후 시트를 다시 만들 때 Cfg를 재설정하면서 헤더행 머지, 데이터행 세로 머지, 데이터행 가로 머지 여부를 함께 지정해야 합니다. 예를 들어 `sheetdata.Cfg = {FrozenCol:2,SearchMode:2,Page:20, MergeSheet:7, DataRowMerge:1}`은 앞 컬럼 머지와 헤더행 머지를 쓰고 데이터행 가로 머지를 허용합니다. 머지 속성은 `setConfig` API 문서를 참고합니다.

**키워드**: Reset, MergeSheet, ColMerge, DataRowMerge, setConfig, 동적 컬럼

### [MRG-0016] 일부 컬럼만 머지하거나 특정 컬럼(Seq 등)을 머지에서 제외하려면 ColMerge:0을 어떻게 쓰나요?

**질문**

- 데이터 영역에서 일부 컬럼만 머지하고 싶은데 모든 컬럼이 머지됩니다. 특정 컬럼을 머지에서 제외하려면 어떻게 하나요?
- 그리드에서 특정 컬럼만 셀 병합을 적용하고 나머지 컬럼은 병합되지 않게 하려면 어떤 속성을 사용해야 하나요?
- ColMerge를 설정했는데 머지가 되지 않고 다 풀립니다. 처음과 끝 컬럼만 머지하거나 한 컬럼만 머지하려면 어떻게 설정하나요?
- 번호(Seq) 컬럼은 머지하지 않고 두 번째 컬럼이 머지되면 그 기준으로 다음 컬럼들도 머지되게 하려면 어떻게 설정하나요?

**답변**

컬럼의 `ColMerge` 속성 값에 따라 머지 규칙을 따를지 결정되며 기본값이 1(true)이라, 별도 설정이 없으면 전체 컬럼이 머지됩니다.

- 머지에서 제외할 컬럼마다 초기화 구문에서 `ColMerge:0`(또는 `false`)을 지정하면 시트의 머지 종류와 상관없이 그 컬럼은 머지되지 않습니다. 앞컬럼 머지, 헤더 머지, `msFixedMerge + msHeaderOnly` 방식에서도 같으며, 필요하면 `RowMerge:0`도 함께 넣습니다.
- `ColMerge`만으로는 머지되지 않으며 SetConfig의 `MergeSheet`에 머지 규칙을 설정해야 합니다.
- 헤더가 아닌 데이터 영역에서만 일부 컬럼을 머지하려면 `MergeSheet`를 2, 3, 4 중 하나로 설정하고 대상이 아닌 컬럼은 `ColMerge:0`으로 설정합니다.
- 한 컬럼의 같은 값만 세로로 병합하려면 나머지 컬럼의 `ColMerge`를 0으로 하고 `MergeSheet`를 1번(`msAll`) 또는 7번으로 지정합니다. 병합을 쓸 컬럼이 하나뿐이고 헤더도 병합하려면 `MergeSheet`를 `msHeaderOnly + msBaseColumnMerge`로 설정할 수도 있습니다.
- 처음과 끝 컬럼만 머지하려면 중간 컬럼에 `ColMerge:0`, 처음·끝 컬럼에 `ColMerge:1`을 주고 `MergeSheet`를 앞컬럼 머지로 설정합니다.
- Seq 컬럼처럼 머지되면 안 되는 컬럼은 `ColMerge:0`으로 해제하고 규칙은 `msPrevColumnMerge + msHeaderOnly`(숫자 7)로 설정합니다.

**키워드**: ColMerge, ColMerge:0, MergeSheet, msPrevColumnMerge, msBaseColumnMerge, 특정 컬럼 머지 제외

### [MRG-0017] 체크박스·상태·삭제·금액 컬럼처럼 특정 컬럼이 머지되지 않게 하려면 ColMerge:0을 어떻게 쓰나요?

**질문**

- 머지를 사용하는데 상태 컬럼, 삭제 컬럼, 체크박스 컬럼처럼 특정 컬럼은 머지되지 않게 하고 싶습니다. 어떻게 설정하나요?
- SetMergeSheet(msAll)로 머지를 사용하면 체크박스 컬럼이 같은 값끼리 합쳐져 보입니다. 행마다 체크박스가 각각 표시되게 하려면 어떻게 하나요?
- 컬럼 머지를 사용하면 상태 컬럼과 삭제 컬럼까지 빈 값으로 머지된 상태로 로딩됩니다.
- 예전 버전에서는 머지되지 않았는데 버전을 업그레이드한 뒤 체크박스 컬럼이 통으로 머지됩니다.

**답변**

컬럼 생성 시 `ColMerge`의 기본값이 1이라 같은 값이면 머지됩니다. 체크박스는 체크/언체크 값(1, 0)이 같으면 합쳐지며, `MergeSheet`는 `ColMerge:1`인 가장 왼쪽 컬럼(상태 컬럼)을 기준 컬럼으로 삼으므로 상태·삭제 컬럼이 빈 값으로 머지된 채 로딩될 수 있습니다.

- 머지에서 제외할 컬럼(체크박스, 상태, 삭제, 금액 등)을 InitColumns로 초기화할 때 `ColMerge:0`(또는 `ColMerge=0`)으로 설정합니다. 병합할 컬럼에는 `ColMerge:1`을 설정합니다.
- 구버전(7.0.7.1)에서 7.0.13.190으로 교체한 뒤 상태·삭제 컬럼에서 머지가 발생하는 것도 `MergeSheet` 설정에 따른 동작이므로 `ColMerge:0`으로 제외합니다.
- 업그레이드 후 체크박스 컬럼이 통으로 머지되는 경우, 별도로 `SetMergeSheet`를 호출하고 있던 것이 원인일 수 있으므로 해당 호출을 제거합니다.

**적용 버전**: 7.0.7.1에서 7.0.13.190으로 교체 시 동작 변경

**키워드**: ColMerge:0, MergeSheet, SetMergeSheet, InitColumns, 체크박스 컬럼 머지, 상태 컬럼

### [MRG-0018] ColMerge를 중복 선언하거나 문자열("false")로 선언하면 머지가 되지 않는 이유

**질문**

- 컬럼 정의에 ColMerge:1과 ColMerge:0을 함께 넣었더니 병합이 되지 않습니다. 같은 속성을 중복해서 쓰면 어떻게 적용되나요?
- 컬럼 머지 속성을 ColMerge:"false"처럼 문자열 값으로 선언해도 되나요? 머지 속성에는 어떤 타입의 값을 써야 하나요?

**답변**

컬럼 정의에는 `ColMerge`를 하나만 설정해야 합니다. 같은 컬럼에 값을 중복해서 쓰면 제일 마지막 값이 설정된 것으로 보입니다.
`ColMerge`는 어느 시점부터 Number 타입으로 바뀌어 `ColMerge:0` 또는 `ColMerge:false`는 되지만 문자열 선언(`ColMerge:"false"`)은 동작하지 않습니다. 이 부분을 초기화 함수(`IBS_initSheet`)에서 고쳐야 합니다.

**키워드**: ColMerge, ColMerge:0, ColMerge:false, IBS_initSheet, 중복 선언

### [MRG-0019] 값이 없는(빈·공백) 셀이 함께 머지될 때 머지하지 않게 하려면 UseEmptyMerge를 어떻게 설정하나요?

**질문**

- IBSheet7에서는 값이 없는 셀도 머지가 됩니다. ActiveX처럼 데이터가 없는(빈) 셀은 머지하지 않게 하려면 어떻게 설정하나요?
- 헤더에 빈 값을 설정하면 ActiveX에서는 머지되지 않았는데 IBSheet7에서는 머지됩니다.
- 컬럼 값이 공백일 때 머지하지 않게 하거나, 반대로 공백이 머지되지 않는 이유를 알고 싶습니다.

**답변**

ActiveX에서는 값이 없으면 머지를 하지 않았지만 IBSheet7은 컬럼의 Merge 속성이 true(기본값)이면 빈 값 셀도 머지합니다. `UseEmptyMerge`(기본값 1)를 0으로 설정하면 빈 값(공백) 셀이 머지되지 않습니다.

- `ibsheet.cfg`에 `UseEmptyMerge:0`을 설정합니다. 시트 개별로 적용하려면 InitColumns 하기 전에 `sheet.UseEmptyMerge=0`을 적용합니다.
- 이 설정은 데이터 행에 적용되며 헤더에는 동작하지 않습니다. 헤더는 중간 컬럼에 스페이스를 하나 넣어야 합니다.
- 반대로 빈 값 셀이 머지되지 않는다면 cfg에 이 속성이 0(false)으로 설정되어 있는지 확인합니다.
- 이 속성은 가이드 문서에는 빠져 있습니다. 7.0.13.62 버전에서 신규 추가된 기능이므로 50 버전 등 그보다 낮은 버전에서는 사용할 수 없고 제품을 업그레이드해야 합니다.

**적용 버전**: 7.0.13.62 이상

**키워드**: UseEmptyMerge, ibsheet.cfg, 빈 값 머지, 공백 머지, 빈 셀 병합 방지

### [MRG-0020] UseEmptyMerge를 SetConfig에 적용했는데 효과가 없을 때 설정해야 하는 위치

**질문**

- UseEmptyMerge 속성을 SetConfig에 적용했는데도 효과가 없고 잘 동작하지 않습니다. 이 속성은 어디에 설정해야 하나요?
- 가로·세로 머지를 구현했더니 데이터가 없는 셀까지 병합되어 버립니다. 개별 셀로 두려면 어떻게 하나요?
- null 값인 셀이 병합되지 않게 하려고 UserEmptyMerge:1 속성을 적용했는데도 병합이 해제되지 않습니다.

**답변**

빈 값 머지 제어 속성은 전역 속성이므로 시트의 SetConfig에 적용하면 잘 동작하지 않고, cfg 파일에 설정해야 합니다.

- `ibsheet_config.js` 파일을 호출하도록 구성하고 그 파일에 해당 속성을 0으로 추가해 해결한 사례가 있습니다.
- 일부 안내에는 속성명이 `UserEmptyMerge`로 적혀 있습니다.
- 7.0.9.1 버전 사용 시에는 최신 버전 제품 파일로 교체해야 할 수 있으며, 최신 버전은 라이선스 적용 방식이 바뀌었습니다.

**적용 버전**: 7.0.9.1 사용 시 최신 버전으로 교체 필요할 수 있음

**키워드**: UseEmptyMerge, UserEmptyMerge, ibsheet.cfg, ibsheet_config.js, SetConfig, 전역 속성

### [MRG-0021] 버전 교체 후 빈 값 머지가 다르게 동작하거나 UseEmptyMerge 설정 후에도 가로 머지가 계속되는 경우

**질문**

**적용 버전**: 89 버전과 103 버전 사이에 변경, 7.0.13.124-20180810-14에서 수정

### [MRG-0022] SetDataRowMerge(1) 가로 머지 후 머지된 컬럼 끝의 우측 border가 사라지는 현상

**질문**

- SetDataRowMerge(1)로 가로 머지를 설정하고 일부 컬럼은 rowMerge를 0으로 설정했더니, 머지된 컬럼이 끝나는 부분의 우측 border가 사라집니다. 어떻게 해결하나요?

**답변**

머지하는 컬럼 사이에 히든 컬럼이 끼어 있어서 생기는 현상으로 보입니다. 머지 대상 컬럼 중 첫 번째 컬럼을 제일 뒤로 이동하면 해결됩니다.

**키워드**: SetDataRowMerge, rowMerge, border, 히든 컬럼, 가로 머지

### [MRG-0023] 데이터 행을 가로로 머지하려면 어떻게 설정하고 일부 컬럼·일부 행만 가로 머지하려면?

**질문**

- 머지를 가로로 하고 싶은데 세로로만 머지됩니다. 가로 머지에서 일부 컬럼은 머지되지 않게 하려면 어떻게 하나요?
- 그리드에서 특정 조건의 행만 가로로 머지하고 싶습니다. 일부 행과 일부 컬럼만 가로 머지를 허용하려면 어떻게 설정하나요?
- MergeSheet와 DataRowMerge를 설정해 데이터 행 가로 머지를 쓰는데 가로로 같은 값이 병합되지 않습니다.

**답변**

가로 머지는 `DataRowMerge`와 InitColumns의 `RowMerge` 속성을 확인해 설정합니다.

- Cfg에 `DataRowMerge:1`로 가로 머지를 허용하고 컬럼별 `RowMerge` 속성으로 가로 머지 여부를 정합니다. 가로 머지에서 일부 컬럼을 제외하려면 해당 컬럼의 InitColumns에 `RowMerge:0`을 설정합니다.
- 특정 조건의 데이터만 가로 머지하려면 조회 데이터 안에 `RowMerge:1`을 넣어 해당 데이터의 가로 머지를 설정합니다. 중간 몇 개 행만 가로 병합하는 경우도 조회 데이터에 병합 설정을 넣어 조회하는 방법밖에 없을 것으로 예상된다고 안내되었습니다.
- 시트 초기화 시 컬럼에 `Type`이 지정되어 있지 않으면 가로 머지가 되지 않으므로, 가로 머지를 사용할 컬럼에는 `Type`(예: `Text`)을 지정합니다.

**키워드**: DataRowMerge, RowMerge, InitColumns, Type, 가로 머지, MergeSheet

### [MRG-0024] 앞컬럼 머지나 ColMerge만 썼는데 같은 행의 컬럼이 가로로도 머지되는 현상

**질문**

- 앞컬럼 머지를 사용 중인데 서로 다른 컬럼의 값이 같다는 이유로 가로(열 방향)로도 머지되어 표시됩니다. 머지되지 않게 할 수 있나요?

**키워드**: DataRowMerge, ColMerge, 앞컬럼 머지, 가로 머지 방지, RowSpan

### [MRG-0027] RowMerge(가로 머지)가 동작하지 않을 때 Cfg의 MergeSheet·DataRowMerge와 컬럼별 RowMerge 설정

**키워드**: RowMerge, DataRowMerge, MergeSheet, InitColumns, UseEmptyMerge, 가로 머지

## 앞컬럼 머지 규칙

### [MRG-0029] 단위 데이터행 구조에서 앞컬럼 머지가 안 될 때 msFixedMerge와 msPrevColumnMerge 중 무엇을 쓰나요?

**질문**

- 단위 데이터행 구조에서 앞컬럼 머지가 동작하지 않습니다. 어떤 머지 방식을 사용해야 하나요?
- 머지할 때 앞컬럼을 기준으로 머지되게 하고 싶습니다. msFixedMerge로 설정했더니 소계가 앞컬럼과 상관없이 나옵니다.

**답변**

단위 데이터행을 사용할 때는 `msFixedMerge`를 사용해야 하며, `msPrevColumnMerge`가 아니므로 앞컬럼 머지는 사용할 수 없습니다.
반대로 앞컬럼을 기준으로 머지하고 싶다면 `MergeSheet`를 `msPrevColumnMerge`로 설정합니다. `msFixedMerge`로 설정한 경우에는 소계가 앞컬럼과 상관없이 나오지만, `msPrevColumnMerge`를 설정하면 머지된 앞컬럼을 기준으로 머지되어 출력됩니다.

**키워드**: msFixedMerge, msPrevColumnMerge, MergeSheet, 단위 데이터행, 소계

### [MRG-0030] InitColumns에서 머지 속성을 Merge로 지정하면 머지되지 않는 이유(ColMerge)

**질문**

- 머지 화면을 구성했는데 의도한 대로 머지되지 않습니다. InitColumns에서 머지 속성을 어떻게 지정해야 하나요?

**답변**

InitColumns에서 머지 여부를 지정하는 컬럼 속성은 `ColMerge`입니다. `Merge`라고 속성명을 잘못 지정하면 머지가 의도대로 되지 않습니다. 기본적으로 `msPrevColumnMerge` 속성과 InitColumns의 `ColMerge`를 함께 사용합니다.

**키워드**: ColMerge, InitColumns, msPrevColumnMerge, 머지 속성명

### [MRG-0031] 앞컬럼 머지(msPrevColumnMerge)에서 중간 컬럼의 머지가 풀리면 뒤쪽 컬럼이 머지되지 않는 이유와 해결

**질문**

- msPrevColumnMerge + msHeaderOnly를 쓰는데 중간에 다른 컬럼을 두어야 해서 뒤쪽 컬럼의 머지가 풀립니다. 그 뒤에서 다시 머지하려면 어떻게 하나요?
- MergeSheet를 msPrevColumnMerge + msHeaderOnly로 설정한 뒤 필터를 적용하면 필터 결과가 머지되지 않습니다.
- combo 컬럼이 머지되지 않습니다. 앞컬럼 기준 머지는 어떤 조건에서 머지되나요?
- 여러 컬럼을 머지할 때 한 컬럼은 머지하지 않고, 나머지 컬럼은 앞 컬럼의 머지에 맞춰 따로 머지하려면 어떻게 하나요?

**답변**

앞컬럼 머지는 머지 대상 컬럼의 왼쪽 컬럼의 머지 속성을 따릅니다. 앞컬럼의 머지된 데이터 안에서 해당 컬럼의 데이터가 동일한 경우에만 머지되므로, 앞 컬럼의 머지가 풀리면 그 이후 `ColMerge:1` 컬럼도 머지되지 않는 것이 정상입니다. 예를 들어 A|B 컬럼이 1|C, 1|D, 2|C, 2|D인 상태에서 B 컬럼을 C로 필터링하면 A 값이 1과 2로 달라 A의 머지가 풀리므로 B의 C 데이터도 머지되지 않습니다.
해결 방법:

- 중간에 있는 컬럼도 머지가 필요하다면 해당 컬럼의 위치를 조정합니다.
- 중간 컬럼의 머지가 필요하지 않다면 그 컬럼에만 `ColMerge:0`을 설정합니다. 전체 머지 유형을 `msPrevColumnMerge`로 두고 머지하지 않을 컬럼에 `ColMerge:0`을 주면(해당 컬럼이 항상 머지되지 않는다는 전제) 나머지 컬럼은 앞 컬럼 머지의 영향을 받아 머지됩니다.
- 중간에 머지가 풀려도 이후 컬럼을 머지해야 하면 `msBaseColumnMerge`로 변경합니다.
- 특정 데이터 일부만 머지하려면 `SetMergeCell()`을 사용할 수 있습니다.

**키워드**: msPrevColumnMerge, ColMerge:0, msBaseColumnMerge, SetMergeCell, 필터, 앞컬럼 머지

---

### [MRG-0032] 앞컬럼 머지 행 수가 컬럼마다 다르거나 일부 행부터 머지가 깨지고 뒤 컬럼까지 깨지는 경우

**질문**

- 앞컬럼 머지가 5개 행으로 됐는데 그다음 컬럼은 6개 행이 머지됩니다. 어떻게 처리해야 하나요?
- mergeSheet를 8로 사용하는데 일부 행에서 머지가 깨지고 이후 뒤 컬럼들도 머지가 깨집니다.

**답변**

앞컬럼 머지와 헤더 머지를 함께 사용하도록 설정합니다. 단 중간에 머지가 필요 없는 컬럼은 `colMerge:0`을 주어 앞컬럼 머지가 유지되도록 합니다.
`colMerge:1`로 설정된 컬럼에서 머지하려는 행들이 서로 다른 데이터를 가지고 있으면 그 이후부터 머지가 깨지고 뒤 컬럼도 함께 깨집니다. 같은 데이터를 넣은 히든 컬럼을 두어 기준으로 삼는 방법으로 처리할 수 있습니다.

**키워드**: colMerge:0, mergeSheet, 앞컬럼 머지, 헤더 머지, 히든 컬럼

### [MRG-0033] 앞컬럼 머지의 기준 컬럼은 어떻게 정해지고, 사이에 낀 컬럼·SEQ 컬럼·코드명 컬럼은 어떻게 처리하나요?

**질문**

- 앞컬럼 머지를 설정했는데 생각대로 머지되지 않습니다. 앞컬럼은 어떤 컬럼을 말하며, 맨 앞에 SEQ 컬럼이 있을 때는 어떻게 해야 하나요?
- 앞컬럼 기준 머지에서 기준 컬럼과 병합할 컬럼 사이에 다른 컬럼이 끼어 있거나 앞쪽 컬럼의 공백끼리 머지됩니다.
- 코드는 다르지만 코드명이 같은 데이터를 앞컬럼 머지할 때, 코드에 따라 코드명이 분리되어 머지되게 하려면 어떻게 하나요?
- 앞컬럼 머지를 사용하는데 사번이 서로 다른데도 이름이 머지됩니다.

**답변**

앞컬럼 머지에서 기준이 되는 앞컬럼은 자신보다 앞에 있는 컬럼 중 `ColMerge:1`을 가진 컬럼이며, 앞 컬럼의 기준 값별로 머지됩니다.

- 맨 앞에 SEQ 컬럼이 있으면 머지가 되지 않을 수 있으므로 해당 컬럼에 `ColMerge:0`을 설정합니다.
- 중간에 낀 컬럼이나 기준 컬럼 앞쪽 컬럼에 공백이 있으면 공백끼리 머지되는 등 의도와 다르게 머지될 수 있으므로, 해당 컬럼에 `ColMerge:0`을 부여해 건너뛰거나 컬럼 위치를 이동합니다.
- 코드는 다르지만 코드명이 같은 경우 코드 컬럼(히든 컬럼)이 코드명 컬럼 앞에 위치하고 `Merge:1`로 설정되어 있으면 코드에 따라 코드명이 분리되어 머지됩니다. 코드 컬럼의 위치가 코드명 앞인지 확인합니다.
- 사번이 서로 다른데 이름이 머지된다면 머지의 기준 컬럼을 의도한 컬럼(예: 사번 컬럼)으로 변경합니다.
- 그룹별로 표시하려면 그룹화하려는 데이터 순서에 맞게 컬럼 정보를 세팅해 셀의 위치를 재조정합니다.

**키워드**: ColMerge:0, 앞컬럼 머지, SEQ 컬럼, 기준 컬럼, Merge:1, 히든 컬럼

## 기준컬럼·히든 기준 컬럼

### [MRG-0034] msBaseColumnMerge의 기준 컬럼은 어떻게 정해지고 어떻게 설정하나요? (숨김 컬럼이 기준이 되는 경우 포함)

**질문**

- 기준 컬럼이 머지되어 있으면 그 영역 안에서 다른 컬럼도 머지되게 하려면 어떻게 설정하나요? 머지에서 제외할 컬럼은 어떻게 하나요?
- msBaseColumnMerge에서 기준 컬럼은 어떻게 정해지나요? ColMerge가 1인 숨김 컬럼을 맨 앞에 두었는데 화면에 보이는 첫 컬럼이 기준인 것처럼 보입니다.
- msBaseColumnMerge로 병합할 때 기준 컬럼의 병합 범위대로 뒤쪽 컬럼들이 함께 병합되지 않고 일부 컬럼이 따로 병합됩니다.
- msPrevColumnMerge나 msBaseColumnMerge를 사용하는데 ColMerge:1로 설정한 컬럼이 머지되지 않습니다. 맨 앞에 숨김 컬럼이 있는 경우 원인은 무엇인가요?

**답변**

`msBaseColumnMerge`는 앞컬럼 머지와 달리 머지가 풀렸다가 다시 머지될 수 있는 방식입니다. 컬럼들 중 좌측으로부터 첫 번째로 `ColMerge:1`인 컬럼이 기준 컬럼이 되고, 기준 컬럼의 머지 영역 안에서 다른 컬럼들이 머지됩니다.

- 설정: `MergeSheet`를 `msBaseColumnMerge`로 설정하고 기준이 되는 컬럼을 제일 앞에 둡니다. 머지하지 않을 컬럼은 InitColumns에서 `ColMerge:0`으로 설정합니다.
- 여러 행(예: 3줄)씩 묶이는 기준 컬럼을 컬럼 순서상 제일 앞에 두고 그 컬럼부터 머지가 시작되도록 구성해야 뒤쪽 컬럼이 기준 컬럼의 범위대로 함께 머지됩니다.
- 기준 컬럼을 숨겨도 머지 결과는 동일합니다. 숨김(`Hidden:1`) 컬럼도 예외가 아니어서, 맨 앞의 숨김 컬럼이 `ColMerge:1`이면 그 컬럼이 기준이 되어 의도한 컬럼이 머지되지 않을 수 있으므로 해당 숨김 컬럼에 `ColMerge:0`을 설정합니다. `msPrevColumnMerge`에서도 `ColMerge:1`인 컬럼 중 첫 컬럼부터 순차적으로 머지됩니다.

**키워드**: msBaseColumnMerge, ColMerge, MergeSheet, 기준 컬럼, Hidden, ColMerge:0

### [MRG-0035] msPrevColumnMerge와 msBaseColumnMerge는 어떻게 다르고 구분 컬럼별로 나누어 머지하려면 무엇을 쓰나요?

**질문**

- 구분 컬럼 값별로 나누어 머지하려는데 값이 같으면 다른 구분에서도 머지됩니다. msPrevColumnMerge와 msBaseColumnMerge는 어떻게 다르고 어떤 것을 써야 하나요?

**답변**

SetConfig의 `MergeSheet`를 `msPrevColumnMerge + msHeaderOnly` 또는 `msBaseColumnMerge + msHeaderOnly`로 설정합니다.

- 앞컬럼 머지는 앞 컬럼이 머지되어 있으면 연속으로 머지하므로, `ColMerge:1`(기본값 1)인 컬럼의 데이터가 달라 머지가 풀리면 그 뒤 컬럼은 `ColMerge:1`이어도 머지되지 않습니다.
- 기준컬럼 머지는 기준 컬럼이 머지되어 있으면 그 기준 컬럼을 기준으로 `ColMerge:1`인 컬럼의 같은 데이터를 무조건 머지하므로, 중간에 머지가 풀려도 같은 데이터를 머지하거나 중간 컬럼을 기준으로 지정하려면 `msBaseColumnMerge + msHeaderOnly`를 사용합니다.

**키워드**: msPrevColumnMerge, msBaseColumnMerge, MergeSheet, msHeaderOnly, ColMerge

### [MRG-0036] 머지 기준 컬럼보다 앞쪽 컬럼(체크박스 등)이나 뒤쪽 컬럼을 기준으로 머지하려면 어떻게 하나요?

**질문**

- 앞컬럼 머지에서 머지 기준이 되는 컬럼보다 앞쪽에 체크박스 같은 컬럼이 있거나 마지막 컬럼을 기준으로 머지하고 싶습니다. 어떻게 설정하나요?
- A, B, C, D 컬럼이 있을 때 B 컬럼을 기준으로 머지하고 싶고 A 컬럼도 B 기준으로 머지되어야 합니다. 어떻게 해야 하나요?

**답변**

앞컬럼 머지(`PrevColumnMerge`)는 앞컬럼을 바라보며 머지하므로 머지 기준 컬럼보다 앞에 있는 컬럼(예: 체크박스)이나 뒤에 있는 컬럼을 기준으로는 그대로 머지되지 않습니다. 기준이 될 컬럼과 동일한 데이터를 가진 `Hidden` 컬럼을 하나 더 만들어 제일 앞(예: A 앞)에 위치시키면 그 컬럼부터 머지되어 기준 컬럼과 같이 머지되도록 설정할 수 있습니다. 항상 B가 기준이라면 앞컬럼 머지보다 `msBaseColumnMerge`로 `MergeSheet`를 설정하는 것이 좋습니다.

**키워드**: PrevColumnMerge, Hidden, msBaseColumnMerge, MergeSheet, 기준 컬럼

### [MRG-0037] 히든 기준 컬럼으로 마지막 행만 머지에서 제외하거나 SetMergeCell 반복 없이 빠르게 머지하는 방법

**질문**

- OnSearchEnd에서 InitCellProperty로 특정 셀의 ColMerge를 0으로 지정했는데도 값이 같으면 병합됩니다. 마지막 행만 병합에서 제외하려면 어떻게 하나요?
- 같은 값을 가진 행들을 머지하는데 SetMergeCell을 for 문으로 반복 호출하는 방식보다 빠르게 처리하는 방법이 있나요?

**답변**

일반적인 머지 패턴으로 처리하기 어려운 경우 데이터를 변형해 `msBaseColumnMerge` 기준 컬럼 방식으로 처리합니다.

- 머지 대상 컬럼 앞(예: seq 컬럼 옆)에 빈 컬럼을 `Hidden`으로 추가하고 기준 값이 들어 있는 데이터를 조회해 옵니다. 예를 들어 `{1,1,1,1,1,2}`처럼 조회하면 5행은 머지되고 마지막 행은 머지에서 제외됩니다. `MergeSheet`를 `msBaseColumnMerge`(또는 `4`)로 설정해 감춰진 컬럼을 기준으로 삼게 합니다.
- 머지가 불필요한 컬럼은 `ColMerge:0`으로 제외하고, 소계행과 증감량 데이터의 가로 머지가 필요하면 `DataRowMerge:1`을 추가합니다.
- 이 방식은 조회 시점에 데이터 렌더링과 머지 렌더링이 함께 이루어져 `SetMergeCell`을 for 문으로 반복 호출하는 것보다 속도가 훨씬 빠릅니다.

## PrevColumnMergeMode·Page 끊김

### [MRG-0038] 앞컬럼 머지가 Page(기본 20행) 단위로 끊기거나 특정 행부터 병합되지 않는 이유와 PrevColumnMergeMode:0

**질문**

- SearchMode:smLazyLoad에서 병합이 20행 같은 일정 간격으로 끊기거나 스크롤하면 병합이 풀립니다. 어떻게 해결하나요?
- 앞 컬럼 병합(msPrevColumnMerge)이 Page에 설정한 행 수마다 끊어집니다. 전체 데이터에서 병합하려면 어떻게 하나요?
- 같은 값인데도 20번째와 21번째 행처럼 Page 경계에서 병합이 분리되어 그려집니다.
- 시트의 특정 행에서 병합(머지)이 적용되지 않습니다. 어떤 설정을 확인해야 하나요?

**답변**

조회 시 머지는 렌더링 속도를 위해 `Page` 설정값(기본 20) 단위로만 처리됩니다. `SearchMode:smLazyLoad`(`SearchMode:2`)에서는 데이터를 변수에 보관했다가 스크롤이 일정 구간 이동하면 Page 단위로 가져와 하단에 append하므로, Page 경계(예: 20번째와 21번째)의 행은 값이 같아도 병합이 분리되고 이후 추가 조회된 데이터도 이전과 병합되지 않습니다. `smServerPaging2`(Page:10)에서도 10번째와 11번째에서 깨지는 사례가 있었습니다.
해결: SetConfig(Cfg)에 `PrevColumnMergeMode:0`을 추가합니다. 다음 페이지를 렌더링할 때 마지막 데이터와 같은지 비교해 전체 데이터에서 병합을 유지하며, 내부적으로 Page 값을 바꿔 같은 데이터를 한 페이지에 담습니다.

- 앞컬럼 머지(`MergeSheet:msPrevColumnMerge`, 값 2 또는 7)에서만 동작하며, 앞컬럼 머지를 쓸 수 없는 시트는 현재로선 해결 방법이 없습니다. 예: `SetConfig({SearchMode:smLazyLoad, Page:20, MergeSheet:msPrevColumnMerge, PrevColumnMergeMode:0})`
- 머지된 행을 한 번에 화면 위로 올리므로 머지 행이 많을수록 조회·렌더링·스크롤 속도가 저하됩니다. 데이터를 보고 제한적으로 사용하세요.
- 일부 안내에는 속성명이 `PreColumnMergeMode`로 적혀 있습니다.

**키워드**: PrevColumnMergeMode, Page, SearchMode, smLazyLoad, msPrevColumnMerge, 머지 끊김

### [MRG-0039] PrevColumnMergeMode의 기본값과 0/1 설정값은 무엇이며 안내가 서로 다른 이유

**질문**

- 앞 컬럼 병합과 관련된 PrevColumnMergeMode와 Page의 기본값은 무엇이며 각각 어떻게 동작하나요?
- Page를 설정한 만큼 병합이 깨질 때 SetConfig의 PrevColumnMergeMode를 1로 설정하면 되나요?
- 세로로 병합할 수 있는 데이터 건수에 제한이 있나요? 같은 데이터인데도 병합이 되지 않습니다.

**답변**

`PrevColumnMergeMode`는 SetConfig(Cfg)에서 설정하며 기본값은 1(Page 단위로 병합 처리), `Page`의 기본값은 20입니다. 0으로 바꾸면 페이지 전체(전체 데이터) 단위로 병합을 계산하며, 데이터가 많으면 조회 속도가 느려집니다. `SearchMode:2`(smLazyLoad)에서는 기본적으로 Page에 설정된 갯수 내에서만 병합됩니다.
다만 일부 답변은 전체 데이터에서 병합하려면 `PrevColumnMergeMode`를 1로 설정하라고 안내하고(예: `PrevColumnMergeMode: 1`), 다른 답변은 기본값이 1이므로 0으로 설정해야 한다고 안내하여 값이 서로 다르게 적혀 있습니다. 값이 서로 달라 사용하는 버전의 도움말에서 값의 의미를 확인해야 합니다.

**키워드**: PrevColumnMergeMode, Page, SearchMode, 기본값, 전체 데이터 병합

### [MRG-0040] 머지 끊김을 PrevColumnMergeMode:0 대신 Page 값을 늘려 해결할 수 있나요? 권장 Page 값은?

**질문**

- 병합이 Page 단위로 분리될 때 Page 값을 조정해서 더 많은 행을 병합할 수 있나요? 어느 정도로 설정하나요?
- 병합이 Page 단위로 끊어질 때 PrevColumnMergeMode:0 대신 Page 값을 늘려서 해결할 수 있나요? 조건이 있나요?
- SearchMode:2에서 병합이 끊기지 않게 Page를 크게 설정해도 되나요?

**답변**

Cfg의 `Page` 값을 늘리면 더 많은 행을 하나의 병합 단위로 처리할 수 있습니다.

- 조회되는 행 수가 고정적이고 적은 화면(예: 전체 100건 이내)이나 단건 조회 화면에서는 기본값 20을 현재 데이터 크기 정도(예: 100)로 키워 해결할 수 있습니다.
- `SearchMode:2`는 전체 데이터를 메모리에 들고 있고 Page에 설정한 개수만큼만 그리므로 Page를 크게 잡는 것은 권장되지 않습니다. 권장은 20~50개이고 크게 잡아도 최대 100개 정도입니다. Page를 늘려도 병합된 데이터는 Page 단위로 분리되며 더 많은 데이터를 병합 처리할 수 있을 뿐입니다.
- 앞컬럼 머지(`msPrevColumnMerge`, `MergeSheet:2` 또는 `7`)에서 행 수를 한정할 수 없으면 `PrevColumnMergeMode:0`을 설정해 전체 병합을 유지합니다. 이 경우 병합 행이 많을수록 속도가 저하되고 데이터가 많으면 속도 이슈가 있습니다.
- `MergeSheet:1`에서는 `Page` 값을 변경하는 방법 외에 별도 옵션이 없습니다.

**키워드**: Page, PrevColumnMergeMode, SearchMode:2, MergeSheet, Page 권장값, 머지 끊김

### [MRG-0041] 앞컬럼 머지에서 그룹 단위로 머지를 나누려면 Hidden 기준 컬럼을 어떻게 추가하나요?

**질문**

- 앞컬럼 머지에서 그룹 컬럼 단위로 머지를 나누고 싶거나, PrevColumnMergeMode:0 없이 대량 데이터의 머지를 유지하려면 어떻게 하나요?

**키워드**: 앞컬럼 머지, Hidden 컬럼, 그룹 머지, Page, PrevColumnMergeMode

### [MRG-0042] 소계 사용 시 같은 그룹이 둘로 나뉘어 병합되는데 다시 조회하면 합쳐져 보이는 이유

### [MRG-0043] PrevColumnMergeMode:0을 설정해도 병합이 끊길 때 MergeSheet(msAll, msNone)와 ColMerge 설정 조합

**질문**

- PrevColumnMergeMode:0을 설정했는데도 병합이 중간에 끊깁니다. 병합 유형이 msAll이면 적용되지 않나요?
- 컬럼 병합(msPrevColumnMerge)이 적용되지 않거나 상하로 병합이 안 되는 부분이 있습니다. 어떤 설정이 필요한가요?
- 조회 모드가 lazyload이고 ColMerge를 설정했는데 병합이 되지 않고 중간에 풀립니다.

- SetConfig에 `PrevColumnMergeMode:0`

### [MRG-0044] 병합(colmerge) 컬럼이 있는 시트의 조회가 느릴 때 원인과 ColMerge:2 대안

**질문**

- 병합(colmerge) 컬럼이 있는 시트에서 병합 컬럼이 없을 때보다 성능이 더 느립니다. 원인이 무엇인가요?
- 병합 때문에 조회 속도가 느리고 만 건 데이터에서 병합이 Page 단위로 풀립니다. 속도를 줄이거나 병합을 유지할 방법이 있나요?

**답변**

`PrevColumnMergeMode:0` 설정은 전체 데이터에서 병합을 계산하므로 병합이 있는 화면의 성능이 더 느려질 수 있습니다. SetConfig 함수의 page 갯수만큼 병합이 끊겨 계산되는 것과 달리, `PrevColumnMergeMode`를 설정하면 전체 데이터를 대상으로 병합을 계산하기 때문입니다.
병합 처리 자체에서 속도를 줄일 부분은 없고, 만 건 데이터에서 병합 유지와 속도를 함께 해결할 방법도 현재는 없습니다(`SearchMode:3` 페이징에서도 page 건수에 따라 병합이 풀립니다). 대안으로 InitColumns의 `ColMerge:2`는 병합된 영역의 보더를 지워 병합된 것처럼 보이게 하며 속도가 다소 빠를 수 있습니다. 조회용 화면에는 유용하지만 값을 편집해 저장하는 화면에는 유용하지 않습니다.

**키워드**: PrevColumnMergeMode, ColMerge:2, 병합 성능, SearchMode:3, InitColumns, 조회 속도

### [MRG-0045] ActiveX와 달리 HTML 시트의 앞컬럼 머지는 스크롤 시 값이 계속 보이지 않는 이유

### [MRG-0046] msBaseColumnMerge에서 Page 경계에서 병합이 깨질 때 PrevColumnMergeMode를 쓸 수 있나요?

- msBaseColumnMerge를 사용할 때 PrevColumnMergeMode를 설정한 것처럼 앞 컬럼 병합을 유지하는 기능이 있나요?
- msBaseColumnMerge + msHeaderOnly로 머지하는데 특정 행 위치에서 머지가 깨지거나 일부 행만 머지되지 않습니다.

## SetMergeCell 사용법

### [MRG-0049] 특정 영역이나 합계행을 강제로 머지하는 SetMergeCell은 어떻게 사용하나요?

**질문**

- 자동 머지가 아니라 시트의 일부분만 강제로 머지하고 싶습니다. 어떤 메소드를 사용하나요?
- 특정 컬럼의 행이나 합계 행을 강제로 머지하려면 SetMergeCell 인자를 어떻게 지정하나요?
- 머지된 셀에는 어떤 데이터가 표시되나요?

**답변**

일부 영역을 강제로 머지할 때는 `SetMergeCell`을 사용합니다.

- 형식: `SetMergeCell(머지시작 행 index, 머지시작 열 index, 아래로 머지할 행 개수, 오른쪽으로 머지할 열 개수)`. 예: `mySheet.SetMergeCell(0, 0, 1, 2);`는 0행 0열 셀부터 1개 행, 2개 컬럼을 병합합니다.
- 합계 행은 `OnSearchEnd` 이벤트에서 `SetMergeCell(mySheet.LastRow(), 1, 1, 3)`처럼 호출합니다.
- 머지하면 첫 번째(좌측 상단) 셀의 데이터가 표시되므로 보여 줄 값을 그 셀에 먼저 넣어 둡니다(`SetCellText` 등).
- 조회가 끝나 데이터가 존재하는 상태에서 호출해야 하며, 강제 머지는 조회용 시트에서만 사용하도록 권장합니다. 수정·저장하는 시트에서는 문제의 소지가 많습니다.

**키워드**: SetMergeCell, 강제 머지, 합계행 머지, OnSearchEnd, LastRow, 셀 병합

### [MRG-0050] Type이 다른 셀(Text, CheckBox 등)을 SetMergeCell로 가로 머지하려면?

**질문**

- Text와 CheckBox 등 Type이 다른 인접 셀을 특정 행에서 하나로 합쳐 colspan처럼 표시하고 싶습니다.
- 합칠 행이 동적으로 늘거나 줄어도 머지하려면 어떻게 하나요?
- 데이터 타입이 서로 다른 컬럼을 SetMergeCell로 가로 머지할 수 있나요?

**답변**

`SetMergeCell`은 셀의 데이터 타입이 달라도 머지됩니다. Type이 다른 셀은 `SetMergeCell()`로 강제 머지하고 `SetCellValue()`로 값을 넣어 구현합니다.

- 첫 번째 컬럼의 Type은 초기화 시 Text로 지정합니다.
- 조회 완료 후 `OnSearchEnd`에서 `SetMergeCell(12,0,1,3)`을 호출한 뒤 `SetCellValue(12,0,"잔여용구")`처럼 값을 입력합니다(조회 데이터에 값이 포함되어 있으면 `SetCellValue` 호출은 불필요).
- 대상 행 수를 모르면 `OnSearchEnd`에서 `HeaderRows()`부터 `LastRow()`까지 반복하며 `GetCellValue(i,0)`가 해당 값인 행마다 `SetMergeCell(i,0,1,3)`을 호출합니다.
- 머지가 되지 않으면 `SetMergeCell` 인자를 잘못 설정한 것은 아닌지 확인하세요.

**키워드**: SetMergeCell, SetCellValue, OnSearchEnd, HeaderRows, LastRow, Type 다른 셀 머지

### [MRG-0051] 특정 행·영역이나 조건에 맞는 셀만 강제로 머지하려면 어떻게 하나요?

**질문**

- 같은 값끼리 머지하는 자동 머지가 아니라, 특정 영역이나 일부분, 값이 다른 셀, 조건에 맞는 셀만 강제로 머지하고 싶습니다.
- 특정 조건의 행(예: 구분 값이 특정 값일 때)에서만 가로 머지를 적용하는 기능이 있나요?
- 데이터 조회가 완료된 후에 특정 셀들을 강제로 병합하고 싶습니다. 어떤 함수를 사용하나요?

**답변**

IBSheet의 자동 머지는 가로(`SetConfig({DataRowMerge:1})`)와 세로 모두 같은 데이터가 있을 때 머지되는 방식이며, 특정 행만 머지하는 기능은 없습니다. 이때는 조회 완료 후 `setMergeCell()`(`SetMergeCell()`)로 강제 머지합니다.

- 특정 데이터 영역이나 일부분, 값이 서로 다른 셀도 머지할 수 있습니다.
- 조건에 따라 머지해야 한다면 `OnSearchEnd` 이벤트에서 조건에 맞게 for 반복문을 이중으로 구현해, 조건을 만족할 때 `SetMergeCell()`을 호출합니다.
- 머지할 셀이 고정되어 있고 데이터가 많지 않은 경우, 조회용 시트에서 마지막 행만 머지하는 경우에 적합합니다.

**키워드**: SetMergeCell, setMergeCell, DataRowMerge, OnSearchEnd, 강제 머지, 조건부 머지

**질문**

### [MRG-0053] RowMerge로 특정 행을 가로로 머지하고 CheckBox 컬럼은 조건부로 병합하는 방법

**질문**

- 시트의 데이터 영역에서 특정 row를 가로 방향으로 머지(병합)하고 싶습니다. 어떤 기능이나 속성을 이용하면 되나요?
- CheckBox 타입 컬럼에 RowMerge를 적용하면서, 조회 후 특정 데이터가 있는 행만 병합되도록 하려면 어떻게 하나요?

**키워드**: RowMerge, SetRowMerge, OnRowSearchEnd, CheckBox, 가로 머지

### [MRG-0054] 멀티 라인 레코드 시트에서 같은 데이터를 머지하려면 컬럼에 어떤 속성을 설정하나요?

## SetMergeCell 안 될 때·제약

### [MRG-0055] SetMergeCell을 호출했는데 아무 변화나 오류 없이 머지되지 않는 원인

**질문**

- SetMergeCell로 강제 머지를 했는데 아무 변화가 없고 오류 메시지도 나오지 않습니다. 원인이 무엇인가요?
- 합계행 등 특정 행을 가로 머지했는데 머지되지 않습니다. 세 번째 인자에 행 번호나 i 값을 넣어도 되나요?
- SetMergeCell 인자에 SaveName이나 문자열 값을 넣어도 되나요?

**답변**

`SetMergeCell`은 인자가 유효하지 않으면 오류나 경고 없이 아무 동작도 하지 않습니다. 다음을 확인하세요.

- 세 번째 인자는 머지할 행의 개수입니다. 행 번호(예: `LastRow()` 값)나 for 반복문의 i 값, 0을 넣으면 머지되지 않으며, 1개 행을 가로로 머지하려면 1을 지정합니다.
- 컬럼 위치에는 SaveName이 아니라 Col index를 넣어야 합니다.
- 인자는 숫자여야 합니다. `FindSumRow()`처럼 문자열을 반환하는 값이나 String 값을 그대로 넘기면 동작하지 않으므로 `Number()` 또는 `parseInt`로 변환해 전달합니다. 이전 버전에서는 문자열도 동작했던 것으로 보입니다.
- 올바른 예: `mySheet.SetMergeCell(4,0,1,2)`

**키워드**: SetMergeCell, FindSumRow, Number, parseInt, Col index, 머지 안됨

### [MRG-0056] SetMergeCell을 초기화 부분에서 호출하면 머지가 적용되지 않는 이유

**키워드**: SetMergeCell, OnSearchEnd, 초기화, 강제 머지, 호출 시점

### [MRG-0057] SetMergeCell로 머지한 셀의 값이 비어 있거나 문자 값만 표시되지 않는 경우

**질문**

- SetMergeCell로 셀을 강제 머지했는데 머지된 이후에 값이 채워지지 않고 비어 있습니다.
- 데이터 행을 SetMergeCell로 가로 머지했는데 문자 값은 표시되지 않고 숫자 값만 표시됩니다.

- 병합된 시트에 새 행을 추가하면 병합된 컬럼에도 새 행이 같이 병합되게 하고 싶습니다. 자동으로 병합되나요?
- 행을 추가한 뒤 윗 셀과 같은 데이터로 채웠는데 자동으로 머지되지 않습니다. 실시간 머지가 가능한가요?

**답변**

IBSheet7은 실시간 머지를 지원하지 않으며, 행 추가 직후나 값을 입력한 뒤에는 자동으로 머지되지 않습니다. 조회한 데이터가 아니라 `CellText`로 값을 넣은 입력 데이터에는 `DataRowMerge:1`을 설정해도 머지가 되지 않고, 조회된 데이터만 머지가 가능하며 입력된 데이터는 강제머지를 사용해야 합니다. 저장 후 재조회하는 경우가 아니라면 자동 병합 기능이 없습니다(7 버전에서는 기본값을 가진 컬럼(체크박스, Int 등)만 머지될 뿐 Text 컬럼은 머지되지 않습니다).

- 적절한 시점에 `SetDataMerge(0)`를 호출해 기존 병합 정보를 유지하면서 데이터 영역의 병합 처리를 합니다. ActiveX는 위나 아래 행과 같은 값이 들어오면 머지가 자동 동작했지만 Sheet 7은 `SetDataMerge()`를 호출해야 하며, 행 추가 시 머지된 상태로 보려면 특정 시점을 잡아 호출하는 방법뿐입니다. 조회 데이터가 많은 시트에서 이 함수를 호출하면 성능이 저하됩니다.
- 신규 행에 강제로 머지하려면 `SetMergeCell()`로 머지할 영역을 지정해 수동으로 처리합니다.

**키워드**: SetDataMerge, SetMergeCell, DataInsert, DataRowMerge, 강제머지, 실시간 머지, CellText

### [MRG-0099] 행 추가·복사·이동·append 조회·행 병합 설정 후 머지가 안 맞을 때 SetDataMerge를 다시 호출하는 방법

**질문**

- DataInsert로 행을 추가하고 SetCellValue로 각 셀에 값을 넣었는데 머지가 적용되지 않습니다. 어떻게 하면 되나요?
- DataCopy나 행 이동, 행 추가로 데이터를 바꾼 뒤 머지가 맞지 않습니다. 머지를 다시 적용하려면 어떻게 하나요?
- 조회된 데이터를 append:true로 이어 붙여 조회하면 기존에 적용한 셀 병합(머지)이 깨집니다.

**답변**

머지는 실시간으로 재계산되지 않으므로 데이터를 바꾼 뒤 `SetDataMerge`를 호출해 다시 적용합니다. `SetDataMerge`는 비공개 함수입니다.

- 행 추가·복사 후 기존 병합 영역을 `SetSplitMergeCell`로 분할하고 `SetDataMerge`로 재병합하는 방법도 있습니다.
- `msBaseColumnMerge` 설정에서 머지되지 않은 행을 머지된 행 사이로 옮기거나 행을 추가한 뒤에는 렌더링만 다시 하는 것(Rerender)으로는 부족하고 `SetDataMerge(4)`를 호출해야 합니다.
- `append:true`로 조회한 뒤 병합이 깨지면 `OnSearchEnd`에서 `SetDataMerge()`를 호출합니다.
- `SetRowMerge`로 행 병합을 설정한 뒤에는 `SetDataMerge(0)`을 호출해야 설정이 반영됩니다.
- `GetRowData`/`SetRowData`로 다른 시트에 복사한 뒤에도 `SetDataMerge()`를 호출합니다.

**키워드**: SetDataMerge, SetSplitMergeCell, SetRowMerge, DataCopy, DataInsert, OnSearchEnd, append

### [MRG-0101] 세로 머지된 시트에서 DataCopy로 행을 복사하면 오동작하거나 복사된 행까지 머지될 때 대안

### [MRG-0102] 머지 후 값을 편집·붙여넣기·setCellValue로 바꿔도 머지가 갱신되지 않을 때(UpdateMergeCells, SetSplitMergeCell)

**질문**

- 머지된 시트에서 값을 편집하거나 붙여넣기, setCellValue로 바꿔도 머지가 갱신되지 않습니다. UpdateMergeCells의 역할과 머지를 다시 적용하는 방법은 무엇인가요?
- 머지된 시트에 행을 새로 추가하면 머지가 유지되지 않습니다. UpdateMergeCells로 신규 행도 머지할 수 있나요?
- MergeSheet가 msPrevColumnMerge인 상태에서 머지된 영역 최상위 행의 값을 바꾸면 머지된 전체 값이 바뀝니다. 해결 방법이 있나요?

- `msPrevColumnMerge`에서 머지 영역 최상위 행의 값만 바꾸려면 `SetSplitMergeCell(2,1)` → `SetCellValue(2,1,값)` → `SetDataMerge()` 순서로 처리합니다(값 변경 전에 해당 셀의 머지를 분할하고, 변경 후 `SetDataMerge()` 호출).

**키워드**: UpdateMergeCells, SetDataMerge(1), onChange, SetSplitMergeCell, setCellValue, LoadSearchData, msPrevColumnMerge

### [MRG-0103] DataMove로 머지된 행을 이동하면 머지가 풀리거나 이동 위치가 이상해질 때

**질문**

- 머지된 컬럼이 있는 시트에서 DataMove로 행을 옮기면 머지가 풀립니다. 머지를 유지하려면 어떻게 해야 하나요?

### [MRG-0108] UpdateMergeCells를 써도 SetCellValue나 헤더에는 반영되지 않거나 머지된 영역 값을 전체 행에 직접 설정해야 할 때

**질문**

- MergeSheet로 기준 컬럼을 잡아 머지했는데, 머지된 콤보 컬럼 값을 바꾸면 첫 행만 바뀌고 나머지 행은 그대로입니다. 왜 그런가요?
- 3개 행이 머지되어 있을 때 머지된 영역의 값을 바꾸면 3개 행이 모두 수정되나요? 어떻게 처리해야 하나요?
- 머지된 헤더 셀에 SetCellValue로 값을 넣은 뒤 Down2Excel로 내려받으면 머지 영역에 변경된 값이 아닌 원래 빈 값이 나옵니다.
- 값을 수정한 뒤에 병합(머지)된 셀의 모양이 바로 갱신되지 않습니다. 병합을 다시 적용하려면 어떻게 하나요?

**답변**

머지는 같은 값을 가진 셀을 하나로 합쳐 보여주는 처리로, 머지가 시작되는 첫 셀의 값을 보여줄 뿐 내부적으로는 개별 값을 그대로 유지하며 데이터가 조회되는 시점에만 적용됩니다. 그래서 값을 바꾸면 첫 번째 행만 변경됩니다.

- 영역 전체를 바꾸려면 `OnChange`에서 `GetMergedEndCell(행,열)` 결과를 `,`로 나눈 첫 값을 끝 행으로 삼아, 머지된 영역을 찾아 나머지 행에 `SetCellValue`로 같은 값을 강제로 설정합니다.
- `UpdateMergeCells` 속성은 사용자가 편집으로 값을 바꿀 때만 적용되고 API(`SetCellValue`)를 통한 변경에는 적용되지 않으며, 데이터 행에서만 동작하므로 헤더 행에는 적용할 수 없습니다. 헤더 머지 영역은 `GetMergedStartCell`, `GetMergedEndCell`로 기준 컬럼의 머지 시작과 끝을 찾아 머지된 셀들에 `setCellValue()`로 함께 값을 넣어야 합니다.
- 수정 후 병합을 다시 적용하려면 `mySheet.LoadSearchData(mySheet.GetSaveJson({AllSave:1}), {Sync:1})`처럼 현재 데이터를 `GetSaveJson`으로 추출해 같은 시트에 `LoadSearchData`로 다시 로드하는 방법이 있습니다.

**키워드**: GetMergedEndCell, GetMergedStartCell, UpdateMergeCells, SetCellValue, LoadSearchData, GetSaveJson, Down2Excel

### [MRG-0109] 머지된 체크박스를 체크하면 첫 번째 행만 값이 바뀌고 체크 행 조회도 첫 행만 나올 때 전체 행에 반영하는 방법

**질문**

- 체크박스 컬럼을 머지했을 때 체크/해제하면 첫 번째 행의 값만 바뀌고 나머지 행의 값은 들어가지 않습니다. 모든 행에 반영하려면 어떻게 하나요?
- 체크박스 컬럼이 머지되어 있을 때 한 행을 체크하면 머지 영역의 첫 번째 행만 값이 1이고 나머지는 0으로 읽힙니다.
- 머지된 체크박스 컬럼에서 체크된 행을 가져오면 머지된 첫 행만 조회됩니다. 머지된 전체 행의 데이터를 가져오는 방법이 있나요?
- MergeSheet:msPrevColumnMerge에서 기준 컬럼으로 CheckBox도 머지해 표시하려고 SaveName을 같게 했더니 선택된 행을 찾지 못합니다.

**답변**

머지된 상태에서 한 행을 클릭하면 머지된 행 전체가 아닌 한 행만 선택되며(하위 호환성을 위한 동작), 머지된 체크박스는 체크해도 머지가 풀리지는 않지만 상태 변화는 첫 번째 행만 됩니다. 버전 차이가 아니라 머지된 행들의 값을 함께 바꿔 주는 로직이 없어서입니다. 체크된 행 조회도 단위 데이터 행의 기준이 되는 첫 번째 행의 데이터만 가져옵니다.

- `OnChange`(또는 `onClick`) 이벤트에서 해당 체크박스 컬럼이면 `GetMergedEndCell(Row,Col)`이 반환하는 값을 `,`로 나눈 첫 값으로 머지 종료 행을 구하고, 현재 행 다음부터 종료 행까지 `SetCellValue`로 같은 체크값을 설정합니다.
- 머지 영역 전체 데이터가 필요하면 `GetMergedStartCell`과 `GetMergedEndCell`(`GetMergeStartCell`, `GetMergeEndCell`로도 표기)로 머지 시작·끝 row/col index를 구해 머지된 행들의 데이터를 가져옵니다.
- 기준 컬럼(예: 회차)과 CheckBox가 같은 `SaveName`을 가지면 체크된 값을 정확히 찾을 수 없으므로, 첫 CheckBox 컬럼 앞에 기준 컬럼과 동일한 컬럼을 `Hidden:1`, `ColMerge:1`로 추가하면 그 뒤의 CheckBox도 머지됩니다.

**키워드**: GetMergedEndCell, GetMergedStartCell, OnChange, CheckBox, SetCellValue, SaveName, ColMerge:1

### [MRG-0110] 머지된 체크박스 컬럼에서 헤더 전체 체크 시 머지 영역마다 첫 행만 체크되게 하는 방법

**질문**

- 머지된 행이 있는 시트에서 헤더의 전체 선택을 누르면 머지된 두 행이 모두 수정 상태가 되어 중복 전송됩니다. 하나의 행만 처리되게 할 수 있나요?
- 머지된 체크박스 컬럼에서 헤더의 전체 체크를 눌렀을 때, 머지된 첫 번째 행만 체크된 것처럼 동작하게 하려면 어떤 이벤트와 함수를 사용하나요?
- 머지된 체크박스 컬럼에서 헤더 전체 체크박스를 눌렀을 때 머지된 영역마다 맨 위 행 하나만 체크되게 하는 기능이 있나요?

**답변**

`UpdateMergeCells:0` 설정에서 전체 체크 시 머지 영역 안의 맨 위 행만 체크하는 기능은 제공되지 않아 소스로 구현해야 합니다.

- `OnBeforeCheck` 이벤트에서 모든 행에 체크가 돌 때 머지 여부를 판단해, 머지된 하위 행은 `SetAllowCheck`로 체크가 되지 않도록 설정합니다.
- 구체적으로는 `OnMouseDown`에서 `MouseRow`와 `HeaderRows`로 헤더 클릭 여부를 저장해 두고, `OnBeforeCheck`에서 `GetMergedStartCell`과 `GetMergedEndCell`이 서로 다른 머지 셀이고 헤더 클릭이면 `SetAllowCheck(0)`으로 막은 뒤 머지 시작 행에만 헤더 체크 값(`GetHeaderCheck`)을 `SetCellValue`로 설정합니다. 그 외에는 `SetAllowCheck(1)`로 엽니다.
- 또는 `OnCheckAllEnd` 이벤트에서 `GetMergedStartCell`로 머지가 시작되는 행을 찾고, 나머지 행은 `SetCellValue`로 체크 상태를 해제하는 로직을 구현합니다.

**키워드**: OnBeforeCheck, SetAllowCheck, OnCheckAllEnd, GetHeaderCheck, UpdateMergeCells:0, GetMergedStartCell, 헤더 전체 체크

### [MRG-0111] 맨 앞 체크박스 컬럼을 다른 컬럼의 머지 범위에 맞춰 병합하는 방법(SetMergeCell 강제 병합)

**질문**

- 같은 값끼리 병합되도록 설정한 컬럼이 있는 그리드에서 맨 앞의 체크박스 컬럼도 함께 병합되어 보이게 할 수 있나요?
- 우측 컬럼에서 머지된 영역의 범위만큼 체크박스 컬럼의 셀도 병합하고 싶습니다. 병합 범위를 어떻게 가져와 처리하나요?
- 앞컬럼 머지를 쓰면서 맨 앞 체크박스 컬럼을 두 번째 컬럼의 머지 영역에 맞춰 머지하고 싶습니다. 어떻게 구현하나요?

**답변**

체크박스는 `MergeSheet` 옵션으로 병합되지 않으며 앞컬럼 머지 설정만으로는 첫 번째 컬럼이 다른 컬럼의 머지 영역에 맞춰지지 않습니다. 앞컬럼 머지는 유지하고, 체크박스 컬럼은 대상 컬럼의 머지된 영역을 계산해 강제로 머지합니다.

- `GetMergedStartCell`, `GetMergedEndCell`로 병합의 범위를 가져온 뒤 `SetMergeCell()`로 강제 병합하는 로직을 구현합니다.
- 병합된 이후에는 최상단 행만 체크박스가 동작하므로 권장하지는 않습니다. 병합된 영역에서 최상단을 제외한 셀의 값을 바꾸려면 `CellValue` 함수로만 변경할 수 있습니다.

**키워드**: SetMergeCell, GetMergedStartCell, GetMergedEndCell, MergeSheet, 체크박스 병합, 앞컬럼 머지, 강제 병합

### [MRG-0112] 머지 영역의 시작·끝 셀을 구하는 GetMergedStartCell, GetMergedEndCell 사용법과 활용(행 추가, 병합 여부 확인, validation 제외)

**질문**

- 앞 컬럼 머지를 사용할 때 같은 값의 행을 추가해 기존 머지에 포함시키려면 어떻게 하나요? 머지 영역의 시작·끝 셀을 구하는 함수도 알고 싶습니다.
- 머지된 셀을 선택하면 어떤 행·열이 반환되며, 머지된 영역의 마지막 행은 어떻게 알아내나요?
- 특정 셀이 세로로 병합된 셀인지 여부를 확인하고 싶습니다. 병합 여부를 바로 반환해 주는 함수가 있나요?
- colspan으로 강제 머지한 영역에서 첫 번째 행을 제외한 값 없는 셀은 validation 체크를 하지 않으려면 어떻게 하나요?

**답변**

머지 영역은 `GetMergedStartCell` / `GetMergedEndCell`(일부 문서에는 `GetMergeStartCell`, `GetMergeEndCell`로 표기)로 계산합니다.

- 머지된 영역을 선택하면 시트는 머지 영역의 첫 번째 행과 셀만 반환합니다(`OnSelectCell`의 NewRow, NewCol). 영역의 마지막 행은 `GetMergedEndCell(srow,scol)`이 반환하는 쉼표 구분 문자열의 첫 값으로 구하며, 시작 행부터 그 행까지 반복해 각 행을 처리할 수 있습니다.
- 특정 셀 자체가 세로 병합인지 반환하는 함수는 제공하지 않으므로, `GetMergedStartCell`, `GetMergedEndCell`로 병합된 영역을 가져와 확인합니다.
- 앞 컬럼 머지에서 같은 값의 행을 기존 머지에 포함시키려면 `GetMergedEndCell`로 머지된 셀의 마지막 행을 구해 그 위치에 `DataInsert`를 합니다. `GetSelectRow`로 구한 선택 행 위치에 넣으면 머지가 풀릴 수 있습니다.
- colspan으로 머지된 영역은 하위 셀에 값이 없어도 강제로 머지된 것이므로, `SetCellValue()`로 동일한 값을 넣어 주거나 머지 영역을 확인해 해당 컬럼들 사이는 Validation 체크를 하지 않도록 처리합니다.

**키워드**: GetMergedStartCell, GetMergedEndCell, DataInsert, GetSelectRow, OnSelectCell, colspan, validation

### [MRG-0115] 앞컬럼 머지에서 체크박스를 다른 컬럼의 머지 영역(그룹)에 맞춰 머지하려면 어떻게 하나요?

**질문**

- 앞컬럼 머지를 사용할 때 맨 앞 체크박스 컬럼이 뒤쪽 컬럼의 머지 영역 기준으로 머지되게 하려면 어떻게 하나요?
- 그룹별로 나누어지는 체크박스를 구현할 때 숨김 시트에 데이터를 복사하지 않고 처리할 수 있는 방법이 있나요?
- 체크박스 컬럼을 여러 셀 머지했을 때 OnClick 이벤트에서 머지 영역 전체를 동일하게 체크/해제하고 있습니다. 이렇게 직접 처리해야 하나요?

**답변**

체크박스 앞에 기준이 될 컬럼과 같은 값의 컬럼을 `Hidden`으로 하나 더 추가하고 앞컬럼 머지를 사용합니다. 히든 컬럼은 보이지 않지만 기준 컬럼으로 동작해 체크박스도 그 기준대로 그룹별로 머지됩니다. 이 방식이므로 숨김 시트에 데이터를 복사할 필요가 없습니다.

- 필요하면 체크박스 컬럼에 `ColMerge:1`을 설정합니다.
- 체크박스 뒤 컬럼들도 같은 기준으로 머지 영역을 갖게 되며, 체크박스만 다른 기준으로 머지하는 것은 어렵습니다. 대안으로 `msAll`로 같은 값을 모두 머지하는 방법이 있습니다.
- 체크박스 컬럼이 머지된 경우 체크/해제는 기본 동작으로 처리되므로 `OnClick`에서 머지 영역에 동일하게 체크/해제하는 로직은 뺄 수 있을 것으로 보입니다. 같은 데이터를 머지하려면 `msPrevColumnMerge`를 사용하고 맨 앞 컬럼에 머지 기준이 될 데이터를 넣는 것이 좋습니다.

**키워드**: Hidden, ColMerge:1, msPrevColumnMerge, msAll, OnClick, 체크박스 머지

## 머지 표시·행 높이·모양

### [MRG-0116] 머지된 시트에서 행 높이가 일정하지 않거나 늘어나는 현상(크롬, msAll 첫 행)의 수정 버전

**질문**

### [MRG-0137] 병합 영역이 시트 높이보다 길면 가운데 값이 보이지 않을 때 VAlign, Page, ToolTip 설정

**질문**

- 머지 영역이 커지면 병합된 셀의 값이 안 보이거나 스크롤 시 값이 빠르게 움직입니다. 고정되게 할 수 있나요?
- 병합 영역이 길 때 ActiveX에서는 내용이 가운데에 보였는데 IBSheet7에서는 보이지 않습니다.
- 병합한 컬럼의 셀이 시트 높이를 넘어가면 데이터가 보이지 않습니다. 이를 해결할 기능이 있나요?

**답변**

머지된 셀은 가상의 셀이 아니라 Table>TR>TD의 `RowSpan`으로 설정된 값이라 스크롤에 맞춰 값이 자동으로 움직이게 할 수 없습니다. 병합된 값은 기본값 `VAlign:Middle`에 따라 머지 영역 중간에 표시되며, 머지 영역이 커져 시트 높이를 넘으면 특정 구간에서는 값이 보이지 않거나 정렬이 맞지 않게 보이고 스크롤 이동 시 값이 들어 있는 구간의 DOM이 빠르게 이동합니다. IBSheet7에서는 ActiveX처럼 보이게 하는 방법이 없습니다.

- 스크롤을 내려도 값이 노출되길 원한다면 머지값이 하나로 합쳐지는 형태는 불가하며, 가능한 한 시트가 표시되는 영역의 높이 정도로 `Page` 값(기본 20)을 설정해 그 안에서만 병합이 유지되도록 합니다.
- 시트 높이를 넘는 병합 셀의 내용을 보여 주는 기능은 없으며 `InitColumns()`에서 `ToolTip`을 설정해서 사용합니다.

**키워드**: VAlign, RowSpan, Page, ToolTip, 병합 영역, ActiveX, InitColumns

### [MRG-0139] 병합 시트에서 행을 선택하면 선택 색이 머지 영역과 분리되어 보일 때 selectionMode 0(셀 단위 선택)

### [MRG-0152] Page 건수(기본 20) 이후 행이나 LazyMode 조회에서 머지가 풀릴 때 Page 값 조정

### [MRG-0162] 트리 시트에서 머지(셀 병합)를 함께 사용할 수 있나요? 트리와 병합 동시 사용 제약

**질문**

- 트리 구조 시트에서 셀 병합(머지)을 함께 사용할 수 있나요? 트리와 병합을 같이 사용하면 접고 펼치는 이미지가 깨지는 등 정상 동작하지 않습니다.
- 트리 시트에서 셀 머지가 적용되지 않습니다. 머지나 짝수/홀수 행 배경색 같은 기능을 사용할 수 없는 건가요? 이유도 알고 싶습니다.
- 트리 기능을 사용하는 시트에 가로 병합(셀 병합)을 함께 적용하려는데 병합이 되지 않습니다.

**답변**

IBSheet7은 트리 시트에서 머지를 지원하지 않으며, 트리와 병합은 동시에 사용할 수 없습니다. IBSheet7은 트리 노드를 표현할 때 자식을 table 구조로 구성하기 때문에 Merge와 짝수/홀수 배경색 등을 지원하지 않으며, 두 기능은 구조적으로 제약이 있어 함께 사용하면 접고 펼치는 이미지가 깨지는 등 정상 동작하지 않습니다. 트리에서 머지를 적용할 수는 있어도 조회 속도가 매우 느려지므로 사용하면 안 됩니다.

- 트리 메뉴별 병합과 오른쪽 마우스 클릭으로 제어하는 기능 중 병합도 지원되지 않습니다(설계 단계부터 머지 기능을 고려하지 않고 개발됨).
- IBSheet8에는 기능이 있으나 문제가 많고, 레벨이 많은 경우 속도 이슈가 발생할 수 있습니다.

**키워드**: 트리, 머지, 병합, 트리 시트 미지원, 짝수 홀수 배경색, IBSheet8

- 앞 컬럼 머지를 쓰고, 해당 컬럼은 `SetMergeCell()`로 병합할 구간을 별도 설정해 강제 머지하는 방법도 있습니다.

**키워드**: SetMergeSheet, SetMergeCell, OnSearchEnd, 앞 컬럼 머지, 기준 컬럼 머지, 수동 병합

### [MRG-0184] 세로 머지(ColMerge)와 가로 머지(DataRowMerge, RowMerge) 동시 적용 시 우선순위와 ㄱ자 머지

- 세로 머지와 가로 머지(DataRowMerge)를 동시에 적용하고 가로 머지 영역의 구분선도 없애고 싶은데 세로 머지만 적용됩니다. 가능한가요?

**답변**

- `createPivotTable()`은 PivotTable이 최초 생성될 때만 `rowMerge`가 우선되도록 수정되었습니다. 단 컬럼 이동이나 삭제처럼 렌더링이 다시 되는 시점에는 `ColMerge`가 우선되어 `rowMerge`가 풀리는 제약이 있습니다.
