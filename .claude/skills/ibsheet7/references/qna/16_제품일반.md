### [GEN-0001] IBSheet7에 권고·안정화 버전이 있나요? 릴리즈와 패치는 얼마나 자주 나오나요?

**질문**

- IBSheet7에서 따로 정해진 안정화 버전이 있는지, 항상 최신 버전을 사용하는 것이 좋은가요?
- IBSheet7에 권고 버전이 따로 정해져 있나요? 새 버전은 얼마나 자주 릴리즈되나요?
- IBSheet7은 얼마나 자주 릴리즈나 패치가 나오나요? IBUpload나 IBSheet3(ActiveX 기반)도 정기 릴리즈가 있나요?

**답변**

고정된 안정화 버전이나 권고 버전은 따로 없고 항상 최신 버전을 배포하는 것이 원칙입니다. 일반적으로 최신 버전이 이전 버전보다 버그가 수정되고 기능도 개선되었으므로 가장 안정적인 버전으로 보면 됩니다.

- IBSheet7 grid 제품(`ibsheet.js`)은 통상 2주에 한 번 릴리즈하며, 버그의 심각성을 고려해 급한 사항은 긴급 패치로 배포합니다.
- IBUpload는 통상적인 릴리즈 없이 요청에 의한 패치가 있을 때만 릴리즈합니다.
- IBSheet3(ActiveX 기반)는 신규 기능 패치가 사실상 중단되어 정기적인 릴리즈가 없습니다.

**키워드**: 안정화 버전, 권고 버전, 릴리즈 주기, 긴급 패치, 2주, 최신 버전

**질문**

- IBSheet7의 최신 버전이 몇 버전인지 알고 싶습니다. ibsheet.js 버전과 엑셀모듈(서버모듈 jar) 버전을 각각 알려 주세요.

**답변**

2026년 8월 시점의 IBSheet7 최신 버전은 ibsheet.js 7.0.13.297(2026.07.06 릴리즈)이며, 엑셀모듈(서버모듈)은 ibsheet7-2.1.47.jar입니다. 이후 릴리즈로 더 높은 버전이 나올 수 있습니다.

**적용 버전**: 7.0.13.297

**키워드**: 7.0.13.297, ibsheet7-2.1.47.jar, 최신 버전, 서버모듈 버전

### [GEN-0003] IBSheet7 서버모듈 버전(2.0.xx)의 숫자 의미는? 높은 버전 jar는 낮은 버전 패치를 포함하나요?

**질문**

- IBSheet7 서버모듈 버전(2.0.xx)의 숫자는 무엇을 뜻하나요? 높은 버전의 jar는 낮은 버전 jar의 패치를 포함하나요?

**답변**

서버모듈 버전 2.0.xx에서 2는 메이저 버전, xx는 마이너 버전입니다. 모듈이 수정·추가될 때마다 마이너 버전이 1씩 증가하므로 더 높은 마이너 버전(예: 2.0.92)에는 낮은 버전(예: 2.0.82)의 패치가 포함되어 있습니다.

**키워드**: 서버모듈 버전, 2.0.xx, 마이너 버전, 2.0.92, 2.0.82, 패치 포함

**적용 버전**: 7.0.8.0 이상

**키워드**: AutoFitColWidth, FitColWidth, 7.0.8.0, 지원 버전

### [GEN-0008] 현재 사용 중인 IBSheet7 버전은 어떻게 확인하나요? ibsheet.js 상단 주석과 Version() 함수

**질문**

- 현재 사용 중인 IBSheet7의 제품 버전을 확인하려면 어떻게 해야 하나요?
- 브라우저 콘솔에서 현재 사용 중인 IBSheet7 시트의 버전을 확인하려면 어떻게 하면 되나요?
- 사용 중인 ibsheet.js, ibmulticombo.js, ibchart.js 같은 제품 js 파일의 버전은 어떻게 확인하나요?
- 화면에 적용된 IBSheet 제품이 IBSheet7이 맞는지, 구체적인 버전 번호가 몇인지 어느 파일에서 확인할 수 있나요?

**답변**

두 가지 방법으로 확인합니다.

- 파일에서 확인: `ibsheet.js` 파일을 메모장 같은 편집 도구로 열면 맨 위 주석에 제품명과 버전이 적혀 있습니다(예: `ibsheet7`, `v7.0.13.XXX`로 표시되면 IBSheet7 제품). `ibmulticombo.js`, `ibchart.js` 같은 다른 제품 js 파일도 상단에 버전이 기입되어 있습니다.
- 콘솔에서 확인: 시트를 사용하는 화면에서 개발자도구(F12) 콘솔에 시트 객체의 `Version()` 함수를 호출합니다. 예: `mySheet.Version()`, `시트id.Version()`, `alert(객체ID.Version())`. 시트 정보가 `Grids` 배열에 담겨 있으므로 `Grids[0].Version()`으로도 확인할 수 있습니다. 오래된 버전은 이 방법으로 확인할 수 있습니다.
버전이 제대로 나오지 않으면 개발자도구 왼쪽 상단의 네모 아이콘 또는 Ctrl + Shift + C로 시트를 선택한 뒤 다시 확인합니다.

**키워드**: Version(), Grids[0].Version(), ibsheet.js 상단 주석, 버전 확인, 개발자도구 콘솔, IBSheet7

## 매뉴얼·도움말·제품 식별

### [GEN-0012] 소스의 함수가 IBSheet 제공 함수인지 프로젝트에서 만든 래퍼 함수인지 어떻게 구분하나요?

**질문**

- 소스에 정의된 함수가 IBSheet가 제공하는 함수인지 프로젝트에서 만든 래퍼(프레임워크) 함수인지 구분하는 기준이 있나요?

**답변**

IBSheet 제공 함수는 모두 PascalCase(첫 글자 대문자) 이름을 씁니다. 따라서 `setCellFormat` 같은 camelCase 함수는 사이트에서 만든 래퍼 함수이고, 그 안에서 `this.IBSObject.XXXX()` 형태로 호출되는 `InitCellProperty`, `GetCellProperty` 등이 IBSheet 공식 함수입니다. `ibsheet.js`는 제품 공식 파일(난독화)이며 사이트에서 작성한 `ibsheet7.js` 같은 파일은 제품 제공 파일이 아닙니다.

**키워드**: PascalCase, camelCase, 래퍼 함수, IBSObject, InitCellProperty, GetCellProperty

### [GEN-0014] 사용 중인 시트가 IBSheet7인지 ActiveX인지, 또는 IBSheet8인지 어떻게 구분하나요?

**질문**

- 사용 중인 시스템에서 쓰는 시트가 IBSheet7인지 ActiveX인지 알 수 없습니다. 브라우저 동작이나 소스 파일로 어떻게 구분할 수 있나요?
- 현재 프로젝트에서 쓰는 시트가 IBSheet7인지 IBSheet8인지 어떻게 구분하나요?

**답변**

ActiveX와 IBSheet7 구분:

- 시트 위에서 마우스 오른쪽 클릭 시 웹페이지의 컨텍스트 메뉴가 뜨면 IBSheet7로 구현된 화면이고, 아무 반응이 없으면 ActiveX일 수 있습니다.
- Edge/IE 모드로 접속해야 실행되면 ActiveX이고 Edge 일반 모드에서 실행되면 IBSheet7입니다.
- 소스에서 `IBsheet.CAB` 파일이 있으면 ActiveX, `ibsheet.js` 파일이 있으면 IBSheet7입니다.
IBSheet7과 IBSheet8 구분:

- `ibsheet.js`를 텍스트 편집기로 열어 상단 주석의 제품명을 봅니다.
- 관련 파일에 `ibsheetinfo.js`가 있으면 IBSheet7, `ibsheet-common.js`가 있으면 IBSheet8입니다.
- 시트ID.함수() 호출 시 함수명이 대문자로 시작하면 IBSheet7(예: `sheet.GetCellValue`), 소문자로 시작하면 IBSheet8(예: `sheet.getValue`)입니다.
- 브라우저 콘솔에서 `Grids`를 입력해 값이 나오면 IBSheet7, `IBSheet`를 입력해 값이 나오면 IBSheet8입니다.

**키워드**: IBsheet.CAB, ibsheetinfo.js, ibsheet-common.js, Grids, 제품 구분, IBSheet8

### [GEN-0015] 어떤 객체가 IBSheet7 시트 객체인지 판별하는 방법이 있나요?

### [GEN-0061] log4j 취약점이 IBSheet7 서버모듈에 영향을 주나요? 서버모듈 2.0의 log4j를 삭제해도 되나요?

**키워드**: log4j, log4j-1.2.13, ibsheet7 2.x.jar, POI, 서버모듈, 2.15.0, 취약점

### [GEN-0063] CSP(Content-Security-Policy)를 적용하면 시트가 그려지지 않거나 EvalError가 발생합니다. 지원되나요?

**질문**

- 보안을 위해 CSP 설정을 적용하면 Uncaught EvalError가 발생합니다. eval을 쓰지 않고 사용할 수 있는 방법이 있나요?
- meta 태그로 Content-Security-Policy를 style-src 'self'만 지정했는데도 IBSheet가 화면에 그려지지 않습니다. CSP 설정을 지원하나요?
- 웹 취약점 점검에서 CSP 헤더의 script-src, style-src 지적이 나와 헤더를 조치하면 IBSheet 스크립트 로드가 안 되어 그리드가 동작하지 않습니다.
- CSP 보안 설정을 적용했더니 크롬이나 Edge에서 시트가 그려지지 않고 IE에서는 정상입니다. nonce 방식 등으로 unsafe-eval 없이 쓸 수 있나요?

**답변**

IBSheet7은 CSP(Content Security Policy) 보안 설정을 지원하지 않거나 완전히 지원하기 어려워, 적용하면 크롬이나 Edge에서 시트가 그려지지 않거나 `EvalError`가 발생할 수 있습니다.

- `ibsheet.js` 코어 파일은 파일을 난독화한 뒤 난독화된 내용을 실행하기 위해 내부적으로 `eval` 함수를 반드시 사용하며 이를 대체할 방식이 없습니다. 컬럼 간 계산식과 필터/검색 조건도 런타임에 javascript 함수로 컴파일되므로 `unsafe-eval` 제한을 충족하지 못합니다.
- 셀 배경색·글자색은 인라인 스타일로, 셀·행 이벤트(onmousemove, onclick 등)는 인라인 이벤트 핸들러로 처리됩니다.
- script-src, style-src를 제한하는 CSP 헤더나 meta 설정을 적용하면 스크립트 로드가 막혀 그리드가 동작하지 않을 수 있습니다. 따라서 제품은 CSP 적용 대상에서 제외하는 방식으로 사용하거나, CSP에서 CSS는 `style-src 'unsafe-inline'`, JavaScript는 `script-src 'unsafe-inline' 'unsafe-eval'`을 허용해야 합니다.
- CSP는 서버 설정뿐 아니라 방화벽, Proxy Server 같은 통신 장비에서도 적용될 수 있으므로 해당 장비 설정도 확인합니다.

**키워드**: CSP, Content-Security-Policy, EvalError, unsafe-eval, unsafe-inline, script-src, style-src

### [GEN-0064] 웹 취약점 점검에서 ibsheet.js의 eval() 사용이 지적됩니다. 어떻게 대응하나요?

**질문**

- 보안 점검에서 ibsheet.js가 eval() 함수를 사용한다는 취약점으로 지적되었습니다. eval을 쓰는 이유와 안전성은 어떻게 설명하나요?
- 웹 취약점 점검에서 ibsheet.js의 eval() 사용이 지적됩니다. new Function('return ' + result) 방식으로 치환할 수 있나요?
- 웹 취약점 점검에서 시트 쪽에 eval 함수를 쓴다고 지적되었는데 제품 안에 eval 함수를 쓰는 부분이 있나요?

**답변**

`ibsheet.js`는 소스 보호를 위해 암호화(난독화)되어 있고, 난독화된 문자열을 실행 시점에 `eval()`로 복원해 구동하므로 `eval()` 사용은 제품에 필수적입니다. 난독화 문자열은 사전 인증된 소스에서 사전에 정의된 고유 규칙으로 생성되어 외부에서 제공되는 임의의 코드를 실행하지 않고, 내부 함수·변수명도 난독화되어 코드 분석과 조작이 극도로 어렵습니다.

- eval 사용은 난독처리 시 필요한 내용이어서 `var test = ( new Function( 'return ' + result ) )();` 형태로 바꾸는 처리는 어렵습니다.

### [GEN-0085] IBSheet7을 IBSheet8로 교체·업그레이드하면 기존 소스를 그대로 쓸 수 있나요?

**질문**

- IBSheet7을 쓰던 화면을 IBSheet8 제품으로 교체하면 기존 소스가 그대로 동작하나요? js 파일만 바꾸면 되나요?
- IBSheet7 화면을 IBSheet8로 바꾸려면 제품 파일만 교체하면 되나요? 두 제품의 코드 작성 방식 차이와 필요한 작업이 궁금합니다.
- IBSheet7을 IBSheet8로 업그레이드할 수 있나요? 두 제품은 어떤 관계인가요?
- IBSheet8로 버전업할 예정인데 기존 소스를 그대로 쓸 수 있는지, 별도 작업이 필요한지 궁금합니다.

**답변**

IBSheet7과 IBSheet8은 별도의 제품이라 소스가 호환되지 않으며 업그레이드가 아니라 신규(추가) 개발로 보아야 합니다. IBSheet8은 현재 주력으로 판매되는 제품입니다.

- js 파일 교체만으로는 동작하지 않습니다. 제공하는 함수(API), 속성, 객체 생성 부분 등이 다르고 IBSheet7 관련 API는 사용할 수 없습니다.
- 화면에 보이는 모습은 비슷하고 IBSheet8은 IBSheet7의 기능을 거의 다 갖추고 있으나 개발 방법이 다르므로, 기존 페이지 코드를 IBSheet8에 맞게 변환하는 작업(화면 변환 공수)이 필요하며 완전 재개발 수준으로 고려해야 합니다.

**키워드**: IBSheet8, IBSheet7, 마이그레이션, 업그레이드, API 비호환, 재개발

### [GEN-0086] IBSheet7 화면 코드를 IBSheet8 코드로 변환해 주는 마이그레이션 도구가 있나요?

**질문**

- IBSheet7로 만든 화면의 스크립트 코드와 속성을 수정 없이 IBSheet8에서 그대로 사용할 수 있나요? 마이그레이션 도구나 주의사항이 있나요?

**답변**

IBSheet7로 구축된 페이지는 별도 코드 수정 없이 IBSheet8에서 그대로 로드해 사용할 수 없습니다. 코드 변환을 지원하는 AI 기반 코드 마이그레이션 툴킷이 있으며, 상용 프로그램 설치 없이 Python과 Node.js 환경만 갖추면 기존 페이지를 IBSheet8 코드로 자동 변환합니다(약 70~80% 자동 변환, 20~30% AI 변환 및 검증). 구축 시 공통 wrapping 작업이 별도로 적용된 경우에는 변환 도구의 일부 조정이 필요하고, 시스템별 특성에 맞춘 툴킷 커스터마이징도 가능하며 범위에 따라 별도 비용이 발생할 수 있습니다.

**키워드**: 코드 마이그레이션 툴킷, IBSheet8, Python, Node.js, 자동 변환, wrapping

### [GEN-0087] IBSheet7과 IBSheet8은 기반 기술과 API가 어떻게 다른가요? 신규 개발 시 어느 제품을 검토하나요?

**질문**

- IBSheet7과 IBSheet8은 기반 기술과 API 측면에서 무엇이 다른가요? 신규 개발이나 전체 재개발 시 어느 제품을 검토해야 하나요?

**답변**

IBSheet7과 IBSheet8은 모두 html로 이루어진 NonActiveX 제품이며 기반 기술은 동일합니다. IBSheet7은 IBSheet3 사용자의 요구를 반영해 IBSheet3와 유사한 API 명을 갖도록 만들어졌고 처음 만들어질 때 SPA 같은 환경을 고려하지 못했습니다. IBSheet8은 SPA 중심의 최근 추세에 맞춰 만들어졌으며 IBSheet7의 API를 참조하지 않고 새로운 API 명을 갖습니다. 신규 개발이나 전체 재개발인 경우 IBSheet8 도입을 검토할 수 있습니다.

**키워드**: IBSheet7, IBSheet8, NonActiveX, SPA, API 명, IBSheet3

**키워드**: 대용량 조회, IBSheet8, DOM 수, 재개발, 속도 이슈

### [GEN-0091] ActiveX 기반 IBSheet Pro·IBSheet3를 IBSheet7로 교체하면 그대로 동작하나요? Chrome·Edge에서는?

**질문**

- ActiveX 기반 IBSheet Pro나 IBSheet3와 IBSheet7은 무엇이 다른가요? Chrome, Edge에서 쓰려면 어떻게 해야 하나요?
- ActiveX를 사용하는 시스템에서 제품만 IBSheet7로 바꾸면 그대로 동작하나요?
- 현재 ActiveX 버전을 사용하고 있는데 HTML 버전인 IBSheet7으로 전환할 수 있나요? 지원되는 브라우저와 도구가 궁금합니다.

**답변**

IBSheet Pro와 IBSheet3는 ActiveX 기반이라 IE에 종속적이어서 크로스 브라우징을 지원하지 않고 Edge나 Chrome에서는 설치와 실행이 되지 않습니다(제품 파일도 ocx가 들어간 Cab 파일). IBSheet7은 javascript 기반 js 파일 형태의 NonActiveX 제품으로 모바일을 포함한 멀티 플랫폼·멀티 브라우저를 지원하며 기존 IBSheetPro API를 약 70% 지원합니다. 따라서 Chrome이나 Edge에서 쓰려면 IBSheet7 같은 NonActiveX 제품으로 교체해야 합니다.

- 기반기술과 사용 API가 달라 제품만 바꾼다고 동작하지 않으며, 버전 업그레이드 형식으로 바로 테스트할 수 없고 소스코드를 IBSheet7용으로 변경해야 합니다.
- 마이그레이션 툴이 지원되어 전환이 어렵지 않으며 IE7부터 지원할 수 있습니다(HTML5 기반 기술보다는 하위 브라우저 지원).

**키워드**: ActiveX, IBSheet7, NonActiveX, 마이그레이션, Chrome, Edge, IE7

### [GEN-0093] ActiveX 시트 코드를 IBSheet7 코드로 바꾸는 마이그레이션 툴은 어디까지 변환해 주나요?

**질문**

- ActiveX 기반 IBSheet3나 Pro의 초기화·이벤트 코드를 IBSheet7 코드로 옮기려는데 자동 변환 기능이나 도구가 있나요?
- IBSheet3(ActiveX) 제품을 IBSheet7로 변환 툴로 마이그레이션하면 어디까지 자동으로 변환되나요?
- ActiveX에서 IBSheet7으로 마이그레이션할 때 API는 어디까지 매핑되고 변환 툴로 자동 변환되는 범위는 어디까지인가요?
- 마이그레이션 툴에서 OnPopupclick 이벤트 구문이 변환되지 않습니다. 원인이 무엇인가요?

**답변**

시트 초기화 부분과 이벤트 부분의 코드를 IBSheet7 API로 변환해 주는 코드 변환툴이 제공됩니다. javascript로 만들어진 툴에 기존 초기화 코드를 넣고 변환 버튼을 누르면 IBSheet7의 매핑 코드로 변환되며 이를 원래 페이지에 붙여넣는 방식이라 완전 자동화는 아닙니다. 툴은 수정·커스터마이징해서 쓸 수 있고 API 매핑 리스트는 엑셀 문서로 제공됩니다.

- 변환률은 약 70%이며 IBSheet7은 IBSheet3의 API명이나 이벤트 시점을 최대한 맞췄지만 VB로 만든 ActiveX와 원천 기술이 달라 모든 기능이 구현되지는 않습니다.
- 결과에 '확인필요, 지원불가' 같은 코멘트가 붙은 부분은 개발자가 확인해야 하고, 시트 API가 포함된 일반 JavaScript에 매핑되는 API가 없으면 이전 코드가 그대로 출력되므로 변환 결과를 검증합니다.
- 자체 프레임워크로 감싸 쓰는 경우 변환률이 더 떨어지며, 스타일 초기화 구간은 주석 처리 후 변환하고 나중에 추가 처리하는 것이 좋습니다.
- 이벤트명의 대소문자가 정확하지 않으면 변환되지 않습니다. `OnPopupclick`이 아니라 `OnPopupClick(Row,Col)`처럼 정확히 작성합니다.
- 업무 로직에 따른 구현은 모두 변환되지 않으므로 화면별 기능 분석과 업무 테스트가 반드시 필요합니다.

**키워드**: 마이그레이션 툴, 코드 변환툴, API 매핑, OnPopupClick, 변환률 70%, ActiveX, IBSheet3
