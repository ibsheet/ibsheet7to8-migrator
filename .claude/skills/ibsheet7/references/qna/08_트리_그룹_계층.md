### [TREE-0001] 트리용 JSON 데이터 형식과 자식이 없는 노드에 [+] 아이콘을 표시하는 HaveChild

**질문**

- 트리 구조로 표시하려고 JSON 데이터를 로드했는데 계층 구조가 제대로 만들어지지 않습니다. 트리용 JSON 데이터는 어떤 형태로 구성해야 하나요?
- JSON 데이터로 트리를 구현했는데 자식이 없는 노드에는 [+] 아이콘이 나오지 않습니다. [+] 아이콘이 표시되게 하려면 JSON 데이터를 어떻게 구성해야 하나요?

**답변**

트리용 JSON은 `{data: [ [ ... ] ]}` 안에 행 객체를 나열하고, 하위 행은 부모 행 객체의 `Items:[ ... ]` 배열에 중첩해 계층을 표현합니다. 예제에는 `Expand:1`을 지정한 행과, `Items` 없이 `HAVECHILD:1`을 지정한 행도 포함되어 있습니다. 자식이 없는 노드에도 [+] 아이콘을 표시하려면 JSON 데이터의 해당 행에 `HaveChild:1` 속성을 줍니다.

**키워드**: Items, HaveChild, HAVECHILD, Expand, 트리 JSON, [+] 아이콘

### [TREE-0002] 트리 자식 데이터가 10,000건씩 묶여 보일 때 묶인 자식 행의 실제 데이터를 확인하는 방법

**질문**

- 트리 자식 데이터가 10,000건씩 묶여 보이는데, 묶인 자식 행들의 실제 데이터를 확인하려면 어떻게 하나요?

**답변**

`GetChildRows(2)`처럼 특정 행(예: 2번째 행)의 모든 자식 행 인덱스를 가져옵니다. 행 인덱스는 `|` 구분자로 이어진 문자열 형태로 한꺼번에 반환됩니다. 이 인덱스로 `GetRangeValue()` 같은 함수에서 범위 영역을 지정해 값을 가져와 확인하면 됩니다.

**키워드**: GetChildRows, GetRangeValue, 자식 행 인덱스, 10,000건, 트리 자식 데이터

### [TREE-0003] 행이나 텍스트를 클릭해도 트리가 펼쳐지고 접히게 하려면? (GetRowExpanded, IsHaveChild, SetRowExpanded)

**질문**

- 트리 시트에서 +/- 아이콘을 눌러야만 펼쳐지는데, 행이나 텍스트를 클릭했을 때도 하위 노드가 펼쳐지고 접히도록 하려면 어떻게 구현해야 하나요?
- 트리에서 접힘/펼침 마크뿐 아니라 해당 컬럼의 텍스트를 클릭할 때도 노드가 접히고 펼쳐지게 하려면 어떻게 하나요?
- 트리 시트에서 행을 선택했을 때 그 행이 자식 노드를 가지고 있는지, 현재 펼쳐진 상태인지 접힌 상태인지 확인하려면 어떤 함수를 사용해야 하나요?

**답변**

행 클릭 시 펼침·접힘은 별도 로직으로 구현하며, `OnClick` 이벤트에서 `SetRowExpanded`를 사용해 행을 펼치고 닫습니다. 클릭한 행에 자식이 있는지는 `IsHaveChild`로, 현재 펼쳐진 상태인지는 `GetRowExpanded`로 확인합니다. 예: `if(mySheet.IsHaveChild(r)){mySheet.SetRowExpanded(r , !(mySheet.GetRowExpanded(r)));}`
트리 행의 펼침/접힘 처리는 `setRowExpanded()`와 `allowExpand()` 함수를 이용해 처리하면 된다는 안내도 있습니다.

**키워드**: OnClick, SetRowExpanded, GetRowExpanded, IsHaveChild, allowExpand, 트리 클릭 펼침

### [TREE-0004] 트리의 특정 행·레벨을 코드로 접거나 펼치는 방법 (RowExpanded, ShowTreeLevel)

**질문**

- 트리에서 2레벨 행 기준으로 행을 추가하면 3레벨로 추가되는데 접혀 있습니다. 이 행을 펼치려면 어떻게 하나요?
- 트리 구조에서 특정 행(레벨)을 코드로 접거나 펼치고 싶습니다. 어떤 함수를 사용하면 되나요?
- 왼쪽 목록의 행을 클릭했을 때 오른쪽 트리 시트의 특정 레벨이 펼쳐지게 하고 싶습니다.

**답변**

특정 행의 접기/펼침은 `RowExpanded` 함수로 처리하며, 추가된 하위 행이 접혀 있을 때도 `RowExpanded`로 펼칠 수 있습니다. 특정 레벨의 접기/펼침은 `ShowTreeLevel`로 설정합니다. 다른 목록에서 행을 선택했을 때 트리 시트의 해당 행을 펼치려면 `selectedRow`와 `RowExpanded`를 이용합니다.

**키워드**: RowExpanded, ShowTreeLevel, selectedRow, 특정 행 펼치기, 트리 접기

### [TREE-0006] 트리 시트 밖의 조건으로 해당 노드를 찾아 펼치고 선택하는 방법 (FindText, SetRowExpanded)

**질문**

- 트리 구조 시트 바깥의 콤보로 고른 두 단계 조건에 해당하는 노드를 찾아 펼치고 선택하려면 어떻게 해야 하나요?

**답변**

`FindText`로 첫 조건의 행을 찾아 `SetRowExpanded(행,1)`로 펼친 뒤, 앞서 찾은 행을 함께 넘겨 `FindText`로 두 번째 조건의 행을 찾고 다시 펼칩니다. 마지막으로 찾은 행을 `SetSelectRow`로 선택합니다.

**키워드**: FindText, SetRowExpanded, SetSelectRow, 노드 검색, 트리 선택

### [TREE-0007] 트리 데이터의 레벨이 어긋나거나 중간 레벨이 빠지면 트리가 깨집니다

**질문**

- 트리 데이터에 0레벨, 1레벨 다음에 3레벨처럼 중간 레벨이 빠져 있으면 트리가 꼬이거나 일부 행이 다른 레벨로 표시됩니다. 어떻게 해결하나요?
- 일부 2레벨 행이 1레벨 아래로 들어가지 못하고 계층이 어긋나게 표시됩니다. 원인이 무엇인가요?

**답변**

트리는 데이터가 순차적으로 렌더링되며 트리 이미지가 그려지므로, 데이터의 레벨 값이 잘못되면 이후 행들의 계층이 꼬입니다. 부모 레벨 없이 자식 레벨을 표시할 수 없어 중간 레벨이 빠져도 트리가 깨집니다.

- 레벨이 0, 1, 2, 3처럼 건너뛰지 않고 이어지도록 데이터를 수정합니다(예: 누락된 2레벨 데이터를 만들어 줍니다).
- 바로 위 행이 3레벨인데 5레벨 행이 있으면 5레벨로 점프하면서 뒤의 행이 틀어지므로, 이런 행은 4레벨로 수정하는 등 레벨 값을 바로잡습니다.
- 처음 조회할 때는 0, 1레벨만 가져오고 트리를 클릭할 때(`OnTreeChild`) 하위 노드를 조회하는 방식으로 구현할 수도 있습니다.

**키워드**: 트리 레벨, Level, OnTreeChild, 트리 깨짐, 계층 어긋남

### [TREE-0008] 하위 데이터를 펼칠 때 조회하는 동적 확장 트리는 어떻게 구현하나요?

**질문**

- 처음에는 최상위 레벨(0레벨) 데이터만 조회하고 +버튼을 누를 때마다 서버와 통신해서 하위 데이터를 가져오는 확장형 동적 트리를 구현하려면 어떻게 하나요?
- 트리에서 하위 데이터가 없는 행에도 펼침/접힘(+, -) 버튼이 표시되게 하려면 어떻게 하나요?
- 4레벨 트리를 3레벨까지만 먼저 조회하고, 4레벨 데이터는 노드를 펼칠 때 조회해 붙이려면 어떻게 하나요?

**답변**

조회 데이터에서 자식이 있는 행에 `HaveChild:1` 속성을 함께 담으면(예: `{a:"aa", b:"bb", HaveChild:1}`) 하위 데이터가 아직 없어도 해당 행에 +/- 버튼이 표시됩니다. `SetRowHaveChildValue` 메소드로도 같은 효과를 낼 수 있습니다.
노드를 펼칠 때 `OnTreeChild` 이벤트가 발생하므로, 이 이벤트 안에서 `DoSearchChild()`(또는 `LoadSearchChild`)로 하위 데이터를 조회해 해당 행 아래에 표시합니다. 하위 데이터 조회는 일반 조회와 같으며 Level 값만 올바르게 가져오면 됩니다. 어느 레벨까지 먼저 가져올지는 조회 조건으로 정합니다.
가져온 데이터가 접히지 않고 모두 펼쳐져 표시된다면 가져오는 데이터 구조가 잘못되었을 수 있습니다. 샘플 갤러리의 동적 확장 트리 탭을 참고합니다.

**키워드**: HaveChild, OnTreeChild, DoSearchChild, LoadSearchChild, SetRowHaveChildValue, 동적 트리, 확장형 트리

### [TREE-0009] 트리에서 SearchMode:3을 쓰면 레벨이 같게 그려지고 자식 행이 -1로 반환됩니다

**질문**

- 트리에서 DoSearchChild로 + 버튼을 눌러 하위 데이터를 조회하면 클릭한 행의 자식이 아니라 같은 레벨로 들어갑니다. 원인이 무엇인가요?
- 트리 시트에서 조회하면 레벨이 다른 데이터가 모두 같은 레벨로 그려지고, 온체인지·온클릭 함수에서 자식 노드의 행이 -1로 반환됩니다. 원인이 무엇인가요?

**답변**

`SearchMode`를 3으로 설정한 시트는 트리를 지원하지 않습니다. 트리 시트에서 `SearchMode:3`을 사용하면 레벨이 다른 데이터가 모두 같은 레벨로 그려지거나, `DoSearchChild` 조회 결과가 자식이 아닌 같은 레벨로 들어가거나, 최상위가 아닌 자식 노드의 행이 -1로 반환될 수 있습니다. 이런 증상이 있으면 `SearchMode`가 3으로 되어 있는지 확인하고 트리에서는 이 모드를 사용하지 마세요.

**키워드**: SearchMode, SearchMode:3, DoSearchChild, 트리, 레벨

### [TREE-0010] 응답 데이터가 d 변수에 담길 때 DoSearchChild로 트리 하위 데이터가 그려지지 않습니다

**질문**

- DoSearchChild로 데이터를 조회해 바인딩했는데 시트에 아무 반응이 없고 데이터가 그려지지 않습니다. 응답 데이터가 d 변수에 담겨 오는 경우 어떻게 처리하나요?

**답변**

응답 데이터를 `d` 변수에 넣어 가져오는 구조에서는 `DoSearchChild`가 데이터를 제대로 바인딩하지 못해 그려지지 않습니다. `DoSearchChild` 대신 `GetSearchData()`로 데이터를 받아 `LoadSearchChildData(JSON.parse(sdata).d)` 형식으로 넣으면 정상적으로 그려집니다.

**키워드**: DoSearchChild, GetSearchData, LoadSearchChildData, d 변수, 트리

### [TREE-0011] 트리 시트에서 SelectCell/SelectRow로 포커스를 옮겨도 스크롤바가 상단에 고정됩니다

**질문**

**답변**

**키워드**: SelectCell, SelectRow, TopRow, 스크롤바, 트리

### [TREE-0013] LevelSaveName 속성은 무엇이며 저장 시 트리 레벨을 서버로 보내려면 어떻게 하나요?

**질문**

- LevelSaveName 속성은 어떤 용도로 사용하나요?
- ActiveX의 InitTreeInfo 두 번째 인자처럼 저장할 때 트리 레벨 값을 서버로 보내려면 IBSheet7에서는 무엇을 설정하나요?
- 쿼리의 레벨 컬럼명에 alias를 줬을 때 컬럼 옵션 LevelSaveName으로 지정해도 트리가 만들어지지 않습니다.
- 트리 시트에서 TreeCol과 LevelSaveName 속성은 각각 어떤 역할을 하나요?

**답변**

`LevelSaveName`은 Level 정보를 서버쪽으로 넘길 때(저장 시) 사용할 SaveName을 지정하는 속성입니다. ActiveX의 `InitTreeInfo` 두 번째 인자(저장 시 Level 값을 보내는 인자)와 같은 처리를 IBSheet7에서는 `InitColumns` 컬럼 정보의 `LevelSaveName`으로 합니다. 예: `TreeCol:1`로 지정한 트리 컬럼에 `LevelSaveName`을 지정합니다.

- `TreeCol`은 트리 속성으로 표현할 컬럼을 지정하는 속성입니다.

### [TREE-0023] JSON 트리에서 Level 값을 넣었는데 트리가 안 보이거나 0레벨로만 그려집니다 (UseJsonTreeLevel)

- 각 행에 `Level:0`, `Level:1`, `Level:2`처럼 깊이를 넣습니다. 키 이름은 대소문자를 지켜 `Level` 또는 `level`만 허용되며 `LEVEL`은 안 됩니다.
- `UseJsonTreeLevel:1`을 설정한 경우 `level` 속성으로 레벨 값을 가져와야 하며, 0으로 설정한 경우 `LevelSaveName`은 조회/저장 시 level 대신 사용할 변수값이라는 설명도 있습니다.

### [TREE-0028] JSON 트리에서 HaveChild 속성은 어떻게 쓰며, 폴딩 이미지가 안 나오는 이유는?

- 동적 트리를 사용하려는데 XML 데이터 구조로 된 샘플밖에 없습니다. JSON 구조로 동적 트리를 구성하려면 havechild 속성 등을 어떻게 표현하나요?
- 샘플은 XML 구조로 조회하는데 JSON 구조로는 트리 조회가 불가능한가요? XML에서 쓰던 HAVECHILD 속성을 JSON에서도 사용할 수 있는지 궁금합니다.

### [TREE-0039] 트리를 조회할 때 특정 레벨·특정 행을 접힌(또는 펼친) 상태로 표시하려면 어떻게 하나요?

**질문**

- 트리 시트에서 자식이 있는 행의 데이터를 접은 상태로 조회하려면 어떻게 설정해야 하나요?
- 트리 시트를 조회할 때 전체 펼침이나 전체 접힘이 아니라 특정 자식 행만 접거나 펼친 상태로 표시하려면 어떻게 하나요?
- 초기 조회 시점에 트리를 접힌 상태로 표시하려면 어떻게 하나요? 모든 행을 접는 로직이 속도에 영향을 주나요?

**답변**

**키워드**: Expand, OnLoadData, SetRowExpanded, ShowTreeLevel, OnSearchEnd, 트리 접힘 조회

### [TREE-0041] ShowTreeLevel(0,1)을 호출했는데 트리가 접히지 않을 때 호출 시점 (OnSearchEnd)

**질문**

### [TREE-0049] 트리 컬럼 앞에 체크박스를 표시하려면 TreeCheck를 어디에서 설정하나요?

**질문**

- 트리시트에서 트리 컬럼에 체크박스를 표시할 수 있나요? 어떤 속성을 설정하나요?
- 트리 형태로 구성한 시트에서 트리 컬럼 맨 앞에 체크박스가 나타나지 않습니다. 트리 앞에 체크박스를 표시하려면 어떤 속성을 어디에서 설정하나요?
- 트리 시트에서 TreeCheck 체크박스가 나오지 않습니다. TreeCheck 기능을 사용하는 방법을 확인할 수 있는 샘플은 어디에 있나요?

**답변**

`TreeCheck` 속성을 `InitColumns`에서 설정하면 트리 컬럼 앞에 체크박스가 표시됩니다. 연관 속성으로 `CheckSaveName`이 있습니다. 예: `TreeCol:1,SaveName:'test2',LevelSaveName:'test6',CheckSaveName:'test5',TreeCheck:1`

- 이 속성은 `InitColumns`에서만 설정할 수 있고, `SetColProperty`로 나중에 설정하는 방식은 어렵습니다.
- 공통 초기화 코드에서 일괄 적용하려면 `InitColumns`를 호출하는 시점에 `TreeCol`이 있는지 확인해 `TreeCheck`를 넣어줄 수 있지만, 그러면 모든 트리 시트에 체크박스가 나타납니다.
- 샘플은 트리(Tree) 기능 메뉴의 트리일반에서 '트리체크 기능 사용'을 체크하면 예제가 나타납니다. 다만 이 기능은 유지보수가 되어 있지 않아 이후 지원이 어려울 수 있습니다.

**키워드**: TreeCheck, InitColumns, CheckSaveName, SetColProperty, TreeCol, 트리 체크박스

### [TREE-0052] TreeCheck 컬럼을 조회할 때 체크된 상태로 표시하려면 데이터를 어떻게 구성하나요?

**질문**

- 트리 시트의 TreeCheck 컬럼에서 조회 시 체크 상태를 표시하고 체크값을 저장하려면 데이터를 어떤 구조로 구성하고 어떤 속성을 설정해야 하나요?
- 트리 컬럼에 TreeCheck를 쓰고 CheckSaveName 값(Y/N)으로 체크 여부를 가져오도록 TrueValue를 Y로 설정했는데 조회 시 트리 체크박스가 선택되지 않습니다.
- 트리 시트에서 트리체크 기능으로 체크박스를 사용하는데, 데이터를 불러올 때부터 체크된 상태로 표시하려면 어떻게 하나요?
- XML 데이터 구조를 쓰는 트리 시트에서 조회하면서 트리 체크박스를 체크된 상태로 표시하려면 어떻게 하나요?

**답변**

조회 데이터에 `SaveName#TreeCheck`(예: `C2#TreeCheck`:1) 형태의 키로 0 또는 1 값(문자열·숫자 모두 가능)을 지정하면 해당 행이 체크된 상태로 표시됩니다. 트리 체크 정보를 조회 시 적용할 때도 같은 방식이며, 이때 `CheckSaveName` 값이 아니라 해당 컬럼명(`SaveName`)을 사용해야 합니다.

- 이 셀 Attribute 형태를 쓰려면 cfg에 `UseJsonAttribute`를 `"1"`로 설정해야 하며, 서버에서 해당 형태로 데이터를 만들어 보내거나 `OnLoadData` 시점에 처리합니다. 데이터 구조는 도움말의 6.2.1.1 DATA 요소를 참고합니다.
- `CheckSaveName`은 저장 시 서버로 전달되는 이름이며 조회에는 적용되지 않습니다.
- y/n 같은 값은 허용되지 않고 `TrueValue`, `FalseValue`도 적용되지 않습니다. `TrueValue`는 `CheckBox` 타입에서 체크 시의 value를 뜻하는 속성이며 TreeCheck 컬럼에서는 현재 1, 0 값만 동작합니다.
- `SaveName#TreeCheck` 방식은 JSON 데이터 구조에서만 가능하고 XML 구조에서는 어렵습니다. XML이라면 컬럼을 하나 만들어 TreeCheck에 해당하는 값을 가져온 뒤 `OnSearchEnd` 이벤트에서 체크하는 로직(`TreeCheckValue`)을 돌려야 할 것으로 보입니다.

**키워드**: TreeCheck, SaveName#TreeCheck, UseJsonAttribute, CheckSaveName, TrueValue, OnLoadData, 초기 체크 상태

### [TREE-0053] TreeCheck 체크를 바꿔도 행 상태가 변하지 않아 GetSaveJson·DoSave에 체크값이 안 나옵니다

**질문**

- 트리 시트에서 TreeCheck를 설정해 사용하고 있는데, 트리 체크박스의 체크 값을 저장할 때 서버로 함께 전송하려면 어떤 설정을 해야 하나요?
- 트리시트에서 트리 체크박스를 체크/해제했는데 GetSaveJson으로 선택된 데이터를 추출하면 데이터가 나오지 않습니다. 왜 그런가요?
- 트리 체크박스(TreeCheck)를 선택해도 status 값이 바뀌지 않고 DoSave를 호출하면 저장할 내역이 없다고 나옵니다. 체크값을 서버로 보내려면 어떻게 하나요?

**답변**

트리 체크 값을 서버로 전송하려면 `CheckSaveName`을 설정해야 합니다. 다만 TreeCheck 컬럼의 체크박스는 체크/언체크해도 행 상태값(Status)을 변경시키지 않는 것이 기본 동작이어서, 체크만 바꾸고 `DoSave`를 호출하면 변경된 정보가 없다고 판단하고 `GetSaveJson`에도 추출되지 않습니다.

- 상태를 바꾸려면 `OnTreeCheckChange` 이벤트에서 상태를 변경하는 로직을 구현합니다. 예를 들어 `value`가 참이면 `SetRowStatus(row, 'U')`, 아니면 `SetRowStatus(row, 'R')`을 호출합니다. 상태가 변경되어야 `CheckSaveName`에 설정된 이름으로 데이터가 전송됩니다.
- 모든 정보를 저장하는 `DoAllSave`를 사용해 `CheckSaveName`의 Key 값으로 TreeCheck 정보를 함께 받을 수도 있습니다.
- 체크된 행만 변경하려는 경우에는 별도의 체크박스 컬럼을 사용합니다.

**키워드**: CheckSaveName, OnTreeCheckChange, SetRowStatus, DoSave, DoAllSave, GetSaveJson, TreeCheck

### [TREE-0054] TreeCheck로 체크된 행의 값을 가져오거나 레벨별로 걸러내는 방법 (GetTreeCheckValue)

**질문**

- 트리 구조로 표시한 조직에서 여러 항목을 멀티로 선택할 수 있나요? 선택한 값은 어떻게 가져오나요?
- TreeCheck로 체크된 행 중 1뎁스를 제외한 마지막 뎁스 행만 처리하려면 체크 값과 트리 레벨을 어떻게 확인하나요?

**답변**

- 체크/해제되는 시점에 처리: `OnTreeCheckChange` 이벤트에서 row와 value가 전달되므로 value가 1인 경우 `GetRowData(row)`로 행 데이터를 가져옵니다. 트리 구조 조직의 멀티 선택도 TreeCheck를 사용하고 이 이벤트에서 체크된 값을 가져옵니다.
- 버튼 클릭 등 별도 시점에 처리: 전체 데이터를 순회하면서 `GetTreeCheckValue(row)`로 선택 여부를 확인하고 `GetRowData(row)`로 추출합니다.
- 레벨별 필터링: 반복문에서 `GetTreeCheckValue`로 TreeCheck 값이 1인 행인지 검사하고, `GetRowLevel`로 트리 레벨을 확인해 1뎁스가 아닌 행만 걸러내는 조건을 추가합니다. 참고: https://docs.ibsheet.com/ibsheet/v7/manual/#docs/funcs/tree/GetTreeCheckValue

### [TREE-0055] 트리 시트에서 체크한 행들을 다른 트리 시트로 옮겨 저장하는 방법 (FindCheckedRow)

### [TREE-0056] 트리에서 부모 행을 체크하면 자식 행도 함께 체크되게 하는 TreeCheckActionMode 설정

- 트리 구조에서 트리 기준 컬럼의 체크박스(TreeCheck)를 클릭할 때 상위 노드만이 아니라 하위 노드도 함께 체크되게 하려면 어떤 함수나 값을 사용하나요?

- `SetTreeCheckActionMode(1)`, `TreeCheck:1` 연동을 사용할 때 값(`SetCellValue`)으로 체크하면 자식 행이 체크되지 않는 현상은 IBSheet7 7.0.13.173-20201029-17 버전에서 처리되었습니다.

**적용 버전**: 7.0.13.173-20201029-17

**키워드**: TreeCheckActionMode, SetTreeCheckActionMode, TreeActionMode, TreeCheck, 부모 자식 체크 연동, 관계형 모드

### [TREE-0067] ShowTreeSubSum의 제약: 소계행 미생성, 부모 값 미포함, 합계 컬럼 값 설정 불가, 트리에서 ShowSubSum 미지원

- ShowTreeSubSum으로 합계를 구하면 상위(부모) 노드 자신의 값은 빠지고 하위 노드 값만 계산됩니다. 부모 값까지 포함할 수 있나요?
- 트리 시트에서 ShowTreeSubSum으로 합계를 표시했는데 합계가 나오는 컬럼에 SetCellValue로 원하는 값이나 문자열을 넣을 수 없습니다.
- 트리를 사용하는 화면에서 ShowSubSum을 쓰면 소계가 제대로 나오지 않거나 확장할 때마다 소계가 계속 붙습니다. 지원되나요?

**답변**

- `ShowTreeSubSum`은 소계행을 추가하는 기능이 아니라, 상위 노드가 하위 노드의 값을 sum하거나 count해서 표시해 주는 기능입니다. 소계행이 필요하다면 트리를 쓰지 않는 쪽이 맞을 수 있고, Group 기능으로 트리 형태를 만드는 방법도 있습니다.
- 자식 노드에 대한 합계(갯수나 합)를 부모 노드에 표시하는 기능이므로 부모 자신은 별도의 값을 가질 수 없고, 중간 노드에 값이 있어도 계산에 포함되지 않습니다. 본인 값까지 포함해야 한다면 비슷한 기능인 그룹이나 소계(`ShowSubSum`) 기능을 사용해야 합니다.
- `ShowTreeSubSum`으로 합계를 표시하는 컬럼에는 `CellValue`로 값을 Set 할 수 없습니다. `ShowTreeSubSum` 호출 대신 모든 값을 직접 계산해 `SetCellValue`로 설정하거나, 조회 데이터에 이미 계산된 값을 포함해 조회해야 합니다.
- 트리를 사용하는 시트에서는 소계 기능(`ShowSubSum`)을 지원하지 않습니다. 적용하면 소계가 나오지 않거나 확장할 때마다 소계가 붙을 수 있습니다.
- `CreatePivotTable`로 만든 피벗 결과에서 트리에 0으로 표시되는 부분은 `ShowTreeSubSum`으로 표시되는 구간이라 0 값을 다른 값으로 표시하거나 없앨 수 없습니다.

**키워드**: ShowTreeSubSum, ShowSubSum, SetCellValue, CreatePivotTable, 트리 소계, 합계 컬럼

### [TREE-0083] 트리 OnDropEnd에서 드롭 위치와 레벨에 따라 DataMove를 처리하려면 어떻게 하나요?

**질문**

- 트리 시트에서 DataMove로 행을 이동할 때 서로 다른 레벨 사이의 이동이 제대로 되지 않습니다. OnDropEnd에서 레벨별로 어떻게 처리해야 하나요?
- 트리 시트에서 드래그 앤 드롭으로 행을 이동할 때 드롭한 위치가 상위 레벨인지 하위 레벨인지 구분해서 처리하려면 어떻게 해야 하나요?

**답변**

`onDropEnd` 이벤트에는 드롭 위치를 알려 주는 `Type` 값이 있어 1, 2, 3 중 하나가 반환되므로 이 값으로 위치별 처리를 합니다.
레벨별로 직접 처리하려면 `OnDropEnd`에서 `GetRowLevel`로 이동 행과 대상 행의 레벨을 구해 분기합니다.

- 레벨이 2단계 이상 차이나면 이동을 취소(return)합니다.
- 이동 행의 레벨이 대상보다 하위이면 `GetLastChildRow(ToRow)`+1 위치로 `DataMove(위치, FromRow)`를 호출합니다.
- 이동 행의 레벨이 대상보다 상위이면 `GetParentRow(ToRow)`+1 위치로 호출합니다.
- 같은 레벨이면 `ToRow`+1 위치로 호출합니다.

**키워드**: OnDropEnd, DataMove, GetRowLevel, GetLastChildRow, GetParentRow, Type, 드래그 앤 드롭

### [TREE-0090] 트리에서 DataInsert로 행을 추가하면 항상 하위로 들어갑니다. 같은 레벨·최상위로 추가하려면?

- 트리 구조 시트에서 DataInsert 함수로 행을 추가할 때 새로 추가되는 행의 레벨은 어떻게 지정하나요? 레벨 인자를 지정하지 않으면 어느 레벨에 추가되나요?

### [TREE-0102] 트리 시트의 조회·렌더링·펼치기가 느릴 때 ChildPage를 얼마로 설정하나요?

**질문**

- 트리 시트에서 데이터를 조회하거나 렌더링하는 속도가 느립니다. 속도를 개선하려면 어떤 설정을 해야 하나요?
- 트리 시트에서 서버 쿼리는 금방 끝나는데 화면에 그리는 데 시간이 오래 걸리고 버벅거립니다.
- 트리 구조 데이터를 수천 건 조회하는데 화면에 아무것도 출력되지 않습니다. 어떤 설정을 선언해야 하나요?
- 트리 시트에서 [+] 펼치기를 눌렀을 때 데이터가 많으면 처리에 시간이 오래 걸립니다.

**답변**

트리 시트는 자식이 table 구조로 생성되어 일반 시트보다 조회·렌더링이 느리며 데이터와 자식이 많을수록 더 느려집니다. `SetConfig`(또는 `ibsheet.cfg`의 Cfg)에 `ChildPage`를 5~10 정도로 설정하면 그 개수만큼 여러 번 나누어 렌더링해 속도가 개선됩니다. 예: `{SearchMode:2, Page:10, ChildPage:10}`. 데이터가 적을 때는 차이가 크지 않습니다.

- 서버 쿼리는 빠른데 화면에 그리는 데 오래 걸리는 경우, 수천 건(5000건, 9120건 등) 조회 시 화면에 아무것도 표시되지 않는 경우, [+] 펼치기가 오래 걸리는 경우에 설정합니다.
- 5만 건 트리에서 `ChildPage:5` 설정 후 개선된 사례가 있으며, IE9에서 2000건 정도 조회 후 화면이 버벅거리고 브라우저가 죽는 경우 `searchmode` 2, `page` 50, `childpage` 20으로 적용한 사례가 있습니다.
- 트리 조회 시 이미지를 넣어 느린 경우, IBSheet Pro에서 IBSheet7로 마이그레이션한 뒤 트리가 느린 경우에도 `ChildPage:5`를 적용합니다.
- 데이터가 늘수록 성능이 나빠질 때는 제품 교체보다 cfg에 `ChildPage:5`를 먼저 적용해 봅니다(최신 제품과 사용 중인 제품의 성능 차이는 크지 않을 것으로 판단됩니다).

**키워드**: ChildPage, SetConfig, 트리 속도, 트리 조회 느림, SearchMode, Page, childpage

### [TREE-0103] 트리 시트에서 스크롤하면 가운데 숫자가 나오고 스크롤이 끊기는 원인 (ChildPage, DeferredVScroll)

**질문**

### [TREE-0104] ChildPage를 설정하면 트리 접기·펼치기나 데이터 렌더링 시 화면이 깜빡이거나 덜컹거립니다

**질문**

- 트리에서 ChildPage를 10으로 설정했더니 트리를 접고 펼칠 때 하단 부분이 깜빡입니다. 이 현상을 개선할 수 있나요?
- 트리 시트에서 속도 때문에 ChildPage를 설정했더니 데이터가 그려질 때 화면이 덜컹거립니다. 이를 개선할 방법이 있나요?

`ChildPage`를 설정하지 않으면 모든 행을 브라우저가 DOM 객체로 가지고 있어 문제가 되므로 `ChildPage:10` 설정이 권장됩니다. 반면 `ChildPage`를 설정하면 전체 영역을 DOM 객체로 가지지 않고 일정 크기 영역에 메모리의 전체 데이터를 appendchild / removeChild 하는 과정이 발생하고, 설정한 개수만큼 렌더링이 여러 번 일어나므로 깜빡임이나 덜컹거림이 발생할 수밖에 없습니다. 이를 개선할 별도의 방법은 없으며 현재 방식이 최선입니다.

**키워드**: ChildPage, 깜빡임, 덜컹거림, appendchild, removeChild, 트리 접기 펼치기

### [TREE-0105] 트리 데이터가 너무 많을 때 '+' 버튼을 누르는 시점에 자식 데이터를 붙이는 방법 (DoSearchChild)

- 트리 데이터를 페이징하며 몇만 건씩 append로 추가하고 싶습니다. 하단에 동적으로 붙이면서 트리 레벨을 유지할 수 있나요?

**답변**

트리는 서버 페이징 조회 방식을 지원하지 않으며, 하단에 데이터를 동적으로 붙이면서 트리 레벨을 유지하는 방법도 지원되지 않습니다. 트리 시트는 일반 시트와 데이터 구조와 표시 방식이 달라, 레벨이 섞인 데이터를 기존 데이터에 append하는 구조로는 설계되지 않았습니다. 서버 페이징을 적용한 트리 시트에서 트리체크 옵션과 체크박스를 사용하면 행 번호가 -1로 반환되는 사례가 있었습니다.
대안은 다음과 같습니다.

- 동적 확장 트리 방식으로, 최초에는 특정 레벨까지만 조회하고 트리 데이터를 클릭할 때 `OnTreeChild` 이벤트에서 하위 데이터를 조회해 가져옵니다. `LoadSearchChildData()`로 선택한 행의 하위 노드를 append할 수 있습니다. Demo의 IBSheet > 동적확장트리 예제를 참고합니다.
- 트리 전체 데이터가 1만~2만 건이라면 최초 조회 시 전체 데이터를 다 그리는 방식으로 바꾸는 방향을 검토합니다. 트리는 조회 데이터가 많을수록 렌더링과 접기·펼치기 때 버벅이는 이슈가 있습니다.

**키워드**: LoadSearchData, Append, 서버 페이징, OnTreeChild, LoadSearchChildData, 동적 확장 트리, 트리 페이징

### [TREE-0119] 트리 시트에서 머지(병합)를 사용할 수 있나요? DataRowMerge, RowMerge, SetMergeCell이 동작하지 않습니다

**질문**

- 트리 시트나 트리 컬럼이 포함된 시트에서 머지를 하고 싶은데 적용되지 않습니다. 트리에서 머지가 지원되나요?
- 트리 시트에서 머지를 할 수 있나요? 가로 머지는 가능한지, DataRowMerge와 RowMerge 설정으로 되는지 궁금합니다.
- 트리 구조 시트에서 셀 머지가 적용되지 않고, SetMergeCell로 강제 머지해도 treeCol 앞쪽 컬럼은 잘 되지 않습니다. 가능한가요?
- MergeSheet로 머지를 적용한 시트를 트리 구조로 바꾸면 머지가 풀립니다. 트리에서 머지를 함께 사용할 수 있나요?

**답변**

IBSheet7에서는 트리 시트의 머지를 지원하지 않습니다. 설계 초기부터 트리는 머지가 되지 않게 했고(성능 이슈도 있음), ActiveX에서는 트리 머지가 가능했지만 IBSheet7에서는 불가능하며 앞으로도 적용될 예정이 없습니다. 트리에서 병합을 사용하다 문제가 생기면 지원이 어려울 수 있습니다.

- `SetConfig`의 `DataRowMerge`와 `InitColumns`의 `RowMerge`를 설정하는 가로 머지, 헤더 설정을 통한 머지도 동작하지 않습니다.
- `SetMergeCell`(`setMergeCell()`)로 강제 머지하면 treeCol 뒤에 위치한 컬럼에서는 동작하기도 하지만 앞에 있으면 잘 되지 않아, 트리에서는 동작하지 않는다고 봐야 합니다. 레벨 값에 따라 머지를 판단하는 분기 처리는 제품에 없고 구현하기도 어렵습니다.
- 같은 값을 공백으로 바꿔 머지처럼 보이게 하려면 `OnLoadData()`에서 데이터를 받아 JSON으로 만들어 바꾸는 로직을 넣습니다.

**키워드**: 머지, 병합, DataRowMerge, RowMerge, SetMergeCell, MergeSheet, 트리 머지

### [TREE-0120] 트리 시트에서 헤더 클릭 정렬이 안 되거나 같은 레벨 안에서만 정렬됩니다 (TreeChildSort)

**질문**

- 트리 형태로 표시한 시트에서 헤더를 클릭해 정렬하려는데 동작하지 않습니다. TreeChildSort를 적용해도 되지 않는데 정렬을 지원하지 않는 건가요?
- 트리 시트에서 정렬하면 같은 레벨 안에서만 정렬되는 것 같습니다. 전체 데이터를 대상으로 정렬할 수 있나요?
- 트리 구조를 사용하는 시트에서 헤더 소팅을 트리 데이터의 레벨 기준으로 하고 싶습니다. 특정 레벨을 기준으로 그 레벨 안의 데이터를 정렬하는 기능이 있나요?
- 트리 시트에서 기준 컬럼이 아닌 다른 컬럼을 정렬(sort)하면 숫자 컬럼과 문자 컬럼이 이상하게 섞이는 것처럼 보입니다. 정렬이 왜 제대로 안 되나요?

**답변**

트리 구조의 시트에서는 일반적인 정렬 기능을 지원하지 않습니다. 트리 시트는 노드 내부(같은 레벨 안)에서만 정렬되며, 전체 데이터를 대상으로 정렬하면 노드 구조가 틀어지기 때문에 컬럼 전체를 대상으로 하는 정렬은 불가능합니다. 헤더 정렬은 컬럼 기준으로 동작하므로 트리 데이터 안에서 특정 레벨을 기준으로 정렬하는 것도 지원되지 않습니다.
`TreeChildSort`는 1레벨 데이터의 하위 노드를 정렬하는 제약이 있는 기능이며, 7.0.6.0 버전에서 추가되었으므로 7.0.0.0 버전에서는 지원되지 않습니다.

**적용 버전**: 7.0.6.0 이상(TreeChildSort)

**키워드**: TreeChildSort, 트리 정렬, 헤더 정렬, sort, 노드 구조, 레벨 정렬

### [TREE-0142] IBSheet7 트리 데이터를 IBSheet8 convertTreeData()로 변환할 때 지켜야 할 조건은?

- IBSheet7 형태의 트리 데이터를 IBSheet8에서 사용하려고 convertTreeData()로 변환하는데 오류가 나고 데이터가 이상하게 표시됩니다. 변환할 때 지켜야 할 조건은 무엇인가요?

IBSheet8의 `convertTreeData()`로 IBSheet7 형태의 트리 데이터를 변환하려면 세 가지 조건을 지켜야 합니다.

- 상위 키 값에 대한 정렬이 지원되지 않으므로 변환할 데이터는 화면에 표시될 순서대로 정렬되어 있어야 합니다.

### [TREE-0143] IBSheet3의 InitTreeInfo 대신 IBSheet7에서 트리를 만드는 방법은? 트리를 지원하나요?
