### [FRM-0001] 스프링부트처럼 jsp를 쓰기 어려운 환경에서 엑셀 다운로드/업로드 모듈은 어떻게 적용하나요?

**질문**

- 스프링부트처럼 jsp 사용이 어려운 환경에서 엑셀 다운로드/업로드 모듈은 어떻게 적용하나요? ibsheet.cfg의 Down2Excel_Url, LoadExcel_Url 설정도 궁금합니다.
- 스프링 환경에서 Down2Excel을 호출하면 404 에러가 발생합니다. 어떻게 설정해야 하나요?

**답변**

jsp 사용이 어려운 사이트는 jsp의 내용을 java(서블릿/컨트롤러)로 변환하여 적용합니다. 서버모듈/jsp 폴더의 `ibsheetFileImportExportController.java`가 jsp 내용을 java로 바꾼 파일이지만 IBSheet8용이므로, 이를 참고하여 IBSheet7용으로 만듭니다. IBSheet7과 8은 exception 쪽 로직만 다르므로 jsp를 참고해 그 부분을 변경합니다.
그런 다음 `ibsheet.cfg`의 `Down2Excel_Url`, `LoadExcel_Url`에 jsp 대신 `abc.do` 같은 컨트롤러 주소를 적습니다. 스프링 servlet을 통해 `Down2Excel`을 처리하려면 해당 경로 설정을 `.do`로 지정하고 컨트롤러 java를 추가해야 하며, 이를 하지 않으면 404 에러가 발생할 수 있습니다.

**키워드**: Down2Excel_Url, LoadExcel_Url, ibsheet.cfg, ibsheetFileImportExportController.java, 스프링부트, jsp 변환, 404

### [FRM-0002] 프레임워크가 Multipart를 처리해 엑셀 다운로드/업로드가 안 될 때 서버모듈 JSP를 서블릿으로 바꾸는 방법은?

**질문**

- Spring Boot처럼 프레임워크가 Multipart를 처리해 엑셀 다운로드나 LoadExcel이 동작하지 않을 때, 서버모듈 JSP를 서블릿으로 바꾸는 방법은 무엇인가요?
- Spring을 사용하는 환경에서 서버모듈 Down2Excel.jsp를 호출하면 Multipart로 전송되면서 415 에러가 납니다. 어떻게 해결하나요?

**답변**

SpringBoot에서는 MultiPartFilter가 적용되므로 엑셀 다운로드·업로드 시 `.setData`로 데이터를 적용해야 합니다. 서블릿 변환 방법은 다음과 같습니다.

- `ibsheet.cfg`의 `Down2Excel_Url`을 서블릿 이름(예: `Down2Excel.do`)으로 변경합니다.
- `Down2Excel.jsp`를 서블릿으로 바꾸고, `down.setService(request, response)` 전에 `request.getParameter`로 받은 `Data`를 `down.setData(Data)`로 다시 설정합니다.
Multipart 전송으로 415 에러가 나는 경우에도 `Down2Excel.jsp`를 서블릿으로 만들어 연결하고 프레임워크 단에서 multipart resolver 값을 0으로 설정해야 합니다. 가장 간단하게는 jsp 파일들을 WEB-INF 바깥쪽에 위치시키면 됩니다.

**키워드**: Down2Excel.jsp, 서블릿 변환, setData, Down2Excel_Url, 415 에러, MultiPartFilter, SpringBoot

### [FRM-0003] Spring 환경에서 엑셀 다운로드 시 download Excel Data is not valid 또는 IBSheetDown.setData NullPointerException이 납니다

**질문**

- Spring 기반 프레임워크에서 엑셀 다운로드가 안 됩니다. `download Excel Data is not valid` 오류가 나거나 `IBSheetDown.setData`에서 NullPointerException이 납니다. 원인과 해결은?
- Spring 기반 프레임워크에서 MultipartResolver가 설정되어 있으면 서버모듈이 MultipartRequest에서 파일 정보를 가져올 때 null이 나옵니다. 어떻게 우회하나요?
- Spring 기반 프레임워크에서 엑셀 다운로드 JSP를 controller로 바꿨더니 IBSheetDown.setData에서 NullPointerException이 납니다. MultipartResolver 충돌은 어떻게 설정해 해결하나요?

**답변**

Spring 기반 프레임워크에서 MultipartResolver가 설정되면 MultipartRequest 안의 정보를 프레임워크가 가져가기 때문에, 서버모듈이 MultipartRequest 객체에서 파일 정보를 가져올 때 null이 됩니다. Tomcat의 web.xml, context.xml에 multipart를 정의해 오류가 사라져도 다운로드가 안 되는 경우 같은 원인으로 보입니다. 우회 방법은 다음과 같습니다.

- `context-common.xml` 또는 `dispatcher-servlet.xml`에 `IBMultipartResolver` 클래스를 사용하는 bean을 추가하고(다른 xml에 선언되어 있을 수 있으니 multipartResolver로 검색), `multipartResolver` alias가 이 bean을 가리키게 합니다.
- 제공되는 `IBMultipartResolver.java`를 지정한 경로나 원하는 위치에 복사하고, bean의 class 위치와 일치하도록 위치 정보를 수정합니다.
- 이 클래스는 요청에 `SheetWork` 파라미터가 있거나 `AjaxComponent` 헤더가 `IBUpload`이면 Multipart가 아닌 것처럼 처리해 Spring 멀티파트 리졸버가 가져가지 못하게 합니다.

**키워드**: IBMultipartResolver, MultipartResolver, IBSheetDown.setData, download Excel Data is not valid, SheetWork, context-common.xml, dispatcher-servlet.xml

### [FRM-0004] 스프링/전자정부프레임워크에서 Down2Excel·DirectDown2Excel이 NullPointerException 또는 Data is not valid 오류를 냅니다 (Multipart:0)

**질문**

- Spring Boot 환경에서 Down2Excel로 엑셀을 내려받을 때 서버에서 NullPointException이 발생하며 시트 데이터를 받지 못합니다. 해결 방법이 있나요?
- 스프링이나 전자정부프레임워크 환경에서 DirectDown2Excel을 호출하면 NullPointerException이 나거나 'An error has occurred while downloading the file' 메시지가 나옵니다. 어떻게 해결하나요?
- 전자정부프레임웍 환경에서 DirectDown2Excel을 호출하면 `DownLoadExcel Data is not valid` 오류나 NullPointException이 발생합니다. 어떻게 해결하나요?
- 스프링 프레임워크 환경에서 DirectDown2Excel에 SHEETDATA로 넘긴 데이터가 출력되지 않습니다. 원인과 해결 방법은 무엇인가요?

**답변**

`Down2Excel`/`DirectDown2Excel`은 시트 헤더·데이터 정보를 기본적으로 Multipart 형식으로 전달하는데, 스프링·전자정부프레임워크에서는 MultipartResolver 등이 Multipart 데이터를 가져가 서버(jsp)에서 데이터를 받지 못합니다. 그 결과 `NullPointException`, `DownLoadExcel Data is not valid`, 'An error has occurred while downloading the file' 같은 증상이 나타납니다. 해결 방법은 다음과 같습니다.

- MultipartResolver 설정을 하고, `SheetWork` 파라미터가 null이 아니면 `return false` 하도록 처리합니다.
- `Down2Excel({Multipart:0})`, `DirectDown2Excel` 호출 시 `Multipart:0`으로 설정해 데이터를 post로 보냅니다. 이때 `DirectDown2Excel.jsp`에서 `String data = request.getParameter("Data");`로 받으며, 파라미터 이름은 대소문자를 구분하므로 `data`가 아니라 `Data`로 받아야 합니다.
- post 방식은 서버의 `MaxPostSize`, `MaxParameterCount` 제한을 받으므로 데이터가 잘리면 값을 늘리거나 무제한으로 설정합니다.
- 스프링 컨트롤러를 거치며 multipart 내용이 사라지는 경우에는 컨트롤러에서 넘어오는 `Data` 값을 받아 강제로 request에 담아 `DirectDown2Excel.jsp`로 전달하고, `DirectDown2Excel.jsp`도 그에 맞게 수정합니다.

**키워드**: Multipart:0, DirectDown2Excel, Down2Excel, MultiPartResolver, SheetWork, MaxPostSize, MaxParameterCount, NullPointException

### [FRM-0005] Spring·전자정부프레임워크에서 LoadExcel/DirectLoadExcel 업로드 시 NullPointException이 나거나 포워딩(FP) 페이지가 호출되지 않습니다

**질문**

- Spring 프레임워크 환경에서 LoadExcel로 엑셀 업로드 시 서버 JSP가 데이터를 받지 못하고 NullPointException 등 오류가 발생합니다. 원인과 해결 방법은 무엇인가요?
- 전자정부(Spring) 프레임워크에서 DirectLoadExcel을 쓰면 FP로 지정한 포워딩 페이지가 호출되지 않습니다. 원인과 해결 방법이 무엇인가요?

**답변**

엑셀 요청은 기본적으로 Multipart 형식으로 전달됩니다(시트 데이터가 많아 일반 post로 보내면 서버가 받지 못하는 경우를 막기 위함). Spring에서는 프레임워크가 엑셀 파일과 Multipart 내용을 모두 가져가므로 `DirectLoadExcel.jsp` 등 JSP가 데이터를 받지 못해 NullPointException이 발생합니다. 해결 방법은 다음과 같습니다.

- `CommonsMultipartResolver`를 상속한 MultiPartResolver를 만들어 `isMultipart`에서 요청 파라미터 `SheetWork`가 있으면 false를 반환해 multipart가 아닌 것처럼 동작시키고, `context-common.xml` 또는 `dispatcher-servlet.xml`에 bean으로 등록합니다.
- multipart가 아닌 post 형식으로 데이터를 넘기도록 설정합니다.
- 먼저 Spring의 멀티파트 설정을 제거하고 확인해 봅니다. 파일명은 들어오는데 FP 포워딩 페이지가 호출되지 않는 경우에는 `multiPartResolver` 설정을 해 봅니다.

**키워드**: LoadExcel, DirectLoadExcel, CommonsMultipartResolver, isMultipart, SheetWork, FP, NullPointException

### [FRM-0008] 전자정부·스프링 환경에서 엑셀 다운로드·업로드 JSP를 WEB-INF 아래에 두면 에러가 납니다

**질문**

- 전자정부 프레임워크를 사용하는데 엑셀 다운로드와 업로드가 잘 되지 않습니다. 어떻게 해야 하나요?

**답변**

JSP 파일들이 web-inf 안에 있으면 별도로 해야 할 설정이 있으므로, 다운로드·업로드 jsp를 WEB-INF에 두지 말고 WEB-INF 밖의 `ibsheet.js`가 있는 쪽 아무 폴더에 두어 사용하세요. WEB-INF 아래에 두면 다운로드는 되지만 업로드 관련 파일에서 url 계산이 정상적으로 되지 않아 파일 다이얼로그 창을 띄우지 못하는 현상이 있으며, 이는 IE 하위 브라우저에서 발생하고 크롬 등에서는 정상입니다.

**키워드**: WEB-INF, 엑셀 업로드, 엑셀 다운로드, 전자정부 프레임워크, 파일 다이얼로그, jsp 위치

### [FRM-0011] Jakarta EE 환경(JDK 17/21, 스프링부트)에서는 어떤 서버모듈 jar를 적용해야 하나요?

해결 방법은 다음과 같습니다.

- jQuery를 1.7.0 ~ 1.8.3 사이 버전으로 업데이트합니다. 1.7.2 이상을 쓰면 해결되며 1.7.2 버전이 가장 적당합니다. 1.6.2에서 발생하던 현상이 1.6.3부터 재현되지 않았다는 안내도 있고 1.6.3에서 문제가 확인되었다는 안내도 있으므로, 1.7.0 이상으로 올리는 것이 안전합니다.
- 1.8.3 이상에서는 `jquery.mask()` 등 날짜 마스킹 기능이 정상 동작하지 않을 수 있으니 주의합니다.
- jQuery 1.x, 2.x는 보안 취약점이 있어 3.x로 올려야 하는 경우 사용 중인 inputmask(jquery mask)도 함께 버전을 올려야 합니다. 최신 jQuery로 올리면 기존 jquery mask가 동작하지 않을 수 있습니다.

**적용 버전**: jQuery 1.7.0 ~ 1.8.3 권장(1.7.2 적당)

**키워드**: jQuery 1.6.2, clearInterval, jQuery 달력, 데이터 미표시, jquery.mask, jQuery 1.7.2, 스크롤

- 레이어 팝업이나 모달 팝업 안에 시트를 넣어 쓰는데 처음 한 번은 잘 뜨지만 팝업을 닫았다가 다시 열면 시트가 안 나타나거나 오류가 납니다. 원인과 해결은?

- 레이어 팝업을 띄우고 팝업 input에 포커스를 줘도 부모 시트가 키 이벤트를 받거나 마우스 휠 스크롤에 시트가 움직입니다. setBlur()를 호출해도 같다면 어떻게 하나요?

DropDown 메뉴가 시트 영역을 침범하는 경우에도 `SetBlur()`로 포커스를 제거하고, modal처럼 표시 영역과 외부 영역을 분리해 외부 영역을 선택할 수 없게 사용하는 것을 권장합니다.
- `SetBlur`로 해결되지 않는 키 입력·마우스 휠 스크롤 문제는 부모 시트에서 `SetEnable(0)`을 호출하고 레이어 팝업을 닫기 직전에 `SetEnable(1)`을 호출하는 enable 방식으로 처리합니다. enable 하면 시트에서 선택했던 행 정보가 사라지므로 팝업을 열기 전에 행 정보를 기억해 두었다가 닫을 때 `SelectCell`(또는 `SelectRow`)로 다시 선택하는 코드가 필요합니다.
- 시트가 뿌옇게 변하는 div의 z-index가 팝업보다 높으면 `ibsheet.css`의 `GMDisabled` z-index를 수정합니다.

**적용 버전**: 7.0.13.157 이상(SetBlur(1))

**키워드**: SetBlur, SetEnable, 레이어 팝업, 모달, 스크롤, GMDisabled, SelectCell

### [FRM-0110] 팝업창·iframe·IBTab 탭 페이지에서 부모창의 시트나 함수에 접근하려면 어떻게 하나요?

**질문**

- 팝업창을 열어 다른 URL로 이동시킨 뒤 팝업에서 부모 창(opener)에 접근하려는데 접근이 안 됩니다. 어떻게 해야 하나요?

**답변**

접근 방식은 창을 연 방법에 따라 다릅니다.

**키워드**: opener, parent, window.opener, window.parent, 팝업 부모창 접근, IBTab, 크로스 도메인

### [FRM-0121] display:none이거나 크기가 0인 iframe·영역 안에서는 시트가 생성되지 않거나 오류가 납니다

- 크기가 0인 iframe에 시트가 있는 페이지를 불러온 뒤 DataInsert를 호출하면 'Page' 속성을 가져올 수 없다는 오류가 납니다. 원인과 해결 방법은?
- iframe으로 포함한 시트 화면에서 iframe의 높이와 너비를 0으로 하면 저장이 되지 않고 100으로 하면 저장됩니다. 높이·너비와 관련 있나요?

**답변**

IBSheet는 생성 시 부모 영역의 크기를 계산하므로 `display:none`이거나 `width:0`, `height:0`인 div·iframe에서는 정상적으로 생성되거나 표현되지 못합니다. 크기가 0인 iframe에서 `DataInsert`를 호출하면 'Page' 속성을 가져올 수 없다는 오류가 날 수도 있습니다. 해결 방법은 다음과 같습니다.

- iframe 너비가 0이면 width 값을 설정합니다(예: `width='0'` 대신 `width='500px'`). `height`가 0이면 시트는 화면에 보이지 않습니다.

**키워드**: display:none, visibility:hidden, IBS_InitSheet, iframe 크기 0, hide show, DataInsert

- 탭으로 화면을 불러오는 구조에서 그리드의 컬럼이 비정기적으로 틀어집니다. 헤더 설정과 SetAutoRowHeight를 추가해도 해결되지 않는데 원인은 무엇인가요?
- 모달 안에 시트를 생성하면 처음에 시트 너비가 늘어났다가 모달 크기에 맞게 변경됩니다. 어떻게 해결하나요?

**답변**

시트는 시트를 그릴 div 객체를 만들고(이때 너비와 높이가 잘 잡혀 있어야 함) `createIBSheet` 또는 `createIBSheet2`가 그 div에 append하는 방식으로 그려지며, 시트 너비는 상위 엘리먼트의 너비에 영향을 받습니다. IBSheet는 순수 자바스크립트로 구현되어 객체 생성 시 DOM이 만들어지므로 상위 엘리먼트나 전역 CSS가 영향을 주면 시트 표시도 달라집니다.

- 상위 엘리먼트에 `display:flex`, `position:absolute` 같은 규칙이 있으면 시트가 영역을 벗어날 수 있으며, flex 속성을 제거하면 시트가 div에 맞춰 표시됩니다.
- 탭 컨테이너의 `fade` 클래스처럼 애니메이션 효과를 주면 PC 성능에 따라 div의 높이나 너비가 잘 잡히지 않아 컬럼이 틀어지므로 `fade`를 제거합니다.
- 프레임워크가 DOM 생성 시점에 시트 영역의 height를 바꾸면 고정값을 지정해도 다른 값이 적용될 수 있으며, 이때 `setTimeout`으로 실행 순서를 뒤로 미루면 정상 동작합니다.
- 모달 안 div의 너비·높이가 동적으로 설정된다면 해당 크기가 정해진 뒤에 시트를 생성하거나, timeout으로 모달보다 늦게 시트가 생성되도록 합니다.

**키워드**: display:flex, fade, createIBSheet2, setTimeout, 부트스트랩, 시트 높이, 모달 시트 너비

### [FRM-0144] 시트 생성 후 같은 화면에서 ibsheet.js를 또 include하거나 시트 생성을 두 번 호출하면 시트가 멈추거나 그려지지 않습니다

**질문**

- 화면 안에 import 하는 화면이 시트를 생성하는 div 아래쪽에 있으면 시트가 생성된 뒤 동작하지 않습니다. 원인과 해결은?
- div로 만든 팝업 안에 서버에서 가져온 내용을 append해서 시트를 띄우는데 시트가 그려지지 않습니다. 원인이 무엇인가요?

**답변**

시트를 생성한 뒤 같은 화면에서 `ibsheet.js`를 또 호출(include)하면 시트가 멈춥니다. 아래쪽에 import된 화면에서 ibsheet.js가 두 번 호출되는 경우이며, include되는 것은 모두 상단에 위치해야 합니다. div 팝업에서도 팝업 안의 시트 생성이 두 번 호출되어 그려지지 않은 사례가 있으므로 호출이 한 번만 이루어지도록 수정하고, 그래도 문제가 계속되면 추가로 점검합니다.

**키워드**: ibsheet.js, include 중복, 시트 생성 두 번 호출, div 팝업, import 화면

### [FRM-0148] 탭을 전환할 때마다 시트가 다시 초기화되면 전체 체크가 사라지거나 머지·ColHidden이 풀리거나 깨집니다

**질문**

- 탭을 클릭할 때마다 시트 컬럼이 바뀌는 화면에서 시트를 style hidden으로 감췄다 보이게 했더니 두 번째 탭의 시트가 깨져 보입니다. 어떻게 하나요?
- 탭으로 구성된 화면에서 두 번째 탭의 시트에 전체 체크박스가 나오지 않습니다. 탭을 누를 때마다 시트 초기화를 하고 있는데 어떻게 해야 하나요?
- div 탭 두 개로 화면을 나눴는데 두 번째 탭에 갔다가 첫 번째 탭으로 돌아와 조회하면 시트의 머지가 풀립니다. 어떻게 해결하나요?
- MdiTab()으로 탭마다 페이지를 호출하고 ColHidden으로 컬럼을 숨겼는데, 다른 탭으로 이동해 보면 컬럼 숨김이 풀려 있습니다. 왜 그런가요?

**답변**

탭 전환 시 시트를 어떻게 다시 쓰는지에 따라 증상이 달라집니다.

- 탭 클릭 시 컬럼이 동적으로 바뀌는 경우에는 `style: hidden`으로 시트를 감췄다 보였다 하는 방식보다 `Reset()` 함수를 사용하는 것이 좋습니다. 일부 컬럼만 숨겨지고 내용이 동일하다면 `ColHidden`으로 숨기는 방법도 있고, 컬럼 정보를 전체적으로 재구성해야 하면 `Reset()`으로 초기화한 뒤 시트를 다시 생성합니다. 컬럼 수가 다시 바뀌면 컬럼 정보 조회 → 시트 생성 → 데이터 조회 순서로 개발합니다.
- 탭을 누를 때마다 시트 초기화를 반복하면 전체 체크박스가 누락되는 등의 현상이 생길 수 있으므로, 시트 초기화 시에 시트가 이미 있는지 확인해 최초 1회만 초기화하도록 구현합니다.
- 탭을 오갈 때 시트의 머지가 풀리는 경우에는 `Reset()`을 호출하거나, `LastCol` 함수로 시트가 이미 초기화되었는지 판단한 뒤 초기화 여부를 결정하도록 처리합니다.
- `MdiTab()`은 탭의 페이지를 클릭하면 지정된 경로의 페이지를 새로 호출하므로, 초기화 시점에 `ColHidden`을 처리하지 않으면 숨김이 풀리는 것이 당연합니다. 사용자 권한 정보 등을 받아 컬럼을 숨기는 경우에도 페이지가 초기화되는 시점에 `ColHidden`이 적용되도록 처리합니다.

**키워드**: Reset, ColHidden, LastCol, MdiTab, 탭 전환, 시트 재초기화, 전체 체크

### [FRM-0152] 탭 전환 시 이전 탭 시트의 포커스 표시가 계속 함께 보입니다
