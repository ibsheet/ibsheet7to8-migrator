이 도구가 하는 일 (1분 요약)

  • IBSheet7 코드(GetCellValue, SaveName, SearchMode:2, Hidden:true 등)를 IBSheet8 코드로 바꿉니다.
  • 안전한 변환은 자동(engine/), 판단이 필요한 변환은 AI가 매뉴얼(docs/)을 근거로 처리합니다.
  • 변환 후 스스로 검증(verify/)합니다: IBSheet7 잔존 0건 / JS 구문 정상 / 원본 함수 누락 0건.
⚠️ 이 도구는 화면(프론트) 코드 변환 + 정적 검증까지 책임집니다. 서버(컨트롤러·SQL)와 실제 브라우저 동작 검증(QA)은 변환 후 별도로 진행해야 합니다. (8단계 참고)
⚠️ 변환 결과는 helpers/ibsheet-migration.js 파일 1개를 함께 필요로 합니다. 이 파일을 웹앱에 배포하지 않으면 검증 3종은 PASS인데도 브라우저에서 오류가 납니다. (8단계 1번 필수)

폴더 구성

ibsheet7to8-migrator/ ├── migrate.py ← 실행 CLI (convert / verify / rules / doctor) ├── AGENTS.md ← 규칙 원본(모든 AI가 이걸 따름) ├── CLAUDE.md ← Claude Code 진입점 (AGENTS.md 포인터) ├── GEMINI.md ← Gemini 진입점 (AGENTS.md 포인터) ├── .github/copilot-instructions.md ← GitHub Copilot 진입점 (AGENTS.md 포인터) ├── 사용가이드.md ← 이 문서 ├── migrate.config.example.json ← 프로젝트별 설정 템플릿 ├── docs/ ← 지식(.md) method/property/event-mapping, deprecated, conventions │ ├── ibsheet7-manual/ ← IBSheet7 벤더 매뉴얼 전문 (모든 매핑 판단의 1차 근거) │ └── ibsheet8-manual/ ← IBSheet8 벤더 매뉴얼 전문 ├── helpers/ ← 런타임(.js) ibsheet-migration.js ★변환 대상 프로젝트에 배포 필요 ├── samples/ ← 참조 예제 asis/ · tobe/ 두 쌍 + README (변환 판단 근거 예시) ├── engine/ ← 변환 엔진(.py) migrate_core.py + rules/migrate_rules.json └── verify/ ← 검증(.py) residue_scan.py · jscheck.py · fn_parity.py

helpers/만 고객 웹앱에 함께 배포되는 산출물입니다. 나머지(migrate.py·docs·engine·verify·samples)는 변환 작업용이라 배포하지 않습니다.

폴더명은 Git clone 시 ibsheet7to8-migrator가 됩니다. 압축 파일로 전달받았다면 그 안의 폴더명을 따르며, 이름이 달라도 동작에는 영향이 없습니다(툴킷 내부는 상대 경로로만 참조합니다).

2

사전 설치 (상세)

아래는 ① 인터넷이 자유로운 PC와 ② 사내 폐쇄망/제약 PC(인터넷 제한·관리자권한 없음·프록시) 두 경우를 함께 안내합니다. 제약 환경이면 IT/시스템 관리자의 도움이 필요할 수 있습니다. 막히면 무리하지 말고 관리자에게 요청하세요.

2-1. Node.js (LTS)

JS 구문 검증과 AI CLI 도구의 기반이 됩니다.

① 인터넷 가능 PC
  • nodejs.org → LTS Windows Installer(.msi) 다운로드
  • 기본값 그대로 설치 ("Add to PATH" 유지)
  • 새 터미널에서 node --version, npm --version 확인
② 사내 폐쇄망/제약 PC
  • 인터넷 PC에서 .msi를 받아 전송 후 설치
  • 관리자권한이 없으면 IT 관리자에게 "Node.js LTS 설치" 요청
  • 프록시 환경: npm config set proxy http://프록시:포트 / https-proxy 동일 설정

2-2. Python 3

변환 엔진(engine/)·검증 스크립트(verify/)를 실행합니다. 외부 패키지 설치가 필요 없는 순수 표준 라이브러리 스크립트라 Python 본체만 있으면 됩니다.

① 인터넷 가능 PC
  • python.org/downloads → 최신 3.x 설치 파일
  • 첫 화면에서 "Add python.exe to PATH" 체크(중요) 후 Install
  • 새 터미널에서 python --version 확인 (안 되면 py --version)
② 사내 폐쇄망/제약 PC
  • 인터넷 PC에서 설치 파일을 받아 전송, 또는 IT 관리자에게 "Python 3 설치" 요청
  • 사내에 이미 Python이 있으면 버전만 확인하고 사용(3.8 이상 권장)

2-3. AI 코딩 도구 (택1)

어떤 AI를 쓰든 동일한 규칙(AGENTS.md)과 검증(verify/)으로 동작합니다. 사내에서 이미 도입·허용된 도구가 있으면 그것을 쓰는 게 가장 좋습니다.

플러그인 설치 과정이 없습니다. 아래 둘 중 한 방법으로 사용합니다.

툴킷 받기 — 둘 중 하나

방법결과 폴더

git clone https://github.com/ibsheet/ibsheet7to8-migrator.git		ibsheet7to8-migrator

방법 A — 이 폴더를 작업 디렉터리로 (권장, 빠른 시작)

  1. 툴킷 폴더를 원하는 위치에 둡니다.
  2. 변환할 소스를 이 폴더 안/근처에 두거나 경로로 지정합니다.
  3. 이 폴더에서 AI 도구를 실행하면 진입점 파일(AGENTS.md 계열)의 규칙이 자동 적용됩니다.

방법 B — 변환 대상 프로젝트에 규칙 이식

  1. 사용하는 AI의 진입점 파일(CLAUDE.md / GEMINI.md / .github/copilot-instructions.md 중 해당)과 AGENTS.md를 변환 대상 프로젝트 루트에 복사합니다.
  2. ./engine · ./verify · ./docs 경로가 이 툴킷 폴더를 가리키도록(또는 폴더째 함께 복사) 합니다.
  3. 대상 프로젝트에서 AI 도구 실행.
4

프로젝트 설정 (1회, 선택이지만 권장)

프로젝트마다 컬럼/폼 변수 명명 규칙이 달라서, 이를 알려주면 변환 정확도가 올라갑니다. migrate.config.example.json을 변환 대상 프로젝트 루트에 migrate.config.json으로 복사한 뒤 수정합니다.

{
  // 컬럼 참조에서 떼어낼 접두사 (리스트/시트 변수 → IBSheet8 컬럼 Name엔 접두사 불가)
  "stripPrefixes": ["\\w+DTOList\\.", "\\w+Sheet\\."],

  // 폼 필드/팝업이라서 떼면 안 되는 접두사 (그대로 유지)
  "keepPrefixes": ["\\w+CommonDTO\\.", "\\w+DTO\\.", "\\w+Map\\."],

  // 조회/저장 서버 호출 URL 변환 규칙
  "urlConvention": { "search": "{screenId}Ajax.do", "save": "{screenId}Save.do" }
}

판단이 어려우면 설정 파일 없이 기본값으로 시작해도 됩니다. AI가 변환 중 애매한 접두사는 질문하거나 ⚠로 표시합니다.

변환 실행 — 따라하기

진입점 파일이 적용된 상태에서 자연어로 요청하면 됩니다. (별도 명령어 없음)

src/main/webapp/.../orderList.jsp 를 IBSheet8로 변환해줘

어디에 입력하나요?

이 요청은 2-3단계에서 설치한 AI 도구의 대화창(프롬프트)에 입력합니다. 별도 프로그램이 아니라 그 AI 도구 자체가 입력 창구입니다.

AI 도구입력하는 곳
Claude Code터미널에서 claude 실행 → 뜨는 프롬프트에 입력 (또는 VS Code/JetBrains의 Claude Code 패널)
Gemini CLI터미널에서 gemini 실행 → 프롬프트에 입력
GitHub CopilotVS Code의 Copilot Chat 패널에 입력
⚠️ AI 도구가 설치·로그인되어 있지 않으면 입력할 곳이 없습니다. 자연어 변환은 AI가 있어야만 동작하므로 먼저 2-3단계를 완료하세요. AI를 쓸 수 없는 환경이라면 자연어 변환은 불가능하고, 9단계의 스크립트 단독 실행(자동 변환 + 검증)만 가능합니다(판단 변환은 사람이 직접 코드 수정).

AI가 AGENTS.md의 5단계 워크플로우(자동 변환 → 판단 변환 → 자기 검증)를 따라 처리합니다. 여러 파일은 정확도를 위해 한 번에 한 파일씩 변환합니다(함수 누락 방지). 폴더를 주면 목록을 만들어 순차 처리합니다.

src/main/webapp/jsp/order/ 아래 IBSheet 쓰는 JSP들을 차례로 IBSheet8로 변환해줘

변환 예시 (실제 출력 형태)

[변환] orderList.jsp
  자동 변환: 메서드 18건, 속성 24건
  판단 변환: 11건 (Hidden→Visible 3, ColValueDup→getRowsByDup 2, GetSelectRow→getFocusedRow 6)
  검증: 잔존 0건 PASS / 구문 OK / 함수 누락 0건 PASS
  ⚠ 동작 검증 권장: L412 GetSearchData→$.ajax 재구성 (조회 로직)
  출력: orderList.tobe.jsp
6

변환이 진행되는 방식 (5단계)

단계내용
1. 스코프 & 설정대상 파일 확정, migrate.config.json 로드
2. 자동 변환engine/migrate_core.py가 안전한 1:1 메서드·속성 변환 적용
3. 판단 변환의미가 바뀌는 부분(반환값 변경, 접두사 strip, 미지원 API 등)을 AI가 docs/ 근거로 한 건씩 변환
4. 자기 검증verify/ 3종 모두 통과시킴
5. 리포트변환·검증 결과 + 수동 검토 권장 항목 정리

결과 확인하는 법

산출물위치의미
변환 파일원본 옆 *.tobe.jsp (기본)안전한 변환까지 적용된 중간 산출물. 원본은 보존됩니다
리포트변환 중 생성 report.json자동 변환 내역 + 남은 판단 항목의 위치·사유
검증 3종콘솔 출력아래 참고
★ 브릿지 헬퍼helpers/ibsheet-migration.js변환 결과가 호출하는 런타임 파일. 웹앱에 함께 배포해야 합니다
⚠️ *.tobe 파일을 그대로 배포하면 안 됩니다. *.tobe는 안전한 것만 미리 적용된 초안입니다. 판단이 필요한 자리는 원본 코드가 그대로 남아 있습니다. 예를 들어 169줄짜리 화면 하나에서 자동 20건이 적용됐고, 그 파일 안에 IBSheet7 호출이 35건 남았습니다 (mySheet.GetCellValue(...) · mySheet.SetCellValue(...) — IBSheet8에 없는 메서드라 브라우저에서 ... is not a function).
남은 자리에 표시(마커·TODO)를 넣지 않습니다 — 원본 코드를 훼손하지 않기 위한 설계입니다. 어디를 고쳐야 하는지는 옆에 생기는 *.report.json의 needs_review에 규칙 ID·줄 번호·사유로 있습니다. 그것을 처리한 뒤에 배포하세요.
입력 파일의 인코딩 — UTF-8과 cp949(euc-kr)를 자동으로 판별합니다. 출력은 원본과 같은 인코딩·BOM 유무·줄끝(CRLF/LF)으로 씁니다. charset=euc-kr인 화면을 UTF-8로 바꿔 내보내지 않습니다.
IBSheet v3 화면은 건너뜁니다 — InitDataProperty·InitHeadRow·InitRowInfo 계열을 쓰는 화면은 IBSheet v3로, IBSheet7과 세대가 다른 제품입니다. 「IBSheet v3 방식 — v7→v8 변환 대상이 아닙니다」로 알리며, 옮기려면 새로 작성해야 합니다.
왜 헬퍼가 필요한가: IBSheet7의 행 인덱스는 헤더·필터·합계행을 포함하지만 IBSheet8은 데이터행만 셉니다. 열도 IBSheet7은 0부터·숨김컬럼 포함인데 IBSheet8은 1부터입니다. 이 보정을 호출부마다 손으로 넣으면 실수가 잦아, 브릿지 함수 하나로 캡슐화합니다. 변환 결과에 getValue2·setAttribute2·getRowByIndex7처럼 2/7로 끝나는 함수가 보이면 이 헬퍼의 함수입니다.

변환 후 해야 할 일 (중요)

이 도구의 범위는 프론트 코드 변환 + 정적 정합성 검증까지입니다. 화면이 실제로 동작하려면:

1. ★ 브릿지 헬퍼 배포 (필수 — 빠뜨리면 화면이 안 뜹니다)

helpers/ibsheet-migration.js 를 웹앱의 정적 리소스 경로에 복사하고, IBSheet8 본체 다음에 <script>로 불러옵니다.

<!-- 순서 중요: IBSheet8 본체 → 브릿지 헬퍼 -->
<script src="/js/ibsheet/ibsheet.js"></script>
<script src="/js/ibsheet/plugins/ibsheet-common.js"></script>   <!-- IB_Preset 쓰면 필요 -->
<script src="/js/ibsheet/plugins/ibsheet-excel.js"></script>    <!-- 엑셀/텍스트 다운·업로드 -->
<script src="/js/ibsheet/plugins/ibsheet-dialog.js"></script>   <!-- 찾기·피벗 다이얼로그 -->
<script src="/js/ibsheet/plugins/jszip.min.js"></script>        <!-- exportData/importData -->
<script src="/js/ibsheet/ibsheet-migration.js"></script>
변환 결과에 Extend:IB_Preset.*(Status·DelCheck 등)이 있으면 plugins/ibsheet-common.js도 함께 불러와야 합니다. 본체에 없는 전역이라, 빠뜨리면 검증 3종은 PASS인데 브라우저에서 IB_Preset is not defined로 죽습니다.
IBSheet8은 기능이 본체 + 플러그인으로 나뉘어 있습니다. IB_Preset.*→plugins/ibsheet-common.js, down2Excel·loadExcel·down2ExcelBuffer 계열→plugins/ibsheet-excel.js, showFindDialog·showPivotDialog 계열→plugins/ibsheet-dialog.js, exportData·importData(클라이언트 방식 엑셀)→plugins/jszip.min.js. 빠뜨리면 검증 3종은 PASS인데 브라우저에서 ... is not a function으로 죽습니다. 엑셀·텍스트 다운로드/업로드는 서버 모듈 설치까지 필요합니다. migrate.py convert가 변환 결과를 보고 알려줍니다.
다이얼로그 참고 — IBSheet7 에 대응이 있는 것은 ShowFindDialog·ShowPivotDialog 두 개뿐입니다. 엑셀 다운로드/업로드 등 나머지 다이얼로그는 IBSheet8 신규 기능이라 변환 대상이 아닙니다.
  • 배포 경로는 프로젝트 규칙에 맞추면 됩니다(예: common/ibsheet/plugins/). 경로만 맞으면 됩니다.
  • 브릿지 함수는 IBSheet["Plugins"] 프로토타입에 등록되어 모든 시트 인스턴스에서 sheet.getValue2(...) 형태로 호출됩니다. 화면마다 따로 넣을 필요 없고 공통 include에 한 번이면 됩니다.
검증 3종은 정적 검사라 이 파일이 없어도 PASS가 나옵니다. 배포 누락은 검증으로 잡히지 않으니 반드시 확인하세요.

CLI 단독 vs AI — 역할이 다릅니다

자주 묻는 질문 (FAQ)

Q. 원본이 바뀌나요?
A. 아니요. 기본은 원본 옆에 *.tobe.<확장자>로 새로 만듭니다. 덮어쓰기는 사용자가 확인한 경우에만 합니다.

Q. 변환하면 바로 화면이 동작하나요?
A. 코드 변환과 정적 검증까지입니다. 서버(백엔드)와 브라우저 동작 검증은 별도로 필요합니다(8단계).

Q. 꼭 Claude를 써야 하나요?
A. 아니요. Claude Code·Gemini·Copilot 등 원하는 AI를 쓰면 됩니다. 규칙(AGENTS.md)과 검증(verify/)이 동일하게 적용되어, 어떤 AI가 변환하든 결과는 같은 기준으로 판정됩니다.

Q. Python/Node가 회사 PC에 없습니다.
A. 설치가 어렵다면 관리자에게 요청하세요. 두 런타임이 없으면 자동 변환·구문 검증이 동작하지 않습니다.

Q. 변환 결과에 getValue2, setAttribute2, getRowByIndex7 같은 낯선 함수가 있습니다. IBSheet8 API인가요?
A. 아니요. 툴킷이 제공하는 표준 브릿지 헬퍼(helpers/ibsheet-migration.js)의 함수입니다. IBSheet7과 IBSheet8이 1:1로 맞지 않는 부분(행/열 인덱스 체계 차이, 반환값 의미 변경, IBSheet8에 없는 기능)을 흡수합니다. 이름 끝의 2/7이 브릿지 함수 표식입니다. 이 파일을 웹앱에 함께 배포해야 동작합니다(8단계 1번).

Q. 브릿지 없이 순수 IBSheet8 API만으로 변환할 수 있나요?
A. 대부분 가능하지만 권장하지 않습니다. IBSheet7 행 인덱스 → IBSheet8 행 객체 변환은 헤더·필터·상단합계 행 수를 매번 계산해야 하고, ComputeSum처럼 IBSheet8에 아예 없는 기능은 직접 구현해야 합니다. 호출부마다 이 보정을 흩뿌리면 실수가 잦아, 브릿지 하나로 모으는 것이 안전합니다.

Q. 브릿지 헬퍼를 우리 쪽에서 수정해도 되나요?
A. 가능하지만, 수정하면 툴킷 갱신 시 충돌합니다. 프로젝트 고유 로직이 필요하면 별도 파일에 추가하고 헬퍼 원본은 그대로 두는 것을 권장합니다.

Q. IBSheet 라이브러리(8) 자체도 포함되나요?
A. 아니요. 이 툴킷은 코드 변환 도구입니다. IBSheet8 라이브러리/라이선스는 IBSheet 벤더를 통해 별도 도입해야 합니다.
